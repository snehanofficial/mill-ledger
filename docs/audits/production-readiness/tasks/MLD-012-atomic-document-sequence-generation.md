## 1. Description
In `server/src/modules/finance/finance.service.ts:74`, invoice numbers are generated by counting existing invoices:
`const invoiceCount = await tx.salesInvoice.count({ where: { organizationId } }); const invoiceNumber = ...${String(invoiceCount + 1).padStart(4, "0")}`.
Under concurrent invoice creation (e.g. multiple dispatch trucks cleared simultaneously at peak hours), two transactions read the exact same count and generate duplicate invoice numbers (`INV-2026-0001`), resulting in unique constraint crashes or GST compliance violations (Section 31 of CGST Act mandates consecutive serial numbering unique for each financial year).

## 2. Evidence
- Original audit finding: `P1-DATA-04`.
- Architectural Decision: `DEC-002`.
- Files:
  - [server/src/modules/finance/finance.service.ts:70-85](/server/src/modules/finance/finance.service.ts#L70-L85)

## 3. Expected Outcome
1. A dedicated `DocumentSequence` table tracks document sequences per organization, document type, and financial year (e.g. `SALES_INVOICE`, `FY26-27`).
2. Sequence values are incremented inside the database transaction using `SELECT ... FOR UPDATE` or atomic upsert/increment:
   `UPDATE document_sequence SET next_val = next_val + 1 WHERE ... RETURNING next_val`.
3. Consecutive, gap-free, duplicate-free invoice numbers are guaranteed under arbitrary concurrency.

## 4. Scope

## 6. Implementation Plan
1. Schema definition:
   ```prisma
   model DocumentSequence {
     id             String   @id @default(uuid())
     organizationId String   @map("organization_id")
     type           String   // SALES_INVOICE, CREDIT_NOTE, DISPATCH
     financialYear  String   @map("financial_year")
     currentValue   Int      @default(0) @map("current_value")
     updatedAt      DateTime @updatedAt @map("updated_at")

     @@unique([organizationId, type, financialYear])
     @@map("document_sequences")
   }
   ```
2. Helper method `getNextDocumentNumber(tx, organizationId, type, prefix)`:
   Runs an atomic upsert with `currentValue: { increment: 1 }` or raw SQL `UPDATE ... RETURNING`.
3. Integrate into `finance.service.ts:createInvoiceFromOrder`.
4. Run 20 concurrent invoice creation promises to verify uniqueness.
