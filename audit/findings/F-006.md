# Finding F-006: High-Severity Memory Exhaustion Vulnerability in Installed Zod Dependency

**ID**: F-006  
**Title**: Installed Zod version 3.24.2 is subject to high-severity denial-of-service advisory GHSA-mrhx-c7xc-m3w5  
**Severity**: P2  
**Category**: Supply Chain Security / Vulnerability  
**Standard Refs**: OWASP Top 10:2021 A06 (Vulnerable and Outdated Components), GHSA-mrhx-c7xc-m3w5  
**Status**: OPEN  

---

### Expected (source)
Dependencies deployed across server and client should be free from high-severity DoS and memory exhaustion advisories.

### Actual (evidence links)
- Running `pnpm audit` surfaces:
  - `high`: Zod can exhaust memory while validating oversized constrained collections
  - Vulnerable versions: `<4.6.6`
  - Patched versions: `>=4.6.6`
  - Paths: `server>zod`, `client>zod`, `client>@hookform/resolvers>zod`
- Evidence log: [audit/evidence/11-audit.txt](file:///home/snehan/projects/web/mill-ledger/audit/evidence/11-audit.txt)

### Delta
Expected 0 high vulnerabilities; found 1 high vulnerability in Zod 3.24.2.

### Impact
An attacker submitting deeply nested or oversized payload structures to schema validation endpoints could exhaust Node.js memory, causing denial of service.

### Repro Steps
1. Run `pnpm audit`
2. Observe 1 high vulnerability reported for `zod`.

### Root Cause
Installed version `^3.24.2` in `server/package.json` and `client/package.json`.

### Recommended Fix (DO NOT APPLY - AUDIT ONLY)
Assess upgrading to patched Zod release or implementing maximum body size constraints in Express body parser (`express.json({ limit: '100kb' })`) to prevent oversized payload delivery.

### Regression Test to Add
`pnpm audit` check in CI pipeline with zero-high threshold.

### Effort
M (Medium) - Due to potential API compatibility considerations between major Zod versions.

### Status
VERIFIED
