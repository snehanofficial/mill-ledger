# Finding F-017: Mass Assignment Allows Salesman to Create Pre-Approved Orders Bypassing Approval Workflow and Stock Reservation

**ID**: F-017  
**Title**: Unvalidated `status` in order creation payload allows salesman to set `status: "APPROVED"` directly in PostgreSQL  
**Severity**: P0  
**Category**: Authorization / Mass Assignment / Privilege Escalation  
**Standard Refs**: OWASP API Security Top 10:2023 API3:2023 (Broken Object Property Level Authorization), OWASP Top 10:2021 A01:2021 (Broken Access Control), OWASP ASVS v4.0.3 Section 5.1.4

## Delta
The API accepts arbitrary `OrderStatus` enum values from the client payload during order creation. A salesman can directly create orders with `status: "APPROVED"`, completely bypassing manager authorization, ATP stock checks, credit limit checks, and stock reservation creation. The order exists in the database as `APPROVED` with 0 stock reserved, corrupting downstream fulfilment invariants.

---

## Impact
- **Financial & Operational Impact**: Any salesman can bypass manager oversight, approve their own orders, and initiate dispatches without credit checks or inventory reservation. If unreserved orders are dispatched, the mill oversells stock and commits to unbacked orders, leading to stockouts and supplier defaults.

## Repro Steps
1. Authenticate as `salesman1@millledger.local`.
2. Send `POST /api/v1/sales/orders` with body:
   `{"customerId": "<valid_customer_id>", "status": "APPROVED", "lines": [{"productVariantId": "<variant_id>", "quantity": 1}]}`.
3. Observe HTTP 201 response with `order.status === "APPROVED"`.
4. Query PostgreSQL database `SELECT id, status FROM sales_order WHERE id = '<order_id>';` -> status is `APPROVED`.
5. Query `SELECT count(*) FROM stock_reservation WHERE sales_order_id = '<order_id>';` -> returns 0.

## Root Cause
- [server/src/modules/sales/sales.routes.ts:22](file:///home/snehan/projects/web/mill-ledger/server/src/modules/sales/sales.routes.ts#L22): `status: z.nativeEnum(OrderStatus).optional()` exposes an internal lifecycle state to client input.
- [server/src/modules/sales/sales.service.ts:289](file:///home/snehan/projects/web/mill-ledger/server/src/modules/sales/sales.service.ts#L289): Directly assigns `input.status` without verifying if actor has approval authority.

---

## Recommended Fix
1. In `createOrderSchema`, restrict status to `z.enum(["DRAFT", "SUBMITTED"]).optional()` or eliminate the `status` field entirely from the input schema.
2. In `sales.service.ts`, force initial order status to `OrderStatus.SUBMITTED` (or `DRAFT` if requested as draft), never allowing `APPROVED` on creation.
