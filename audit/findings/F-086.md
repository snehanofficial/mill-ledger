# F-086: Missing Pre-Hydration HTML Lang Synchronization and Non-User-Scoped Language Preference Causing FOUC

- **ID**: F-086
- **Title**: Missing Pre-Hydration HTML Lang Synchronization and Non-User-Scoped Language Preference Causing FOUC
- **Severity**: P2
- **Category**: Accessibility / Internationalization Architecture
- **Standard Refs**:
  - WCAG 2.2 SC 3.1.1 Language of Page (Level A)
  - W3C Internationalization Best Practices (Declaring language in HTML)
  - OWASP Top 10:2021 A01 Broken Access Control (Cross-User State Bleed)

---

## Expected (Source)
- **Source**: WCAG 2.2 SC 3.1.1 and Phase 11 Audit Prompt ("Is the language persisted per user and applied before first paint (no flash)?").
- 1. The document language attribute (`<html lang="...">`) must match the user's selected language before the first visual paint, preventing Flash of Untranslated Content (FOUC) and speech synthesizer pronunciation conflicts in screen readers.
- 2. User language preferences must be persisted per user (tied to user profile or user-scoped storage key), not shared globally across different accounts on the same machine.

---

## Actual (Evidence Links)
- **Evidence**:
  - Static HTML entry point in `client/index.html` hardcoded `<html lang="en">` without inline pre-hydration script in `<head>`.
  - Language provider updated `document.documentElement.lang` asynchronously after React mount inside `useEffect`, causing FOUC.
  - Storage key was global `localStorage.getItem("mill_ledger_lang")` without user scoping, bleeding language state across logins.

---

## Delta
Lack of pre-hydration language script and absence of user-scoped preference keys caused visual/acoustic flash and cross-user setting bleed.

---

## Impact
- **Who is hurt**: Users of assistive screen readers (NVDA, TalkBack) and multi-user terminal operators.
- **How**: TalkBack initially adopted an English text-to-speech pronunciation engine because `lang="en"` was present during early document load, producing distorted acoustic speech for Tamil script until hydration completed. Different users sharing a terminal inherited each other's language setting.

---

## Root Cause
- File: `client/index.html`
  - Lacked an inline synchronous script in `<head>` to synchronize `document.documentElement.lang` from storage prior to first paint.
- File: `client/src/lib/i18n.tsx`
  - Used single un-scoped `localStorage` key.

---

## Fix & Verification

### Implementation
- `client/index.html`:
  * Embedded synchronous pre-hydration script in `<head>` setting `document.documentElement.lang` before DOM rendering.
- `client/src/lib/i18n.tsx`:
  * Added `getUserScopedLanguageKey`, `getSavedLanguage`, and `saveUserLanguage`.
  * Updated `LanguageProvider` with user-scoped isolation.
- `client/src/lib/auth-client.ts`:
  * Manages `mill_ledger_active_user` upon `signIn` and `signOut`.
- `client/src/layouts/authenticated-layout.tsx`:
  * Synchronizes active user ID and clears on logout.
