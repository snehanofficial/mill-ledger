# F-086: Missing Pre-Hydration HTML Lang Synchronization and Non-User-Scoped Language Preference Causing FOUC

- **ID**: F-086
- **Title**: Missing Pre-Hydration HTML Lang Synchronization and Non-User-Scoped Language Preference Causing FOUC
- **Severity**: P2
- **Category**: Accessibility / Internationalization Architecture
- **Standard Refs**:
  - WCAG 2.2 SC 3.1.1 Language of Page (Level A)
  - W3C Internationalization Best Practices (Declaring language in HTML)
  - OWASP Top 10:2021 A01 Broken Access Control (Cross-User State Bleed)

---

## Expected (Source)
- **Source**: WCAG 2.2 SC 3.1.1 and Phase 11 Audit Prompt ("Is the language persisted per user and applied before first paint (no flash)?").
- 1. The document language attribute (`<html lang="...">`) must match the user's selected language before the first visual paint, preventing Flash of Untranslated Content (FOUC) and speech synthesizer pronunciation conflicts in screen readers.
- 2. User language preferences must be persisted per user (tied to user profile or user-scoped storage key), not shared globally across different accounts on the same machine.

---

## Actual (Evidence Links)
- **Evidence**:
  - Static HTML entry point in [`client/index.html`](file:///home/snehan/projects/web/mill-ledger/client/index.html#L2):
    ```html
    <!doctype html>
    <html lang="en">
      <head>
    ```
    - `<html lang="en">` is hardcoded. There is no inline pre-hydration blocking script in `<head>` to read saved preferences and set `document.documentElement.lang`.
  - Language provider in [`client/src/lib/i18n.tsx`](file:///home/snehan/projects/web/mill-ledger/client/src/lib/i18n.tsx#L92-L113):
    ```tsx
    export function LanguageProvider({ children }: { children: ReactNode }) {
      const [language, setLanguageState] = useState<Language>(() => {
        if (typeof window !== "undefined") {
          const saved = localStorage.getItem("mill_ledger_lang") as Language;
          if (saved === "en" || saved === "ta") return saved;
        }
        return "en";
      });

      useEffect(() => {
        if (typeof window !== "undefined") {
          document.documentElement.lang = language;
        }
      }, [language]);
    ```
    - `document.documentElement.lang` is updated inside `useEffect`, which runs asynchronously **after DOM layout and initial paint**.
    - Storage key is global `localStorage.getItem("mill_ledger_lang")` without user scoping.
  - Database schema in [`server/prisma/schema.prisma`](file:///home/snehan/projects/web/mill-ledger/server/prisma/schema.prisma#L9-L27):
    - `model User` has columns: `id`, `name`, `email`, `emailVerified`, `image`, `role`, `isActive`, `organizationId`.
    - No `language` or `locale` preference column exists in the database.

---

## Delta
1. **Pre-paint flash (FOUC)**: Screen readers and browser layout engines evaluate `<html lang="en">` on initial parse. Tamil-speaking users experience a flash where the page announces in English before React mounts and flips the attribute.
2. **Global state bleed**: Language is not stored per user. When an operator switches the terminal to Tamil, any subsequent user (e.g. factory accountant or auditor) logging into that browser is forced into Tamil without consent.

---

## Impact
- **Who is hurt**: Users of assistive screen readers (NVDA, TalkBack) and multi-user terminal operators.
- **How**: TalkBack initially adopts an English text-to-speech pronunciation engine because `lang="en"` is present during early document load, producing distorted acoustic speech for Tamil script until hydration completes.

---

## Repro Steps
1. In the browser, toggle language to Tamil (`localStorage.getItem("mill_ledger_lang") === "ta"`).
2. Hard reload the page with network throttling.
3. Inspect `document.documentElement.lang` during early parsing: it is `"en"` until React bundle executes and hydration finishes.
4. Log out and log in as English-speaking Accountant: the account loads in Tamil because the localStorage key is not user-scoped.

---

## Root Cause
- File: [`client/index.html`](file:///home/snehan/projects/web/mill-ledger/client/index.html#L2)
  - Lacks an inline `<script>` in `<head>` to synchronize `document.documentElement.lang` from storage prior to stylesheet/DOM rendering.
- File: [`server/prisma/schema.prisma`](file:///home/snehan/projects/web/mill-ledger/server/prisma/schema.prisma#L9)
  - `User` table lacks a `preferredLanguage` column.

---

## Recommended Fix (Do Not Apply)
1. Add an inline `<script>` in `client/index.html` `<head>`:
   ```html
   <script>
     try {
       const lang = localStorage.getItem("mill_ledger_lang");
       if (lang === "ta") document.documentElement.lang = "ta";
     } catch (_) {}
   </script>
   ```
2. Scope local storage keys by user ID (`mill_ledger_lang_${userId}`).
3. Add `preferredLanguage String @default("en")` to Prisma `User` model and sync preference via `PATCH /api/v1/users/me/profile`.
