# F-083: Silent Server Acceptance of Insufficient Stock Offline Orders Violating Explicit Conflict Queue Requirement (REQ-052)

- **ID**: F-083
- **Title**: Silent Server Acceptance of Insufficient Stock Offline Orders Violating Explicit Conflict Queue Requirement (REQ-052)
- **Severity**: P1
- **Category**: Inventory Invariants / Offline Conflict Resolution
- **Standard Refs**:
  - `Problem_Statement_Winter_Internship_Application_2026.md` (Step 6: "Show how the system handles insufficient stock")
  - `audit/01-expected-spec.md` (REQ-052: Sync State Tracking and Explicit Conflict Queue Triage)
  - `docs/business-rules.md` (BR-021: Stock Allocation & Conflict Triage)
  - Owner Decision #9: "Put conflicting offline orders into a CONFLICT queue when stock is insufficient at synchronization time. Allow authorized users to adjust quantities, create backorders, or cancel. Never silently overbook stock or split orders automatically."

---

## Expected (Source)
- **Source**: `audit/01-expected-spec.md` (REQ-052) and Owner Decision #9.
- When an offline order synchronizes for an item whose required quantity exceeds available unreserved stock (or when available stock is zero), the synchronization endpoint must flag the stock shortage, set the order status to `CONFLICT` (or return HTTP 409 Conflict), refrain from reserving stock, and route the order into an explicit Conflict Queue for manual admin resolution.

## Delta
Instead of placing orders with stock shortages into `status = "conflict"` and displaying an explicit conflict triage warning, the server unconditionally accepts the order as `SUBMITTED`. The client outbox marks the order as `synced` and hides all shortage indications from the salesman.

---

## Impact
- **Who is hurt**: Salesmen, customers, and factory operations dispatchers.
- **How**: Salesmen promise order delivery to customers based on the green "Synced" status in their outbox. In reality, the mill has zero inventory for the order. Without explicit conflict notification, the salesman cannot adjust the quantity or explain backorders to the customer while on site.

---

## Repro Steps
1. In the database, ensure Murukku finished goods available stock is 50 packets.
2. Salesman disconnects device to simulate offline field visit.
3. Salesman queues an offline order for 500 packets of Murukku.
4. Salesman reconnects and triggers synchronization.
5. Inspect outbox: Order displays green badge `Synced: SO-XXXX`.
6. Inspect database: Order is created with status `SUBMITTED` with zero stock reserved, but zero conflict alert was raised to the salesman.

---

## Root Cause
- File: [`server/src/modules/sales/sales.service.ts`](file:///home/snehan/projects/web/mill-ledger/server/src/modules/sales/sales.service.ts#L290-L315)
  - `createSalesOrder` sets order status to `SUBMITTED` even when `shortages.length > 0` and does not set a `CONFLICT` status.
- File: [`client/src/offline/sync-engine.ts`](file:///home/snehan/projects/web/mill-ledger/client/src/offline/sync-engine.ts#L217-L225)
  - `sync-engine` does not inspect `response.data.shortages`. If the server returns HTTP 201, it marks the local order as `synced` regardless of whether stock was short.

---

## Recommended Fix (Do Not Apply)
1. On the server, if `shortages.length > 0` for an order originating from offline sync (or when requested quantity > available), set `status = OrderStatus.CONFLICT`.
2. In `sync-engine.ts`, inspect `response.data.shortages` or order status. If status is `CONFLICT`, set local outbox status to `conflict` with plain English message: "Stock insufficient: only X of Y packets available at sync time".
