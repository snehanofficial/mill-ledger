# F-091: Statically Frozen `<title>` and Total Omission of Essential SEO & Social Metadata

- **ID**: F-091
- **Title**: Statically Frozen `<title>` and Total Omission of Essential SEO & Social Metadata
- **Severity**: P1
- **Category**: Accessibility (WCAG 2.2 AA) & SEO Architecture
- **Standard Refs**:
  - WCAG 2.2 Success Criterion 2.4.2: Page Titled (Level A)
  - `audit/01-expected-spec.md` REQ-062 ("The web application must implement descriptive <title> tags, semantic HTML, and metadata throughout all views")
  - Open Graph Protocol (ogp.me)
  - Twitter Cards Markup Specification
  - Google Search Central: Control Your Snippets in Search Results

---

## Expected (Source)
- **Source**: WCAG 2.2 SC 2.4.2 & `audit/01-expected-spec.md` REQ-062:
  - "Web pages have titles that describe topic or purpose."
  - "Across all routes: Then `<title>` dynamically updates with the active view name and organization title, semantic landmarks are present, and public login pages permit indexing."
  - Public surfaces must provide unique `<meta name="description">`, `<link rel="canonical">`, Open Graph tags (`og:title`, `og:description`, `og:image`, `og:url`, `og:type`), and Twitter Card metadata with properly dimensioned social preview imagery (1200x630).

---

## Delta
1. Zero dynamic title updates across the application; every view has the identical static title, failing WCAG 2.4.2 Level A.
2. Complete absence of description, canonical, Open Graph, and Twitter metadata.
3. Complete absence of an OG social share image.

---

## Impact
- **Who is hurt**: Screen reader users navigating between views, and any user sharing links on messaging/social platforms (WhatsApp, Slack, LinkedIn, Twitter).
- **How**:
  - Screen reader users rely on title announcements to confirm navigation into a new view. Because the title never changes, assistive technologies cannot announce page transitions.
  - Sharing links produces blank or broken link preview cards without descriptive snippets or images.

---

## Repro Steps
1. Navigate to `/auth/login`: check `document.title` -> "MillLedger | Order-to-Audit System for a Small Food Manufacturer".
2. Log in and navigate to `/dashboard`: check `document.title` -> same string.
3. Navigate to `/orders`: check `document.title` -> same string.
4. Inspect `document.querySelectorAll('meta[property^="og:"]')`: returns empty NodeList.

---

## Root Cause
- File: [`client/index.html`](file:///home/snehan/projects/web/mill-ledger/client/index.html#L10)
  - Contains a single hardcoded `<title>` tag with no head management hooks.
- File: [`client/src/app.tsx`](file:///home/snehan/projects/web/mill-ledger/client/src/app.tsx#L50-L100)
  - `route-handles.ts` defines breadcrumbs, but no component or router listener updates `document.title` during route transitions.

---

## Recommended Fix (Do Not Apply)
1. Implement a route title hook or layout effect that derives the title from route handles:
   ```tsx
   useEffect(() => {
     const title = activeBreadcrumb ? `${activeBreadcrumb} | MillLedger` : "MillLedger";
     document.title = title;
   }, [location]);
   ```
2. Add Open Graph, Twitter, and meta description tags to `index.html` and dynamic meta setters for public surfaces.
3. Provide a high-resolution 1200x630 `og-preview.png` in `client/public/`.
