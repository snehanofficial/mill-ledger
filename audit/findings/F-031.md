**Title**: Shared contracts workspace contains zero domain schemas; client executes with no Zod validation while server routes define isolated, unexported schemas  
**Severity**: P1  
**Category**: Architecture / Contract Integrity / Developer Experience  
**Standard Refs**: MLD Master Plan (Shared contracts and Zod schemas across client and server), OWASP API Security Top 10:2023 API8:2023  
**Status**: OPEN

Simultaneously, `grep -rn "zod" client/src` yields zero imports. The React frontend implements zero client-side schema validation on any form or mutation.

### Delta
100% of domain schemas (11 out of 11) are missing from `shared/src/schemas`. The client has zero access to server validation rules, resulting in failed network roundtrips for basic format errors and complete lack of pre-submit validation.

### Impact
Forms cannot give immediate feedback to offline sales agents or shop floor workers before network submission. Outbox sync attempts fail on the server due to client-server contract mismatches. Duplication and drift between UI inputs and backend validation rules.

### Repro Steps
1. Inspect `shared/src/schemas/index.ts`. Observe only `health.schema.ts` is re-exported.
2. Search `client/src` for any import from `shared` schemas: zero matches.
3. Automated script: `node --env-file=audit/.env.audit server/node_modules/tsx/dist/cli.mjs audit/scripts/verify-validation-inventory.ts`.

### Root Cause
Domain schemas were rapidly prototyped inline inside `server/src/modules/*/*.routes.ts` rather than extracted to `shared/src/schemas/`.

### Recommended Fix (do not apply)
Extract all Zod schemas into `shared/src/schemas/*.schema.ts`, export them from `shared/src/index.ts`, and integrate `@hookform/resolvers/zod` in React client form components.

### Regression Test to Add
`shared/src/schemas.test.ts` asserting that schemas for all resources (order, dispatch, production, receipt, invoice, payment) are exported and compile cleanly in both server and client builds.
