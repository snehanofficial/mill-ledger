# Finding F-023: Missing User and Role Management APIs and Unprotected Super-Admin Accounts

**ID**: F-023  
**Title**: Backend lacks user and role management API endpoints; super admin accounts rely on hardcoded seeded credentials without last-admin demotion safeguards or MFA  
**Severity**: P1  
**Category**: Identity & Access Management / Administration  
**Standard Refs**: OWASP Top 10:2021 A01:2021 (Broken Access Control), OWASP ASVS v4.0.3 Section 1.4.1, Section 2.8 (Multi-Factor Authentication)  

---

## Expected (Source)
Source: [docs/authorization-matrix.md](file:///home/snehan/projects/web/mill-ledger/docs/authorization-matrix.md), [server/src/policies/rbac.ts:15](file:///home/snehan/projects/web/mill-ledger/server/src/policies/rbac.ts#L15), OWASP ASVS v4.0.3 Section 1.4.  
The system must provide administrative capabilities to manage users, assign roles, activate/deactivate accounts, protect the last remaining administrator from deletion or demotion, provide secure bootstrap mechanisms rather than static passwords, and offer Multi-Factor Authentication (MFA) for privileged accounts.

---

## Actual (Evidence Links)
Evidence: Analysis of route inventory ([/audit/evidence/routes-runtime.json](file:///home/snehan/projects/web/mill-ledger/audit/evidence/routes-runtime.json)), server sources ([server/src/app.ts](file:///home/snehan/projects/web/mill-ledger/server/src/app.ts)), and auth configuration ([server/src/lib/auth.ts](file:///home/snehan/projects/web/mill-ledger/server/src/lib/auth.ts)).

1. **Zero User Management Routes**: Although [server/src/policies/rbac.ts:15](file:///home/snehan/projects/web/mill-ledger/server/src/policies/rbac.ts#L15) assigns `user: ["create", "read", "update", "delete"]` to `ADMIN`, there is not a single route in the Express router tree (e.g. `/api/v1/users`, `/api/v1/admin/users`) to list, create, update, or delete users.
2. **Static Seeded Administrator Credentials**: In [server/prisma/seed.ts:20-24](file:///home/snehan/projects/web/mill-ledger/server/prisma/seed.ts#L20-L24), the initial administrator is created with static hardcoded password `AdminPassword123!`.
3. **No Last-Admin Protection**: There is no application or database invariant preventing the sole administrator from being disabled (`isActive = false`) or deleted directly via database queries or auth tools.
4. **MFA Not Configured**: Better Auth is instantiated in `server/src/lib/auth.ts` without the `twoFactor` or WebAuthn plugin. Privileged administrator accounts have only single-factor password authentication.

---

## Delta
Privileged role management cannot be operated through the application interface or API. Administrator authentication relies on a well-known static seeded password without MFA.

---

## Impact
- **Administrative Lockout & Credential Exposure**: Production deployments using default seed credentials are vulnerable to automated dictionary takeover. Lack of MFA leaves high-privilege administrative access vulnerable to credential stuffing.

---

## Repro Steps
1. Review all 81 routes in `routes-runtime.json`. Confirm absence of any `/users` or `/admin` routes.
2. Review `server/src/lib/auth.ts`. Confirm no plugins array, no `twoFactor` plugin.
3. Authenticate as `admin@millledger.local` with `AdminPassword123!`.

---

## Root Cause
- [server/src/lib/auth.ts](file:///home/snehan/projects/web/mill-ledger/server/src/lib/auth.ts): Better Auth setup does not include administrative plugins or two-factor authentication.
- [server/src/app.ts](file:///home/snehan/projects/web/mill-ledger/server/src/app.ts): No administrative user router mounted.

---

## Recommended Fix
1. Implement a user management module (`user.routes.ts`, `user.service.ts`) enforcing `authorize("user", "create" | "read" | "update" | "delete")`.
2. Add a database check preventing modification of the final active `ADMIN` account.
3. Configure Better Auth's `twoFactor` plugin with TOTP / Authenticator App support for administrative roles.

---

## Regression Test to Add
Add tests in `server/src/auth.integration.test.ts` verifying that attempting to demote or deactivate the last remaining admin account returns HTTP 400 Bad Request.
