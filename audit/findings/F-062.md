# Finding F-062: Continuous Pulsing Sync Badges and Skeletons Lack User Pause/Stop/Hide Mechanism

- **ID**: F-062
- **Title**: Continuous Pulsing Sync Badges and Skeletons Lack Pause/Stop/Hide Mechanism
- **Severity**: P2
- **Category**: Accessibility / Motion
- **Standard Refs**:
  - W3C WCAG 2.2 Success Criterion 2.2.2 Pause, Stop, Hide (Level A)
  - Apple Human Interface Guidelines: Motion (Make motion optional)

---

## Expected Behavior
Per W3C WCAG 2.2 SC 2.2.2:
> "For any moving, blinking or scrolling information that (1) starts automatically, (2) lasts more than five seconds, and (3) is presented in parallel with other content, there is a mechanism for the user to pause, stop, or hide it unless the movement, blinking, or scrolling is part of an activity where it is essential."

Any non-essential pulsing indicator, loading skeleton loop, or animated badge that runs continuously beyond 5 seconds must provide the user with a control to pause, stop, or hide the animation.

---

## Actual Behavior
1. In `client/src/pages/orders-page.tsx:578` and `client/src/components/shell/device-outbox-sheet.tsx:204`, orders with `status === "syncing"` render a badge with the Tailwind `animate-pulse` utility class:
   ```tsx
   <Badge
     variant="outline"
     className="animate-pulse bg-sky-500/10 text-sky-700 dark:text-sky-400 border-sky-500/20"
   >
     Syncing...
   </Badge>
   ```
2. In `client/src/components/ui/skeleton.tsx:8`, skeleton blocks use continuous pulse:
   ```tsx
   className={cn("animate-pulse rounded-small bg-surface-muted", className)}
   ```
3. When network conditions are poor or synchronization queues process multiple batches, the pulsing loop persists for tens of seconds or minutes with zero pause, stop, or hide control.
4. Programmatic audit evidence recorded in `audit/evidence/motion/metrics/flashing-and-automoving-audit.json`:
   - `hasGlobalPauseControl: false`
   - `pulsingElementsCount: 2+`
   - `wcag222Evaluation: "VERIFIED-FAIL"`

---

## Delta
Pulsing animations start automatically and run indefinitely while syncing or fetching with no pause or hide affordance. While `prefers-reduced-motion` suppresses this for users with OS-level settings, normal-motion users with cognitive disabilities, ADHD, or vestibular sensitivities cannot pause or hide persistent pulsing elements.

---

## Impact
Users with attention deficit disorders or vestibular sensitivities suffer distraction and visual fatigue from continuous peripheral movement during extended synchronization operations on the shop floor.

## Recommended Fix
1. Limit pulsing duration using CSS animation iteration count or timeout (e.g., stop pulsing after 3 iterations / 6 seconds and display a static badge).
2. Provide an explicit in-app "Reduce motion / Pause animations" toggle in the header or user preferences.
