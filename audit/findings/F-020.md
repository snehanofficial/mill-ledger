# Finding F-020: Unrestricted Client Price Overrides Without Manager Approval or Minimum Floor Validation

**ID**: F-020  
**Title**: Sales order creation permits arbitrary client-supplied unit prices without discount bounds, minimum margin validation, or manager approval  
**Severity**: P1  
**Category**: Business Logic / Authorization / Financial Integrity  
**Standard Refs**: OWASP API Security Top 10:2023 API3:2023 (Broken Object Property Level Authorization), OWASP ASVS v4.0.3 Item 10.3.2  

---

## Expected (Source)
Source: [docs/business-rules.md](file:///home/snehan/projects/web/mill-ledger/docs/business-rules.md) Section 3, [docs/product-requirements.md](file:///home/snehan/projects/web/mill-ledger/docs/product-requirements.md) REQ-026.  
Orders must use official price list rates (`product_variant_price`). Price overrides or discounts below baseline list prices require explicit managerial authority and approval. Arbitrary zero or sub-cost prices must be rejected.

## Delta
The backend allows any salesman to dictate arbitrary selling prices down to ₹0.00 without validating against the product's default price list, minimum floor price, or weighted average production cost.

---

## Impact
- **Financial Loss**: A rogue or compromised salesman account can create orders selling inventory for fractions of a rupee, causing massive unrecoverable financial loss once dispatched and invoiced.

---

   `{"customerId": "<customer_id>", "lines": [{"productVariantId": "<variant_id>", "quantity": 100, "unitPrice": 0.01}]}`.

4. Total order amount is ₹1.05 instead of ₹5,250.00.

## Root Cause
- [server/src/modules/sales/sales.routes.ts:28](file:///home/snehan/projects/web/mill-ledger/server/src/modules/sales/sales.routes.ts#L28): Schema permits `unitPrice: z.number().min(0).optional()` without role or discount restrictions.
- [server/src/modules/sales/sales.service.ts:224](file:///home/snehan/projects/web/mill-ledger/server/src/modules/sales/sales.service.ts#L224): Accepts client-provided `unitPrice` directly over price list pricing.

---

## Recommended Fix
1. Disallow salesmen from submitting arbitrary `unitPrice` on order creation; always default unit prices from `ProductVariantPrice`.
2. If discounts or overrides are supported, validate against a maximum allowable discount threshold (e.g., max 5%) and require orders with price overrides to be flagged as requiring manager approval.
