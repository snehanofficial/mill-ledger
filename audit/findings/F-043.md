# F-043: Pervasive Tamil Localization Failure Across Internal Business Routes Despite Language Selector

- **ID**: F-043
- **Title**: Pervasive Tamil Localization Failure Across Internal Business Routes Despite Language Selector
- **Severity**: P1
- **Category**: UX / Regional Accessibility / Localization
- **Standard refs**: NN/g H2 (Match Between System and Real World), Phase 7 Specification Check 9, UI-UX-Spec

---

## 1. Expected vs Actual

- **EXPECTED (Phase 7 Spec Check 9, UI-UX-Spec)**:
  The application must provide bilingual parity between English and Tamil across all user journeys. Selecting Tamil ("தமிழ்") must translate navigation items, page headers, form labels, operational status badges, and table headers into standard mill operational Tamil (e.g., முறுக்கு, இருப்பு, விநியோகம், ஆணை, விலைப்பட்டியல்).
- **ACTUAL (evidence: `client/src/lib/i18n.tsx:19-77`, `client/src/components/shell/nav-config.tsx:64-160`, `client/src/pages/*.tsx`, `/audit/evidence/screenshots/ADMIN/ta/1440px/dashboard.png`, `/audit/evidence/screenshots/ADMIN/ta/1440px/orders.png`)**:
  `dictionary` in `i18n.tsx` contains only 30 keys. The translation helper `t()` is only invoked in `MobileBottomNav` (`client/src/components/shell/authenticated-shell.tsx:983-997`). Sidebar navigation labels in `nav-config.tsx` are hardcoded English strings. Across all 11 core operational pages (`dashboard-page.tsx`, `orders-page.tsx`, `invoices-page.tsx`, `dispatch-page.tsx`, `payments-page.tsx`, `stock-page.tsx`, `purchases-page.tsx`, `production-page.tsx`, `customers-page.tsx`, `reports-page.tsx`), zero components import `useLanguage` or `t()`. All table headers, form labels, action buttons, and KPI titles remain 100% in English when Tamil is active.
- **DELTA**:
  Tamil localization is an illusion: only the login page and mobile bottom nav support Tamil. Over 95% of the ERP and shop floor ledger remains in English, rendering the Tamil language toggle ineffective for factory personnel.

---

## 2. Impact

- **Who is hurt**: Mill floor operators, weighbridge staff, and Tamil-speaking warehouse clerks who rely on Tamil vernacular for recording production runs, stock receipts, and dispatches.
- **Operational consequence**: Misinterpretation of stock exceptions, yield variance, or tax invoices due to English jargon barriers, directly defeating the stated design requirement for regional Tamil food mill operations.

---

## 3. Repro Steps & Root Cause

### Repro Steps
1. Navigate to `http://127.0.0.1:4173/auth/login` and sign in as `production@millledger.local`.
2. Click the header language switcher toggle button ("தமிழ்").
3. Observe header shows "EN" (indicating Tamil is active) and `document.documentElement.lang` is set to `"ta"`.
4. Inspect the sidebar: labels read "Overview", "Operations", "Stock", "Purchases", "Production" (English).
5. Navigate to `/production/today`: headings read "Production Today", "Active batches", "Yield variance", "Murukku output (pkts)" (English).
6. Click "New Run": dialog inputs read "Batch Number", "Flour (kg)", "Oil (L)", "Start Run" (English).

### Root Cause
1. `client/src/components/shell/nav-config.tsx:65-170` hardcodes English string literals for all menu groups and link labels.
2. Production, stock, and orders page components do not connect to `LanguageContext` or wrap UI copy in translation functions.

---

## 4. Recommended Fix & Regression Test

### Recommended Fix (Do Not Apply - Audit Only)
1. Expand `client/src/lib/i18n-dictionary.ts` to include comprehensive Tamil strings for all entity fields, table headers, buttons, and error messages.
2. Refactor `nav-config.tsx` to use translation keys (e.g. `nav.production`, `nav.stock`).
3. Refactor page components to consume `useLanguage()` and `t(key, fallback)` for all visible copy.

### Regression Test to Add
- Add Playwright spec `tests/tamil-parity.spec.ts` asserting:
  - When `mill_ledger_lang === 'ta'`, table headers on `/production/today`, `/stock`, and `/orders` contain non-ASCII Tamil unicode characters (`/[\u0B80-\u0BFF]/`).
  - Zero raw English navigation headers rendered in sidebar.
