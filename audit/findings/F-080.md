## Delta
The application claims "Full bilingual support toggled on the application shell for floor staff and operators" (README and REQ-053), but in reality, **99.5% of the user interface remains in English**. The Tamil toggle is purely cosmetic on the application shell, leaving all production workflows, stock tables, order forms, invoice breakdowns, and server errors untranslated.

---

## Impact
- **Who is hurt**: Shop floor operators, packaging workers, and regional salesmen in Tamil Nadu who cannot read English fluently.
- **How**: Factory workers issuing raw materials (flour, oil, spice mix) or recording production yield and waste cannot understand English form fields, leading to operational mistakes, mislabeled batches, or inability to use the terminal without translation assistance.

## Root Cause
- File: [`client/src/lib/i18n.tsx`](file:///home/snehan/projects/web/mill-ledger/client/src/lib/i18n.tsx#L19-L77) and [`client/src/lib/i18n-dictionary.ts`](file:///home/snehan/projects/web/mill-ledger/client/src/lib/i18n-dictionary.ts#L10-L68)
  - Dictionary defines only 33 keys.
  - Page components hardcode English JSX strings without importing `useLanguage` or wrapping user-visible strings with `t()`.

---

## Recommended Fix (Do Not Apply)
1. Adopt a scalable i18n solution (e.g. `i18next` with `react-i18next` or extend the current dictionary to cover all domain modules).
2. Extract all 755 user-visible strings into localized JSON resource bundles (`locales/en/common.json`, `locales/ta/common.json`, `locales/ta/production.json`, `locales/ta/sales.json`).
3. Replace hardcoded strings across all 11 page components with `t(...)`.
