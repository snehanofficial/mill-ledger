# F-071: Missing Foreign Key and Composite Indexes Causing Sequential Scans on 11 of Top 20 Production Queries

- **ID**: F-071
- **Title**: Missing Foreign Key and Composite Indexes Causing Sequential Scans on 11 of Top 20 Production Queries
- **Severity**: P1
- **Category**: Database Architecture & Indexing Performance
- **Standard Refs**:
  - PostgreSQL Indexing Best Practices (Foreign Key Indexing & Composite Index Ordering)
  - OWASP API Security Top 10:2023 API4:2023 (Unrestricted Resource Consumption via Database Thrashing)

---

## Expected (Source)
- **Source**: `Problem_Statement_Winter_Internship_Application_2026.md`, `audit/01-expected-spec.md` (REQ-055).
- Relational tables supporting high-volume mill records (stock movements, orders, invoices, line items) must index foreign keys and query filter columns to ensure constant or logarithmic ($O(\log N)$) B-tree lookup times, avoiding full sequential table scans ($O(N)$).

## Delta
Critical foreign keys and frequent query predicate columns are completely unindexed in Prisma schema:
- `sales_order_line`: ZERO indexes (not even on foreign key `salesOrderId`). Looking up an order's items scans every order line in the database.
- `sales_invoice_line`: ZERO indexes (not even on foreign key `invoiceId`).
- `sales_invoice`: Only has unique constraint `(organizationId, invoiceNumber)`. Lacks indexes on `customerId`, `status`, `postedAt`, and `outstandingAmount`.
- `sales_order`: Lacks indexes on `customerId`, `(organizationId, createdAt)`, and `(organizationId, status)`.
- `stock_movement`: Index is `(inventoryItemId, warehouseId, postedAt)`. Queries filtering by `inventoryItemId` alone or ordering by `postedAt DESC` without `warehouseId` degrade to Seq Scan on 100k rows.

---

## Impact
- **Who is hurt**: Mill managers, sales managers, accountants running reports.
- **How**: Severe query latency spikes as transactions grow past 10,000. Database CPU utilization reaches 100% due to repeated sequential buffer reads, degrading the entire application.

## Root Cause
- File: [`server/prisma/schema.prisma`](file:///home/snehan/projects/web/mill-ledger/server/prisma/schema.prisma#L639-L762)
  - `SalesOrderLine` and `SalesInvoiceLine` models omit `@@index([salesOrderId])` and `@@index([invoiceId])`.
  - `SalesInvoice` model omits `@@index([customerId, status])` and `@@index([organizationId, postedAt])`.

---

## Recommended Fix (Do Not Apply)
Add the following indexes to `server/prisma/schema.prisma`:
```prisma
model SalesOrderLine {
  ...
  @@index([salesOrderId])
}

model SalesInvoiceLine {
  ...
  @@index([invoiceId])
}

model SalesInvoice {
  ...
  @@index([customerId, status, postedAt])
  @@index([organizationId, postedAt])
  @@index([organizationId, status])
}

model SalesOrder {
  ...
  @@index([organizationId, createdAt])
  @@index([customerId])
}

model StockMovement {
  ...
  @@index([inventoryItemId, postedAt])
}
```
