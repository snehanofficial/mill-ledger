# Finding F-018: Information Disclosure via Unscoped Dispatch List Endpoint

**ID**: F-018  
**Title**: `GET /api/v1/sales/dispatches` is accessible to salesmen and leaks company-wide customer orders, invoices, and dispatch records  
**Severity**: P1  
**Category**: Authorization / BOLA / Information Disclosure  
**Standard Refs**: OWASP API Security Top 10:2023 API1:2023 (Broken Object Level Authorization), OWASP Top 10:2021 A01:2021 (Broken Access Control)  

---

## Expected (Source)
Source: [docs/authorization-matrix.md](file:///home/snehan/projects/web/mill-ledger/docs/authorization-matrix.md), [docs/product-requirements.md](file:///home/snehan/projects/web/mill-ledger/docs/product-requirements.md) REQ-053.  
Salesmen must only see orders, customers, and dispatches associated with their own assigned territory and accounts. Company-wide commercial dispatch activity, vehicle numbers, invoice details, and other salesmen's client accounts must be restricted to management (`ADMIN`, `OWNER`).

---

## Delta
Any salesman can view all dispatches across the mill, including other salesmen's customers, billed amounts, invoice numbers, vehicle numbers, and products dispatched.

---

## Impact
- **Commercial & Confidentiality Risk**: A field salesman can monitor competitor accounts within the same company, view wholesale pricing discounts given to other distributors, and extract customer lists.

---

## Repro Steps
1. Authenticate as `salesman1@millledger.local`.
2. Issue `GET /api/v1/sales/dispatches`.
3. Observe HTTP 200 response returning dispatches belonging to all salesmen with customer names and invoice links.

---

## Root Cause
- [server/src/modules/sales/sales.routes.ts:296](file:///home/snehan/projects/web/mill-ledger/server/src/modules/sales/sales.routes.ts#L296): Authorizes `order:read` without passing user context to service.
- [server/src/modules/sales/dispatch.service.ts:268](file:///home/snehan/projects/web/mill-ledger/server/src/modules/sales/dispatch.service.ts#L268): `getDispatches` lacks user-scoping in the Prisma query.

---

## Recommended Fix
1. Pass `req.user` into `dispatchService.getDispatches(orgId, req.user)`.
2. In `getDispatches`, if `user.role === "SALESMAN"`, filter `salesOrder: { salesmanId: user.id }`.
3. Alternatively, require `authorize("order", "dispatch")` or dedicated `dispatch:read` permission.

---

## Regression Test to Add
Add test in `server/src/invoice-dispatch.test.ts` verifying that `GET /api/v1/sales/dispatches` called by a salesman returns only dispatches where `salesOrder.salesmanId === user.id`.
