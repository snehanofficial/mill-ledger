- **Severity**: P1
- **Category**: Frontend Performance / Bundle Optimization
- **Standard Refs**:
  - Web Performance Budgets: Initial JavaScript < 170 KB gzipped
  - Google Core Web Vitals: Impact on First Input Delay (FID) and Interaction to Next Paint (INP)

## Expected (Source)
- **Source**: Phase 10 Audit Prompt & Specification (`audit/01-expected-spec.md` REQ-055).
- Initial JavaScript delivered on page load must be under approximately **170 KB gzipped** to guarantee rapid parsing and execution on low-power mobile devices under slow network conditions.

## Delta
The initial page load bundle exceeds the 170 KB gzip budget by **+87.54 KB (+51.5% over budget)**.
Key drivers of the bundle bloat:
1. `dexie.js` (197.7 KB raw) is eagerly bundled into `index-BzFjHkL7.js` rather than being code-split and loaded only when offline storage or outbox operations are used.
2. `vendor-ui-CzUsY5oe.js` (151.63 KB raw / 46.76 KB gzip) eagerly preloads all of Radix UI primitives and cmdk even on unauthenticated `/auth/login`.
3. Redundant HTTP clients: Both `@better-fetch/fetch` (24.4 KB raw) and `axios` (~35 KB raw) are bundled simultaneously in the entry chunk.
4. Ghost dependency: `"cn": "^0.5.2"` is declared in `package.json` despite being unused.

---

## Impact
- **Who is hurt**: Field salesmen loading MillLedger on low-cost Android phones over 3G/4G connections.
- **How**: High initial download time, high CPU parse/eval time (~1.2s on mobile), delaying time-to-interactive and driving up LCP.

---

## Repro Steps
1. Run `pnpm --filter client build`.
2. Inspect `client/dist/index.html` modulepreloads and measure cumulative gzip size of loaded scripts.
3. Observe initial gzipped JS is 257.54 KB.

---

## Root Cause
- File: [`client/vite.config.ts`](file:///home/snehan/projects/web/mill-ledger/client/vite.config.ts#L61-L85)
  - `manualChunks` groups all Radix UI and cmdk into `vendor-ui` which is modulepreloaded in `index.html`.
  - Top-level import of `offlineDb` / `sync-engine` in application components drags the entire Dexie library into the entry chunk.
  - Coexistence of Better Auth (`@better-fetch`) and Axios.

---

## Recommended Fix (Do Not Apply)
1. Dynamically import Dexie and the offline sync engine on-demand: `const { offlineDb } = await import("@/offline/db")`.
2. Replace Axios with native `fetch` (or Better Auth's `@better-fetch`) to eliminate 35 KB of duplicate HTTP client code.
3. Remove unused `"cn": "^0.5.2"` from `client/package.json`.
4. Ensure `vendor-ui` is only loaded inside `AuthenticatedLayout` rather than modulepreloaded on the public login page.
