# Finding F-011: Financial Year Calculation Uses Local Server Timezone Causing UTC Misclassification on FY Boundary

**ID**: F-011  
**Title**: `financeService.getFinancialYear()` relies on Node process timezone, misclassifying April 1st morning invoices into previous financial year on UTC servers  
**Severity**: P1  
**Category**: Statutory Compliance / Timezone / Invoicing  
**Standard Refs**: Rule 46 of CGST Rules, 2017, Section 2(7) of the Income-tax Act, 1961 (Definition of Financial Year)  
**Status**: OPEN  

---

### Expected (source)
Under Indian statutory tax law (CGST Rules, 2017 Rule 46(b)), invoice consecutive numbering series are bounded strictly by the Indian Financial Year (April 1st 00:00:00 IST to March 31st 23:59:59 IST). Any transaction occurring on or after 1st April 00:00:00 IST belongs to the new Financial Year (e.g. `2026-27`), regardless of what server or cloud container timezone is configured.

### Actual (evidence links)
In [finance.service.ts:25-34](file:///home/snehan/projects/web/mill-ledger/server/src/modules/finance/finance.service.ts#L25-L34):
```typescript
getFinancialYear(date: Date = new Date()): string {
  const year = date.getFullYear();
  const month = date.getMonth(); // 0-indexed: 0 = Jan, 3 = Apr
  if (month >= 3) {
    return `${year}-${(year + 1).toString().slice(-2)}`;
  } else {
    return `${year - 1}-${year.toString().slice(-2)}`;
  }
}
```
`date.getFullYear()` and `date.getMonth()` return local time values for the current process environment.
When tested in `/audit/scripts/test-tz.ts` under standard production cloud timezone `TZ=UTC`:
- Date input: `2026-04-01T01:30:00+05:30` (1:30 AM IST on April 1st).
- UTC representation: `2026-03-31T20:30:00.000Z` (March 31st).
- `date.getMonth()` evaluated to `2` (March).
- Result: **`2025-26`** instead of statutory expected **`2026-27`**.
- Observed Evidence:
  ```text
  Current Process TZ: UTC
  Date ISO string (UTC): 2026-03-31T20:30:00.000Z
  date.getFullYear(): 2026
  date.getMonth(): 2 (0=Jan, 2=March, 3=April)
  financeService.getFinancialYear(d): 2025-26
  Statutory Expected FY in India (IST): 2026-27
  ```

### Delta
On standard UTC-configured cloud environments (AWS, GCP, Railway, Docker), any invoice generated during the first 5 hours and 30 minutes of the new financial year (between 00:00 IST and 05:30 IST on 1st April) is assigned the previous financial year's numbering sequence and stamped with the wrong FY prefix (`INV-2025-26-XXXX`).

### Impact
Violates CGST Rule 46. Invoices posted on April 1 morning are assigned to the closed previous year's book, creating invalid duplicate numbering in the prior year and throwing off annual statutory reconciliation.

### Repro Steps
1. Run `TZ=UTC pnpm --filter @mill-ledger/server exec tsx ../audit/scripts/test-tz.ts`.
2. Observe output `financeService.getFinancialYear(d): 2025-26` for input `2026-04-01T01:30:00+05:30`.

### Root Cause
[finance.service.ts:25-34](file:///home/snehan/projects/web/mill-ledger/server/src/modules/finance/finance.service.ts#L25-L34) directly invokes JavaScript `Date` getters without converting to Indian Standard Time (`timeZone: "Asia/Kolkata"`).

### Recommended Fix (do not apply)
Convert the date to IST before extracting year and month:
```typescript
const istDateStr = date.toLocaleDateString("en-CA", { timeZone: "Asia/Kolkata" }); // YYYY-MM-DD
const [yearStr, monthStr] = istDateStr.split("-");
const year = parseInt(yearStr, 10);
const month = parseInt(monthStr, 10); // 1-indexed: 4 = April
```
