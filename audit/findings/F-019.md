# Finding F-019: Missing React Router Route Guards and Dedicated 403 Access Denial Page

**ID**: F-019  
**Title**: Direct URL navigation to forbidden routes renders full operational page shells without route-level authorization guards or 403 pages  
**Severity**: P1  
**Category**: Frontend Security / Broken Access Control / UI Parity  
**Standard Refs**: OWASP Top 10:2021 A01:2021 (Broken Access Control), NN/g Heuristic #9 (Help Users Recognize and Recover from Errors), WCAG 2.2 SC 3.3.1 (Error Identification)  

---

## Expected (Source)
Source: [docs/ui-ux-spec.md](file:///home/snehan/projects/web/mill-ledger/docs/ui-ux-spec.md), [docs/authorization-matrix.md](file:///home/snehan/projects/web/mill-ledger/docs/authorization-matrix.md), [docs/product-requirements.md](file:///home/snehan/projects/web/mill-ledger/docs/product-requirements.md) REQ-053.  
When an authenticated user navigates directly via browser URL to a view for which their role lacks permissions (e.g. Salesman navigating to `/invoices`, `/payments`, `/production/today`, or `/purchases`), the router must prevent rendering the operational component and display an accessible, clear 403 Access Denied page explaining the restriction and providing a navigation link back to their allowed workspace.

## Actual (Evidence Links)
Evidence: Executed Playwright UI parity audit test [/audit/tests/ui-parity.spec.ts](file:///home/snehan/projects/web/mill-ledger/audit/tests/ui-parity.spec.ts), saved matrix in [/audit/evidence/role-ui-route-matrix.csv](file:///home/snehan/projects/web/mill-ledger/audit/evidence/role-ui-route-matrix.csv).

In [client/src/app.tsx:113-234](file:///home/snehan/projects/web/mill-ledger/client/src/app.tsx#L113-L234) and [client/src/layouts/authenticated-layout.tsx:26-77](file:///home/snehan/projects/web/mill-ledger/client/src/layouts/authenticated-layout.tsx#L26-L77):
- All routes under `/` are wrapped by `AuthenticatedLayout`.
- `AuthenticatedLayout` only checks `if (!user) return <Navigate to="/auth/login" ... />;`.
- There are ZERO route-level role checks, guard components, or loader checks on any of the child routes (`/orders`, `/invoices`, `/payments`, `/dispatch`, `/purchases`, `/production/*`, `/reports/*`, `/settings`).
- When `SALESMAN` navigates directly to `/invoices`, `/payments`, `/production/today`, or `/purchases`:
  1. The browser navigates to the URL.
  2. The page shell, headers, and tabs mount successfully.
  3. The page component fires queries to `/api/v1/finance/invoices`, `/api/v1/payments`, etc., which are rejected with HTTP 403 by the backend.
  4. The frontend displays empty tables, zero KPI totals, or infinite loading states. Zero 403 Forbidden page or banner is displayed.
- On `/orders`, both `ACCOUNTANT` and `OWNER` are presented with the "New order" button despite having zero create permissions.

---

## Delta
Role-based route restrictions exist only as conditional sidebar link hiding in `nav-config.tsx`. Direct URL navigation completely bypasses frontend authorization checks. Forbidden pages render their full DOM structure and attempt unauthorized network requests rather than enforcing an immediate 403 barrier.

---

## Impact
- **Security & User Confusion**: Users are misled into thinking pages are empty or broken rather than restricted. Sensitive UI layouts, column headers, form fields, and operational workflows are exposed to unauthorized roles.

2. In the browser address bar, enter `http://localhost:5173/invoices` or `http://localhost:5173/payments`.
3. Press Enter.

---

## Root Cause
- [client/src/layouts/authenticated-layout.tsx:54](file:///home/snehan/projects/web/mill-ledger/client/src/layouts/authenticated-layout.tsx#L54): AuthenticatedLayout enforces authentication but does not evaluate role permissions against the matched route.
- [client/src/app.tsx:113-234](file:///home/snehan/projects/web/mill-ledger/client/src/app.tsx#L113-L234): Route definitions lack permission metadata and role guard wrappers.

---

## Recommended Fix
1. Define a `ProtectedRoute` wrapper component or route loader that compares `user.role` against route permission requirements.
2. If unauthorized, render a standardized `<ForbiddenPage />` (HTTP 403 equivalent) with a descriptive alert and a "Back to dashboard/orders" CTA.
3. Conditionally render action buttons (e.g., "New order", "Record payment") based on `hasPermission(user.role, resource, action)`.
