# Finding F-027: Stock Hoarding & Inventory Denial of Service via Non-Expiring Reservations

**ID**: F-027  
**Title**: Stock reservations lack TTL and expiration semantics, enabling inventory lockup and order fulfillment denial of service  
**Severity**: P1  
**Category**: Business Logic Abuse / Denial of Service  
**Standard Refs**: OWASP Top 10:2021 A04:2021 (Insecure Design), OWASP API Security Top 10:2023 API6:2023 (Unrestricted Access to Sensitive Business Flows), OWASP ASVS v4.0.3 Section 13.2.2 (Verify that business logic limits allow only authorized and timely state transitions)  

---

## Expected (Source)
Source: Problem Statement & Master Project Plan Domain Model.
Stock reservations held against approved sales orders must enforce a finite Time-To-Live (TTL) or reservation expiration window (e.g. 24–48 hours) or an automated expiration sweeper. If physical dispatch does not occur within the policy window, reservations must expire or alert floor supervisors to release committed inventory back to available stock.

---

## Actual (Evidence Links)
Evidence: Inspected [server/prisma/schema.prisma:664-682](file:///home/snehan/projects/web/mill-ledger/server/prisma/schema.prisma#L664-L682) and [server/src/modules/sales/sales.service.ts](file:///home/snehan/projects/web/mill-ledger/server/src/modules/sales/sales.service.ts).

1. In `model StockReservation`:
   ```prisma
   model StockReservation {
     id               String            @id @default(cuid())
     salesOrderId     String
     salesOrderLineId String
     inventoryItemId  String
     warehouseId      String
     reservedQuantity Decimal           @db.Decimal(18, 6)
     releasedQuantity Decimal           @default(0) @db.Decimal(18, 6)
     status           ReservationStatus @default(ACTIVE)
     createdAt        DateTime          @default(now())
     updatedAt        DateTime          @updatedAt
   }
   ```
   There is no `expiresAt` column or reservation lifecycle timestamp.
2. In `sales.service.ts` and codebase wide:
   There is zero scheduled background process, queue worker, or cron job to identify or expire stale active reservations.
3. Coupled with Finding [F-017](file:///home/snehan/projects/web/mill-ledger/audit/findings/F-017.md) (Mass Assignment allowing salesmen to set `status: "APPROVED"` on order creation), a salesman can submit orders that immediately create permanent, non-expiring `StockReservation` rows for the entire mill's on-hand stock.

---

## Delta
Stock reservations have no expiration mechanism or TTL. Once reserved, stock remains locked indefinitely in `status: ACTIVE` until manually rejected by an Admin or physically dispatched.

---

## Impact
- **Supply Chain Disruption**: Rogue or accidental large orders lock down available inventory. Other salesmen and genuine customer orders receive false stock-shortage rejections ("Insufficient available stock"), halting sales operations.
- **Physical Mill Bottleneck**: Floor operators cannot reallocate locked finished goods without administrative intervention.

---

## Repro Steps
1. Place order `SO-TEST-LOCK` for 500 bags of Atta with `status: "APPROVED"`.
2. Verify `stock_reservation` row is created with `status: ACTIVE`.
3. Check available stock via `GET /api/v1/sales/orders/stock-availability`; available stock drops to 0.
4. Wait indefinitely; the reservation never expires, and available stock remains 0.

---

## Root Cause
- Schema deficiency: `model StockReservation` omits `expiresAt DateTime?`.
- Architecture deficiency: Lack of a scheduled cron/background worker to clean up or transition timed-out reservations from `ACTIVE` to `EXPIRED`.

---

## Recommended Fix (Do Not Apply)
1. Add `expiresAt DateTime` to `StockReservation` schema (e.g. `createdAt + 48 hours`).
2. Add background job or on-access check in `getAvailableStock` that treats `status == ACTIVE AND expiresAt < NOW()` as expired.
3. Automatically mark expired reservations as `EXPIRED` and revert order status to `RESERVATION_EXPIRED` or notify dispatchers.

---

## Regression Test to Add
Add integration test in `server/src/orders.test.ts` verifying that stock reservations older than the allowed TTL automatically release their reserved quantity back to available stock.
