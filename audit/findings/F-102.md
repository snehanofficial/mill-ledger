# F-102: Missing Readiness Endpoint, Health Check Omits Database Connectivity, and Express Missing Request Timeout & Trust Proxy Settings

- **ID**: F-102
- **Title**: Missing Readiness Endpoint, Health Check Omits Database Connectivity, and Express Missing Request Timeout & Trust Proxy Settings
- **Severity**: P1
- **Category**: Runtime Reliability & Container Operations
- **Standard Refs**:
  - Kubernetes Health Check Best Practices (Liveness vs Readiness Probes)
  - OWASP Top 10:2021 A05:2021 (Security Misconfiguration)
  - Express.js Behind Proxies Documentation (`trust proxy`)

---

## Expected (Source)
- **Source**: Master Rulebook and Production Runtime Specifications:
  - Separate health (`/health` or liveness) and readiness (`/ready` or readiness) endpoints must exist.
  - The readiness endpoint must actively verify connectivity to dependent services (specifically executing a probe query against PostgreSQL: `prisma.$queryRaw` or `SELECT 1`).
  - Express must configure `trust proxy` appropriately when deployed behind reverse proxies, container gateways, or load balancers so that `req.ip` reflects the true client IP.
  - Request timeouts must be enforced to prevent hung client or database sockets from exhausting server worker threads.

---

## Actual (Evidence Links)
1. **Health Route Omits Database Connectivity**:
   - [`server/src/modules/health/health.controller.ts:4-13`](file:///home/snehan/projects/web/mill-ledger/server/src/modules/health/health.controller.ts#L4-L13):
     ```typescript
     export function getHealth(_req: Request, res: Response<HealthResponse>): void {
       const healthData: HealthResponse = {
         status: "ok",
         timestamp: new Date().toISOString(),
         uptime: process.uptime(),
         service: "mill-ledger-server",
         version: "0.1.0",
       };
       res.status(200).json(healthData);
     }
     ```
   - No database query is executed. Even if PostgreSQL is completely offline, crashing, or unreachable, `GET /api/v1/health` returns HTTP 200 OK.
2. **Readiness Probe Completely Missing**:
   - Probing `GET /api/v1/ready` returns HTTP 404 (`audit/evidence/runtime-ops-results.json`).
3. **Trust Proxy Not Configured**:
   - [`server/src/app.ts`](file:///home/snehan/projects/web/mill-ledger/server/src/app.ts) never calls `app.set("trust proxy", ...)`.
   - Running live inspection (`app.get("trust proxy")`) returns `false`.
   - Sending `X-Forwarded-For: 203.0.113.195, 10.0.0.1` resulted in `req.ip` evaluating to `127.0.0.1`. The client's true IP is discarded.
4. **Missing Request Timeouts**:
   - Neither Express level request timeout middleware nor `pg.Pool` statement timeouts (`server/src/db/client.ts`) are configured.
5. **Incomplete Graceful Shutdown**:
   - In [`server/src/index.ts:12-18`](file:///home/snehan/projects/web/mill-ledger/server/src/index.ts#L12-L18), `server.close()` is invoked, but `prisma.$disconnect()` is omitted, and no timeout is set for forcefully terminating connections if an in-flight request hangs indefinitely.

---

## Delta
- The API lacks a readiness probe, reports false healthy status during total database outages, discards client IPs due to disabled `trust proxy`, and has no request timeout safeguards.

---

## Impact
- **Traffic Blackholing During Outages**: Load balancers and Kubernetes orchestrators relying on `/api/v1/health` will keep routing incoming user traffic to container instances whose database connection pool is broken or exhausted.
- **Defeated IP Rate Limiting & Fraud Detection**: With `trust proxy: false`, all requests passing through an Nginx/ALB reverse proxy appear as originating from the proxy's internal IP (e.g. `127.0.0.1`), causing rate limiters to either block all users simultaneously or fail to block abusive IP addresses.
- **Resource Exhaustion**: Hanging queries can tie up server connections indefinitely without timing out.

## Root Cause
- Health router implemented as a static heartbeat without dependency checks; Express proxy and timeout configurations were never added.

---

## Recommended Fix
1. Add a dedicated readiness endpoint:
   ```typescript
   app.get("/api/v1/health/ready", async (_req, res) => {
     try {
       await prisma.$queryRaw`SELECT 1`;
       res.status(200).json({ status: "ready", database: "connected" });
     } catch (err) {
       res.status(503).json({ status: "unhealthy", database: "disconnected" });
     }
   });
   ```
2. In `server/src/app.ts`, add `app.set("trust proxy", env.NODE_ENV === "production" ? 1 : false);`.
3. Add request timeout middleware (e.g. `connect-timeout` with 30s limit) and configure `statement_timeout: 10000` on `pg.Pool`.
4. In `server/src/index.ts`, call `await prisma.$disconnect()` during graceful shutdown and add a 10s fallback `setTimeout(() => process.exit(1), 10000).unref()`.
