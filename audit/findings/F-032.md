### Expected (source)
Per [architecture.md](file:///home/snehan/projects/web/mill-ledger/docs/architecture.md) and OWASP ASVS Sec 5.1.4, enterprise APIs must reject unknown or unrecognized properties with HTTP 400 Bad Request to prevent parameter tampering, silent data truncation, and client typos from passing undetected.

### Actual (evidence links)
Search across `server/src/modules/` confirms that not a single Zod schema uses `.strict()`:
```bash
grep -rn "\.strict" server/src/ shared/src/
# Result: 0 matches
```
In Zod 3, `z.object({...})` defaults to `strip` mode. When clients transmit unknown properties (such as misspelled fields like `{ "discountAmnt": 50 }` instead of `{ "discountAmount": 50 }`, or malicious properties like `{ "__proto__": ... }`), the backend silently discards the fields without alerting the caller.

Execution of [/audit/scripts/verify-validation-inventory.ts](file:///home/snehan/projects/web/mill-ledger/audit/scripts/verify-validation-inventory.ts) confirms that 10 out of 10 mutating endpoints tested returned HTTP 200 or 201 when submitted with unknown fields (`{ "__unknownProperty_test_xyz": "value" }`):
- `POST /api/v1/sales/orders`: Status 201 (Accepted)
- `PUT /api/v1/sales/orders/:id`: Status 200 (Accepted)
- `POST /api/v1/sales/dispatches`: Status 201 (Accepted)
- `POST /api/v1/finance/invoices`: Status 201 (Accepted)
- `POST /api/v1/payments`: Status 201 (Accepted)

Artifact: [/audit/evidence/validation-inventory-results.json](file:///home/snehan/projects/web/mill-ledger/audit/evidence/validation-inventory-results.json).

### Delta
Expected HTTP 400 Bad Request stating "Unrecognized key(s) in object: '__unknownProperty_test_xyz'". Actual behavior is silent acceptance (HTTP 200/201) with silent stripping of unknown fields.

### Impact
Silent data loss. A mobile salesman submitting critical fields with slight casing or spelling discrepancies will receive a 201 Created response while their intended adjustments or discounts are silently discarded by the server.

### Repro Steps
1. Authenticate as Salesman or Admin.
2. Send `POST /api/v1/sales/orders` with an unknown property:
   ```json
   {
     "customerId": "<id>",
     "lines": [{ "productVariantId": "<id>", "quantity": 1 }],
     "specialDiscountPercentage": 15
   }
   ```
3. Observe HTTP 201 Created response.
4. Verify database: order is created, but `specialDiscountPercentage` was silently stripped with zero warning.
5. Automated script: `node --env-file=audit/.env.audit server/node_modules/tsx/dist/cli.mjs audit/scripts/verify-validation-inventory.ts`.

### Root Cause
All schemas in `server/src/modules/*/*.routes.ts` are declared as plain `z.object({...})` without appending `.strict()`.

### Recommended Fix (do not apply)
Append `.strict()` to all root and nested Zod schemas, or configure a reusable Zod helper:
```typescript
export const strictObject = <T extends z.ZodRawShape>(shape: T) => z.object(shape).strict();
```

`audit/tests/strict-schema.test.ts` submitting payload with `{ "__unexpected": true }` to each endpoint and asserting HTTP 400 with `unrecognized_keys` code.
