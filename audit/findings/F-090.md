# F-090: Soft 404 Status and Unauthenticated Redirect Hijacking on Non-Existent Routes

- **ID**: F-090
- **Title**: Soft 404 Status and Unauthenticated Redirect Hijacking on Non-Existent Routes
- **Severity**: P1
- **Category**: HTTP Semantics & Router Architecture
- **Standard Refs**:
  - RFC 9110: HTTP Semantics, Section 15.5.5 (404 Not Found)
  - Google Search Central: Soft 404 Errors & Troubleshooting
  - OWASP Top 10:2021 A01:2021 (Broken Access Control - Improper Handling of Unknown Resources)

---

## Expected (Source)
- **Source**: RFC 9110 Section 15.5.5:
  - When an origin server does not find a current representation for the target resource, it must respond with status code `404 Not Found`.
  - In a client-side SPA architecture, non-existent routes requested by unauthenticated users or crawlers should not be falsely answered with HTTP 200 OK (causing Soft 404 indexing errors in search engines) nor redirected to `/auth/login` as if the route were an authenticated endpoint.

      ```tsx
        return <Navigate to="/auth/login" state={{ from: location }} replace />;
      }
      ```
    - The visitor is redirected to `/auth/login` instead of being shown a 404 page.

---

## Delta
1. HTTP requests to unknown URIs return HTTP 200 OK with the SPA shell instead of HTTP 404.
2. In-browser navigation to non-existent paths redirects unauthenticated users to `/auth/login` rather than presenting the `NotFoundPage`.

---

## Impact
- **Who is hurt**: Search engines, visitors with broken/typo URLs, and site administrators.
- **How**:
  - Search crawlers waste crawl budget indexing thousands of non-existent URLs as valid pages, penalizing domain quality score due to duplicate Soft 404 pages.
  - Users typing mistyped URLs (e.g. `/loginn`, `/help`) are silently bounced to the login form without any indication that their requested page does not exist.

---

## Repro Steps
1. Run `curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:4173/random-gibberish-path-xyz`: observe `200`.
2. In a browser (incognito/unauthenticated), navigate to `http://127.0.0.1:4173/this-does-not-exist`.
3. Observe browser address bar immediately redirects to `http://127.0.0.1:4173/auth/login`.

---

## Root Cause
- File: [`client/src/app.tsx`](file:///home/snehan/projects/web/mill-ledger/client/src/app.tsx#L198)
  - The catch-all wildcard route `{ path: "*", element: <NotFoundPage /> }` is registered as a child of `AuthenticatedLayout` rather than at the root level of the router.
- File: Production static server / Vite SPA configuration:
  - Static file fallback emits status `200` for all non-static paths.

---

## Recommended Fix (Do Not Apply)
1. Move the catch-all `{ path: "*", element: <NotFoundPage /> }` to the root router level in `client/src/app.tsx`, outside `AuthenticatedLayout`.
2. In SSR or edge routing, return an actual HTTP 404 status code when delivering the 404 page representation.
