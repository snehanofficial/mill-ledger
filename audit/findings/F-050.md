# F-050: Incomplete Dark Mode Infrastructure and Design Token Fragmentation in CSS Output

- **ID**: F-050
- **Title**: Incomplete Dark Mode Infrastructure and Design Token Fragmentation in CSS Output
- **Severity**: P3
- **Category**: Visual Quality / Code Hygiene / CSS Architecture
- **Standard refs**: NN/g H8 (Aesthetic and Minimalist Design), Phase 7 Specification Check 7 & Check 8

---

## 1. Expected vs Actual

- **EXPECTED (Phase 7 Spec Check 7 & Check 8, UI-UX-Spec)**:
  1. The application styling must adhere to a unified token scale for color, spacing, typography, and border radius without ad hoc utility proliferation.
  2. If dark mode is supported, it must include a working theme switcher (or system preference detection) and a comprehensive `.dark` token definition block in CSS.
- **ACTUAL (evidence: `audit/evidence/css-tokens-analysis.json`, `client/src/index.css:5-60`, `client/src/components/**/*.tsx`)**:
  1. **Token Fragmentation**: Automated analysis of the compiled CSS (`index-Dj0XqGw5.css`) revealed significant design token sprawl:
     - **95 distinct color values** in compiled CSS (violating the unified palette concept).
     - **18 distinct font sizes** (mixing ad hoc arbitrary values with Tailwind sizes).
     - **23 distinct spacing values** and **12 distinct border radius definitions** (mixing `rounded-panel`, `rounded-control`, `rounded-md`, `rounded-xl`, `rounded-lg`, `rounded-2xs`).
     - **5 distinct font families**.
  2. **Incomplete Dark Mode**: `client/src/index.css:5` hardcodes `:root { color-scheme: light; }`. There is zero `.dark` class definition block in `index.css`. There is zero theme switcher toggle in the UI. Yet dozens of UI components contain dead `dark:...` utility classes (e.g. `dark:text-amber-400`, `dark:bg-emerald-950`) that can never activate.
- **DELTA**:
  Design tokens are fragmented across arbitrary Tailwind classes; dark mode code is dead and unfunctional.

---

## 2. Impact

- **Who is hurt**: Frontend maintainers inheriting bloated stylesheets; users operating tablets at night or in dimly lit factory control rooms who expect dark mode functionality indicated by the code.
- **Operational consequence**: Styling inconsistency across screens; increased CSS bundle weight with unused dark utility classes.

---

## 3. Repro Steps & Root Cause

### Repro Steps
1. Run `pnpm --filter server exec tsx ../audit/scripts/analyze-css-tokens.ts`.
2. Observe 95 distinct colors and 12 distinct border radii in compiled CSS.
3. Attempt to trigger dark mode by adding class `dark` to `<html>` or `<body>`.
4. Observe: Background and text colors remain light; only isolated amber/green badges switch to dark variants, resulting in unreadable contrast anomalies.

### Root Cause
1. Incomplete styling migration: Developers added shadcn components with dark variants but never configured the root theme provider or `.dark` CSS variable map.

---

## 4. Recommended Fix & Regression Test

### Recommended Fix (Do Not Apply - Audit Only)
1. Complete dark mode implementation by adding a `.dark` CSS variable block to `index.css` and a theme switcher toggle in `StickyHeader`.
2. Or alternatively, strip all dead `dark:` utility classes and standardize on the semantic design tokens in `client/src/index.css`.

### Regression Test to Add
- Add Playwright spec `tests/design-tokens.spec.ts` asserting:
  - Compiled CSS contains `<= 25` distinct semantic color variables.
  - Adding `.dark` to `<html>` correctly updates CSS variables `--background` to a dark hex value.

- **Effort**: Small
- **Status**: VERIFIED

---

## 5. Remediation & Verification

### Implementation
- **Tailwind 4 Dark Variant**: Added `@variant dark (&:where(.dark, .dark *));` and comprehensive `.dark` CSS custom properties block to `client/src/index.css` defining semantic tokens for dark background (`#09090b`), foreground (`#f4f4f5`), card (`#121215`), border (`#27272a`), muted, primary, status alerts, and sidebar.
- **Reactive Theme Hook**: Implemented `client/src/hooks/use-theme.ts` managing `light` | `dark` | `system` theme selection, synchronization with system media query (`prefers-color-scheme: dark`), `localStorage` persistence, and toggling `dark` class / `color-scheme` property on `document.documentElement`.
- **Accessible Theme Switcher UI**: Integrated theme switch button with Sun/Moon icons into `StickyHeader` alongside Tamil/English language selector and Help guide trigger, plus matching theme switch items in `SidebarUserMenu` and avatar dropdown menu in `client/src/components/shell/authenticated-shell.tsx`.

### Regression Test
- Added `audit/tests/f-050-regression.test.ts` verifying:
  1. `client/src/index.css` defines `@variant dark` and `.dark` CSS tokens.
  2. `client/src/hooks/use-theme.ts` manages document theme and media listeners.
  3. `client/src/components/shell/authenticated-shell.tsx` renders accessible theme toggle buttons and dropdown items.
