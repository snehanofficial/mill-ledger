# F-087: Absence of Persistent Storage Request Permitting Silent Browser Eviction of Offline Outbox Queue

- **ID**: F-087
- **Title**: Absence of Persistent Storage Request Permitting Silent Browser Eviction of Offline Outbox Queue
- **Severity**: P2
- **Category**: PWA Architecture / Offline Storage Resilience
- **Standard Refs**:
  - `docs/offline-sync.md` ("Storage: Dexie/IndexedDB user-scoped snapshots, drafts, and outbox commands", "Browser storage eviction is possible even with persistent-storage requests")
  - W3C Storage Standard: Persistent Storage API (`navigator.storage.persist()`)
  - Progressive Web Application (PWA) Storage Resilience Guidelines

---

## Expected (Source)
- **Source**: `docs/offline-sync.md` ("Browser storage eviction is possible even with persistent-storage requests") and W3C Storage Standard.
- To prevent mobile browsers from silently evicting local IndexedDB databases under device memory or disk storage pressure, a progressive web application holding critical offline business commands (orders, payments) must actively request persistent storage via `navigator.storage.persist()`.

---

## Delta
The application stores mission-critical offline sales orders in browser IndexedDB under the default "best-effort" eviction tier without ever requesting persistent storage permission.

---

## Impact
- **Who is hurt**: Field salesmen collecting orders on low-cost Android mobile devices with limited storage (16GB - 32GB).
- **How**: When device storage becomes constrained (e.g. system updates or camera photos), Android Chrome automatically purges "best-effort" site data without user notification. The salesman's entire local outbox of queued orders is wiped by the OS before reaching the factory.

---

## Repro Steps
1. Open the app on Android Chrome.
2. Queue 5 offline orders in the Device Outbox.
3. In DevTools, inspect `navigator.storage.persisted()`: returns `false`.
4. Trigger OS low-disk storage threshold: Chrome purges best-effort IndexedDB storage for the origin, permanently deleting all pending orders.

---

## Root Cause
- File: [`client/src/offline/db.ts`](file:///home/snehan/projects/web/mill-ledger/client/src/offline/db.ts#L70)
  - `MillLedgerDatabase` instantiates Dexie but omits a call to request persistent storage upon initialization.

---

## Recommended Fix (Do Not Apply)
1. In `client/src/offline/sync-engine.ts` or during database initialization, invoke:
   ```ts
   if (typeof navigator !== "undefined" && navigator.storage && navigator.storage.persist) {
     navigator.storage.persist().then((isPersisted) => {
       if (!isPersisted) {
         console.warn("Storage persistence not granted; offline outbox may be subject to browser eviction.");
       }
     });
   }
   ```
