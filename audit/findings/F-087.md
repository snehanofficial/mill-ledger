# F-087: Absence of Persistent Storage Request Permitting Silent Browser Eviction of Offline Outbox Queue

- **ID**: F-087
- **Title**: Absence of Persistent Storage Request Permitting Silent Browser Eviction of Offline Outbox Queue
- **Severity**: P2
- **Category**: PWA Architecture / Offline Storage Resilience
- **Standard Refs**:
  - `docs/offline-sync.md` ("Storage: Dexie/IndexedDB user-scoped snapshots, drafts, and outbox commands", "Browser storage eviction is possible even with persistent-storage requests")
  - W3C Storage Standard: Persistent Storage API (`navigator.storage.persist()`)
  - Progressive Web Application (PWA) Storage Resilience Guidelines

---

## Expected (Source)
- **Source**: `docs/offline-sync.md` ("Browser storage eviction is possible even with persistent-storage requests") and W3C Storage Standard.
- To prevent mobile browsers from silently evicting local IndexedDB databases under device memory or disk storage pressure, a progressive web application holding critical offline business commands (orders, payments) must actively request persistent storage via `navigator.storage.persist()`.

---

## Actual (Evidence Links)
- **Evidence**:
  - Search across `client/src/` for `navigator.storage` or `persist` returned 0 matches before remediation.
  - `MillLedgerDatabase` initialized Dexie with default best-effort storage tier.
  - In constrained mobile environments, browser cleared un-persisted origin storage without warning.

---

## Delta
The application stored mission-critical offline sales orders in browser IndexedDB under the default "best-effort" eviction tier without ever requesting persistent storage permission.

---

## Impact
- **Who is hurt**: Field salesmen collecting orders on low-cost Android mobile devices with limited storage (16GB - 32GB).
- **How**: When device storage becomes constrained, mobile browsers automatically purge "best-effort" site data, permanently deleting un-synced orders.

---

## Root Cause
- File: `client/src/offline/db.ts`
  - `MillLedgerDatabase` omitted a call to request persistent storage upon initialization.

---

## Fix & Verification

### Implementation
- `client/src/offline/db.ts`:
  * Defined and exported `requestPersistentStorage()` using W3C Storage Standard API (`navigator.storage.persist()`).
  * Checks `navigator.storage.persisted()` before requesting to avoid redundant prompt invocations.
  * Triggered `requestPersistentStorage()` automatically upon database instantiation in browser environments.
- `client/src/offline/sync-engine.ts`:
  * Invokes `requestPersistentStorage()` when queuing new offline orders.
  * Re-exports `requestPersistentStorage`.
- `client/src/offline/use-offline.ts`:
  * Invokes `requestPersistentStorage()` on mount inside `useSyncManager`.
- `client/src/offline/db.test.ts`:
  * Added unit test coverage for persistent storage requesting, early return when already persisted, and graceful degradation.
