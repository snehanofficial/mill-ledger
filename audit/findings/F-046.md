# F-046: Ephemeral Filter, Sort, and Tab State Not Preserved in URL

- **ID**: F-046
- **Title**: Ephemeral Filter, Sort, and Tab State Not Preserved in URL
- **Severity**: P2
- **Category**: UX / Information Architecture / Deep Linking
- **Standard refs**: NN/g H3 (User Control and Freedom), NN/g H4 (Consistency and Standards), Phase 7 Specification Check 4

---

## 1. Expected vs Actual

- **EXPECTED (Phase 7 Spec Check 4, UI-UX-Spec)**:
  All table filter controls (status dropdown, date range, search query) and active tab states must be synchronized with the browser URL search params (`useSearchParams`). A user must be able to bookmark, refresh, share a filtered table view (e.g. `/orders?status=SUBMITTED&customer=Madurai`), and use browser Back/Forward navigation without losing their working state.
- **ACTUAL (evidence: `client/src/pages/orders-page.tsx:84-110`, `client/src/pages/invoices-page.tsx:68-80`, `client/src/pages/reports-page.tsx:25-35`)**:
  Zero files in `client/src` import or use `useSearchParams` or `URLSearchParams`. All filters, tabs, search terms, and date ranges are held strictly in local component `useState`:
  ```tsx
  // orders-page.tsx:84-88
  const [activeTab, setActiveTab] = useState<"stream" | "approved" | "completed">("stream");
  const [searchQuery, setSearchQuery] = useState("");
  const [statusFilter, setStatusFilter] = useState<string>("ALL");
  ```
  Navigating away from `/orders` (or hitting F5 / sharing a link) immediately destroys all active filter selections and resets the view to default.
- **DELTA**:
  URL state synchronization is completely unimplemented across the client. Links cannot be shared with colleagues; browser "Back" navigation resets all user filters.

---

## 2. Impact

- **Who is hurt**: Factory owners and accountants reviewing ledger anomalies who want to copy-paste a filtered invoice URL in WhatsApp or email, or who click into an order details view and press "Back" only to find their 5 applied filters wiped clean.
- **Operational consequence**: Wasted time reapplying complex date and customer filters; inability to communicate specific ledger filter contexts between staff.

---

## 3. Repro Steps & Root Cause

### Repro Steps
1. Navigate to `http://127.0.0.1:4173/orders`.
2. Select status filter "PENDING" and type "Madurai" in search input.
3. Observe URL in address bar remains `http://127.0.0.1:4173/orders` (no query parameters).
4. Refresh browser (F5).
5. Observe: Status filter resets to "ALL", search resets to empty.

### Root Cause
1. Page components use isolated `useState()` instead of React Router's `useSearchParams()`.

---

## 4. Recommended Fix & Regression Test

### Recommended Fix (Do Not Apply - Audit Only)
1. Implement a custom hook `useUrlState<T>(key, defaultVal)` wrapping `useSearchParams()`.
2. Bind tab values, search inputs, and status dropdowns to URL query params (`?tab=...&status=...&q=...`).

### Regression Test to Add
- Add Playwright spec `tests/url-filters.spec.ts` asserting:
  - Changing status filter to "APPROVED" updates URL to `?status=APPROVED`.
  - Reloading page with `?status=APPROVED` pre-selects "APPROVED" in the filter dropdown.
