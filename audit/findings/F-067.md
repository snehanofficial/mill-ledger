# Finding F-067: Missing Optimistic Mutations with Rollback Handlers Across Server Workflows

- **ID**: F-067
- **Title**: Missing Optimistic Mutations with Rollback Handlers Across Server Workflows
- **Severity**: P2
- **Category**: Architecture / Feedback Patterns
- **Standard Refs**:
  - TanStack Query v5 Best Practices: Optimistic Updates (`onMutate`, `onError`, `onSettled`)
  - NN/g: Interaction Latency & Feedback Timing (Immediate user response)
  - Master Rulebook Phase 9 Requirement: "optimistic updates with rollback and a visible error;"

---

## Expected Behavior
Per Master Rulebook Phase 9 and TanStack Query best practices:
Interactive operational workflows (order approval/rejection, dispatch confirmation, payment recording, production posting) must provide optimistic UI updates:
1. Immediately apply the intended state change to the query cache on mutation initiation (`onMutate`).
2. If the server request fails or encounters network disconnection, cleanly roll back the cache to its previous snapshot (`onError`).
3. Display an explicit, visible error toast or banner informing the user of the rollback.

---

## Actual Behavior
1. Across all core operational pages (`orders-page.tsx`, `purchases-page.tsx`, `dispatch-page.tsx`, `production-page.tsx`, `payments-page.tsx`, `invoices-page.tsx`), all `useMutation` hooks use standard synchronous server awaiting:
   ```tsx
   // Example from orders-page.tsx:315:
   const approveMutation = useMutation({
     mutationFn: async (orderId: string) => {
       const res = await api.post(`/api/v1/orders/${orderId}/approve`);
       return res.data;
     },
     onSuccess: () => {
       queryClient.invalidateQueries({ queryKey: ["orders"] });
       toast.success("Order approved");
     },
     onError: (err: any) => {
       toast.error(err.response?.data?.message || "Failed to approve order");
     },
   });
   ```
2. Zero mutations across the application define `onMutate` rollback handlers or snapshot previous query cache data.
3. While the HTTP request is in-flight, the UI blocks with an active button spinner (`isPending`). If the request fails, no optimistic state was rendered, so no rollback occurs.
4. Programmatic audit evidence in `audit/evidence/motion/metrics/feedback-patterns-audit.json`:
   - `optimisticUpdatesCheck.presentInServerMutations: false`
   - `reason: "Mutations across Invoices, Orders, Production, Purchases and Payments do not define onMutate rollback handlers; UI awaits server response with button loading spinner."`

---

## Delta
Optimistic updates with rollback do not exist in the server-connected application workflows. The application relies entirely on synchronous round-trip latency.

---

## Impact
On slow or intermittent 3G/4G connections on the mill premises, shop managers experience delayed UI feedback (500ms to 3000ms) when approving orders or posting dispatches, making the app feel slow and unresponsive.

---

## Repro Steps
1. Navigate to `/orders`.
2. Locate an order in `SUBMITTED` status.

## Recommended Fix
Implement TanStack Query optimistic update patterns:
```tsx
onMutate: async (orderId) => {
  await queryClient.cancelQueries({ queryKey: ["orders"] });
  const previousOrders = queryClient.getQueryData(["orders"]);
  queryClient.setQueryData(["orders"], (old: any) =>
    old.map((o: any) => o.id === orderId ? { ...o, status: "APPROVED" } : o)
  );
  return { previousOrders };
},
onError: (err, newTodo, context) => {
  queryClient.setQueryData(["orders"], context?.previousOrders);
  toast.error("Approval failed. State reverted.");
},
onSettled: () => {
  queryClient.invalidateQueries({ queryKey: ["orders"] });
}
```
