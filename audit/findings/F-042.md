# F-042: Ordering Interface Missing Required Product Tiles, Visual Images, and Accessible Quantity Steppers

- **ID**: F-042
- **Title**: Ordering Interface Missing Required Product Tiles, Visual Images, and Accessible Quantity Steppers
- **Severity**: P1
- **Category**: UX / Mobile Interaction / Accessibility
- **Standard refs**: NN/g H6 (Recognition Rather than Recall), Apple HIG adapted (Minimum 44x44 px touch targets, thumb-reachable primary actions), WCAG 2.2 SC 2.5.8 (Target Size Minimum), Phase 7 Specification Check 6

---

## 1. Expected vs Actual

- **EXPECTED (Phase 7 Spec Check 6, UI-UX-Spec)**:
  The ordering screen must provide product tiles with real product image PLUS visible text label (name, packaging unit, standard price, stock/ATP status) so meaning never depends on image alone. The quantity selection must feature an accessible stepper with large touch targets (minimum 44x44 px), a running order total, and clear stock-short state. Dedicated standalone route `/orders/new` must render the functional ordering catalog.
- **ACTUAL (evidence: `client/src/pages/orders-page.tsx:825-885`, `client/src/pages/placeholder-pages.tsx:15-48`, `/audit/evidence/screenshots/SALESMAN/en/390px/orders-new.png`)**:
  `/orders/new` renders a non-functional placeholder screen (`PlaceholderPage`: "New Order Workspace - Module in Progress"). The only ordering interface is a modal dialog on `/orders` containing a plain HTML `<select>` dropdown (`orders-page.tsx:842-856`) and a standard `<input type="number">` (`orders-page.tsx:878-883`). There are zero product images, zero product tiles, and zero quantity steppers with 44x44px touch targets.
- **DELTA**:
  The product tile ordering experience was replaced with a desktop-style `<select>` dropdown. Field salesmen on mobile phones cannot tap visual product cards or use thumb-sized steppers, violating mobile ordering specifications.

---

## 2. Impact

- **Who is hurt**: Field salesmen entering wholesale orders on 320px–390px mobile devices in retail stores or transit.
- **Operational consequence**: High error rate when selecting products from tiny dropdown text; salesmen cannot quickly visually confirm pack sizes (200g vs 500g); typing numbers on soft mobile keyboards without steppers slows order booking by 2–3 minutes per customer call.

---

4. Navigate to `http://127.0.0.1:4173/orders` and click "Create first order" or "New order".
5. Inspect the "Product item" selector: it is an HTML `<select>` tag without images or tile cards.
6. Inspect the "Order quantity" input: it is an `<input type="number">` without plus/minus stepper buttons.

### Root Cause
1. `client/src/pages/placeholder-pages.tsx:53-55` routes `/orders/new` to a dummy placeholder component.
2. `client/src/pages/orders-page.tsx:842-885` implements product selection via `<select>` and raw number input rather than an image-and-text tile grid with 44px stepper buttons.

---

## 4. Recommended Fix & Regression Test

### Recommended Fix (Do Not Apply - Audit Only)
1. Implement a dedicated `/orders/new` screen containing a responsive product grid (`grid-cols-1 sm:grid-cols-2 lg:grid-cols-3`).
2. Each tile must render an optimized product thumbnail, product name, unit packaging, price, live ATP stock badge, and a large stepper (`<button className="size-11 ...">+</button>`).
3. Display a floating sticky footer summary showing item count, taxable subtotal, GST, grand total, and a thumb-reachable "Place Order" button.

### Regression Test to Add
- Add Playwright spec `tests/ordering-tiles.spec.ts` asserting:
  - Route `/orders/new` renders `.product-card` tiles with `img` tags and visible title/price text.
  - Each product card contains plus/minus buttons meeting `box.width >= 44 && box.height >= 44`.
  - Increasing quantity updates running total in sticky bottom bar.
