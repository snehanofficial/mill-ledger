# Finding F-024: Missing Password Reset Flow and Absence of Account Lockout on Failed Logins

**ID**: F-024  
**Title**: Better Auth password reset endpoint is unconfigured (returns 404); account lockout is not implemented after repeated authentication failures  
**Severity**: P2  
**Category**: Authentication / Credential Management  
**Standard Refs**: OWASP Top 10:2021 A07:2021 (Identification and Authentication Failures), OWASP ASVS v4.0.3 Section 2.2.1, Section 2.3.1  

---

## Expected (Source)
Source: OWASP ASVS v4.0.3 Section 2.2, Section 2.3.  
Systems supporting password authentication must provide a secure password reset / recovery flow and enforce rate limiting with account lockout or progressive delays after successive failed login attempts.

---

## Actual (Evidence Links)
Evidence: Executed [/audit/scripts/verify-sessions-auth.ts](file:///home/snehan/projects/web/mill-ledger/audit/scripts/verify-sessions-auth.ts), output in [/audit/evidence/better-auth-sessions.txt](file:///home/snehan/projects/web/mill-ledger/audit/evidence/better-auth-sessions.txt).

1. **Password Reset Returns 404**:
   Sending `POST /api/auth/forget-password` with `{"email": "admin@millledger.local"}` responded with HTTP 404 Not Found.
   Because `emailAndPassword.sendResetPassword` callback is omitted in [server/src/lib/auth.ts:51](file:///home/snehan/projects/web/mill-ledger/server/src/lib/auth.ts#L51), Better Auth disables the password recovery endpoint.
2. **No Account Lockout**:
   After 6 consecutive failed login attempts on `salesman1@millledger.local`, the server returned 401 on each attempt, but the user account remained completely active (`isActive = true`). A subsequent login with the correct password succeeded with HTTP 200 immediately.
   Furthermore, Better Auth logged:
   `WARN [Better Auth]: Rate limiting could not determine a client IP and is falling back to a single shared per-path bucket...`

---

## Delta
Password self-service reset is unavailable. Brute-force attacks against user credentials face only IP-level rate limiting without user account lockout or progressive delay.

---

## Impact
- **Account Recovery Failure & Brute-Force Exposure**: Users who forget passwords must contact database administrators directly. Distributed credential stuffing against a specific target account is not blocked by account-level lockout.

---

## Repro Steps
1. Send `POST /api/auth/forget-password` with `{"email": "admin@millledger.local"}`. Observe HTTP 404 response.
2. Send 10 consecutive failed login requests for a target email.
3. Immediately send a valid login request for that target email. Observe successful HTTP 200 login.

---

## Root Cause
- [server/src/lib/auth.ts:51](file:///home/snehan/projects/web/mill-ledger/server/src/lib/auth.ts#L51): `emailAndPassword` configuration lacks `sendResetPassword` hook and account lockout policies.

---

## Recommended Fix
1. Configure `emailAndPassword.sendResetPassword` in Better Auth with an email provider or logging stub.
2. Implement account lockout or progressive backoff after 5 consecutive failed attempts on a single user identity.

---

## Regression Test to Add
Add integration test in `server/src/auth.integration.test.ts` verifying that `POST /api/auth/forget-password` returns 200 and that accounts lock after configured failed attempts.
