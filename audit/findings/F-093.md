# F-093: Absence of Schema.org JSON-LD Structured Data and Semantic `<main>` Landmark on Login Surface

- **ID**: F-093
- **Title**: Absence of Schema.org JSON-LD Structured Data and Semantic `<main>` Landmark on Login Surface
- **Severity**: P2
- **Category**: Accessibility (WCAG 2.2 AA) & Semantic Web
- **Standard Refs**:
  - WCAG 2.2 Success Criterion 1.3.1: Info and Relationships (Level A)
  - W3C HTML5 Specification: Section 4.4.1 (The `main` element)
  - Schema.org Core Vocabulary: `Organization`, `LocalBusiness`, `SoftwareApplication`
  - Google Search Central: Structured Data Guidelines

---

## Expected (Source)
- **Source**: WCAG 2.2 SC 1.3.1 & Schema.org Specification:
  - Every distinct web page must provide a top-level `<main>` landmark enclosing its central primary content to enable assistive technologies and screen readers to skip navigation.
  - Public web application landing and entry points should provide JSON-LD structured data (`<script type="application/ld+json">`) declaring the publishing `Organization` or `SoftwareApplication` to enable rich search snippets and entity reconciliation in the Google Knowledge Graph.

---

    - No structured data `<script>` tag is rendered.

---

## Delta
1. Zero HTML5 semantic landmarks (`<main>`, `<header>`, `<nav>`, `<footer>`) are rendered on the public login page.
2. Complete omission of Schema.org JSON-LD structured data.
3. Complete absence of navigation links (e.g. Terms, Privacy, Support).

---

## Impact
- **Who is hurt**: Screen reader users, keyboard-only operators, and search engine crawlers.
- **How**: Screen reader users navigating to `/auth/login` cannot use standard landmark navigation keys (e.g., NVDA/JAWS 'M' or 'D') to jump directly to the login form. Search bots cannot identify the operating entity or organization type.

---

## Repro Steps
1. Navigate to `http://127.0.0.1:4173/auth/login`.
2. Inspect the DOM: `document.querySelector("main")` returns `null`.
3. Query for structured data: `document.querySelectorAll('script[type="application/ld+json"]')` returns empty NodeList.

---

## Root Cause
- File: [`client/src/pages/login-page.tsx`](file:///home/snehan/projects/web/mill-ledger/client/src/pages/login-page.tsx#L190)
  - The login container is wrapped in a generic `<div>` rather than a semantic `<main>` landmark.
- File: [`client/index.html`](file:///home/snehan/projects/web/mill-ledger/client/index.html#L1-L18)
  - No JSON-LD schema template was defined for the organization.

---

## Recommended Fix (Do Not Apply)
1. Wrap the login container in `<main>`:
   ```tsx
   return (
     <main className="flex min-h-screen w-full flex-col items-center justify-center bg-background px-4 py-12 sm:px-6 lg:px-8">
       ...
     </main>
   );
   ```
2. Insert Schema.org JSON-LD in `client/index.html` or dynamically via script:
   ```html
   <script type="application/ld+json">
   {
     "@context": "https://schema.org",
     "@type": "SoftwareApplication",
     "name": "MillLedger ERP",
     "applicationCategory": "BusinessApplication",
     "operatingSystem": "All modern web browsers",
     "description": "Order-to-Audit ERP for small food manufacturing mills"
   }
   </script>
   ```
