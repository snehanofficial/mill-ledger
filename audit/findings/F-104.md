# F-104: CI/CD Pipeline Gaps: E2E, Lighthouse, Audit, Bundle Gate, and Secret Scan Missing; Main Branch Lacks Merge Protection

- **ID**: F-104
- **Title**: CI/CD Pipeline Gaps: E2E, Lighthouse, Audit, Bundle Gate, and Secret Scan Missing; Main Branch Lacks Merge Protection
- **Severity**: P1
- **Category**: CI/CD & DevSecOps
- **Standard Refs**:
  - NIST SP 800-218 (Secure Software Development Framework - Tasks PW.1.2, PW.7.1)
  - GitHub Branch Protection Rules Guidelines
  - CIS Software Supply Chain Security Guide v1.0

---

## Expected (Source)
- **Source**: Master Rulebook and CI/CD Quality Baseline:
  - CI pipeline must run: typecheck, lint, unit tests, integration with real PostgreSQL, E2E tests (`pnpm test:e2e`), bundle-size gate, Lighthouse CI, dependency audit (`pnpm audit`), migration checks, and secret scans.
  - Required status checks and branch protection rules must be configured on the `main` branch to prevent direct unvalidated pushes or merging broken pull requests.

---

## Actual (Evidence Links)
1. **Critical CI Step Omissions in `.github/workflows/ci.yml`**:
   - [`ci.yml:62-81`](file:///home/snehan/projects/web/mill-ledger/.github/workflows/ci.yml#L62-L81) executes:
     - `pnpm lint` (Pass)
     - `pnpm typecheck` (Pass)
     - `prisma migrate deploy` (Empty DB only)
     - `pnpm --filter @mill-ledger/server db:seed` (Pass)
     - `pnpm test` (Unit/integration, Pass)
     - `pnpm benchmark` (Pass)
     - `pnpm --filter client build` (Pass)
   - **Missing Gates**:
     - **E2E Tests**: `pnpm test:e2e` is **absent** from CI. Broken E2E flows (such as the duplicate skip link failure found in Phase 0) never fail the CI build.
     - **Bundle Size Gate**: No bundle budget or size gate (e.g. `size-limit`) is configured.
     - **Lighthouse CI**: No `lhci autorun` step exists.
     - **Dependency Audit**: `pnpm audit` is omitted.
     - **Secret Scanning**: No Gitleaks or TruffleHog step exists.
     - **Realistic Migration Verification**: Migrations are only applied to an empty DB, not against realistic pre-existing data.
     - **Server Build**: CI builds `client` only; it never tests `pnpm --filter @mill-ledger/server build`.
2. **Branch Protection Completely Disabled**:
   - Running live API verification:
     ```bash
     gh api repos/snehanofficial/mill-ledger/branches/main/protection
     ```
   - **Response**: `HTTP 404: Branch not protected`.
   - The repository allows direct `git push` to `main` without PR reviews, and CI checks are not required to pass before changes land in production.

---

## Delta
- Six required verification gates (E2E, Lighthouse, Audit, Bundle Gate, Server Build, Secret Scan) are omitted from the CI pipeline, and the `main` branch has zero branch protection rules.

---

## Impact
- **Regressions Reach Production**: Regressions in UI, E2E workflows, or performance budgets merge silently.
- **Accidental Main Overwrite**: Without branch protection, any team member or automated token can force-push to `main` or push untested commits bypassing CI entirely.

---

---

## Root Cause
- CI workflow was authored as an initial minimal smoke check and never expanded to cover all integration gates; repository branch settings were left in default unrestricted state.

---

## Recommended Fix
1. Update `.github/workflows/ci.yml` to include:
   - `pnpm test:e2e` (with Playwright container/browsers setup)
   - `pnpm audit --audit-level=high`
   - `pnpm --filter @mill-ledger/server build`
   - Secret scanning step (`gitleaks/gitleaks-action@v2`)
   - Lighthouse CI action
2. In GitHub repository settings, enable Branch Protection for `main`:
   - Require pull request before merging (at least 1 approval)
   - Require status checks to pass before merging (`Lint, Typecheck, Test & Benchmark`)
   - Enforce for administrators
