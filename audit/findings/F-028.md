# Finding F-028: Customer PII and Offline Orders Retained in Client IndexedDB (Dexie) Across Logout

**ID**: F-028  
**Title**: Dexie IndexedDB fails to purge sensitive customer PII and pending offline orders upon user sign-out  
**Severity**: P2  
**Category**: Cryptographic Failures / Sensitive Data Exposure / Client Storage  
**Standard Refs**: OWASP Top 10:2021 A02:2021 (Cryptographic Failures), A01:2021 (Broken Access Control), OWASP API Security Top 10:2023 API3:2023 (Broken Object Property Level Authorization), OWASP ASVS v4.0.3 Section 3.5.3 (Verify that sensitive session tokens and credentials are deleted upon logout), Section 8.3.1 (Verify that sensitive data stored client-side is cleared when no longer required)  

---

## Expected (Source)
Source: OWASP ASVS v4.0.3 Sec 8.3.1 & Session Management Cheat Sheet.
Upon user logout, all client-side persistent caches storing sensitive enterprise data, customer Personally Identifiable Information (PII — names, addresses, phone numbers, GSTINs), pricing lists, and offline outbox queues must be purged or cryptographically locked to prevent unauthorized disclosure on shared devices (tablets, shop floor terminals, mobile sales devices).

---

## Actual (Evidence Links)
Evidence: Executed Playwright test [/audit/tests/dexie-security.spec.ts](file:///home/snehan/projects/web/mill-ledger/audit/tests/dexie-security.spec.ts) and captured [/audit/evidence/dexie-logout-audit.json](file:///home/snehan/projects/web/mill-ledger/audit/evidence/dexie-logout-audit.json).

In [client/src/layouts/authenticated-layout.tsx:58-68](file:///home/snehan/projects/web/mill-ledger/client/src/layouts/authenticated-layout.tsx#L58-L68):
```typescript
  const handleSignOut = async () => {
    try {
      await authClient.signOut();
    } catch (err) {
      console.warn("Sign out error:", err);
    } finally {
      // OWASP: Purge all cached sensitive domain and session state from client memory
      queryClient.clear();
      navigate("/auth/login", { replace: true });
    }
  };
```
While in-memory `queryClient.clear()` is called, `offlineDb` (Dexie / IndexedDB) is never touched.
Playwright recorded:

All customer records (including phone numbers and GSTINs) and pending outbox orders with item details remain completely unencrypted in browser IndexedDB `mill_ledger_offline_db` indefinitely after logout.

---

## Delta
Sign-out clears React Query memory but ignores IndexedDB (`mill_ledger_offline_db`), leaving the full offline customer cache and outbox orders intact on the client device.

---

## Impact
- **Shared Terminal Data Leak**: On shared sales tablets or factory floor kiosk workstations, subsequent operators or unauthorized users can open browser devtools or local scripts and extract all customer contact details, GSTIN tax identifiers, customer addresses, and pending orders.
- **Cross-User Contamination**: A second salesman logging in on the same tablet could trigger sync of orders prepared by the previous user under a different identity.

## Root Cause
[client/src/layouts/authenticated-layout.tsx:65](file:///home/snehan/projects/web/mill-ledger/client/src/layouts/authenticated-layout.tsx#L65):
The sign-out callback calls `queryClient.clear()` but does not invoke `offlineDb.customers.clear()`, `offlineDb.products.clear()`, or `offlineDb.outbox.clear()`.

---

## Recommended Fix (Do Not Apply)
In `handleSignOut`, add an explicit purge or reset of the local offline database:
```typescript
await Promise.all([
  offlineDb.customers.clear(),
  offlineDb.products.clear(),
  offlineDb.meta.clear(),
  // Check if outbox has unsynced orders; prompt or purge
  offlineDb.outbox.clear(),
]);
```
