# F-053: Static SPA Page Title and Absence of Route Transition Announcements for Screen Readers

- **ID**: F-053
- **Title**: Static SPA Page Title and Absence of Route Transition Announcements for Screen Readers
- **Severity**: P1
- **Category**: Accessibility / Screen Reader Semantics / SPA Focus Management
- **Standard refs**: WCAG 2.2 SC 2.4.2 (Page Titled - Level A), SC 4.1.3 (Status Messages - Level AA), W3C SPA Accessibility Guidelines

---

## 1. Expected vs Actual

- **EXPECTED (WCAG 2.2 SC 2.4.2, 4.1.3, W3C SPA Routing)**:
  1. In a Single Page Application (SPA), navigating between routes must update `document.title` to reflect the current view (e.g. "Orders | MillLedger", "Invoices | MillLedger").
  2. Because client-side routing does not trigger a full browser reload, the application must manage focus (e.g. moving focus to the view's primary `<h1>` or main container) or provide a polite live region (`aria-live="polite"`) that announces the new page title to screen reader users upon route transition.
- **ACTUAL (evidence: `client/src/routes/route-handles.ts`, `client/src/components/shell/authenticated-shell.tsx`, `client/index.html:15-17`, `audit/evidence/a11y/snapshots/comprehensive_wcag_verification.json`)**:
  1. `document.title` is hardcoded once in `index.html`:
     ```html
     <title>MillLedger | Order-to-Audit System for a Small Food Manufacturer</title>
     ```
     Automated checks across 9 routes (`/dashboard`, `/orders`, `/stock`, `/production/today`, `/invoices`, `/dispatch`, `/payments`, `/reports/sales`, `/settings`) revealed that `document.title` is **never updated** (`document.title` remains `"MillLedger | Order-to-Audit System for a Small Food Manufacturer"` on every route).
  2. When a route changes:
     - Focus is dropped to `document.body` (`ActiveTag: BODY`).
     - Zero focus shifting to `#main-content` or `<h1>` occurs.
     - Zero live region exists for route transition announcements.
- **DELTA**:
  Screen reader users receive zero audio feedback or title update when navigating the application; they have no confirmation that navigation occurred or what view is currently displayed.

---

## 2. Impact

- **Who is hurt**: All blind, low-vision, and screen reader operators navigating the MillLedger SPA.
- **Operational consequence**: Total disorientation; users cannot tell whether clicking a sidebar link loaded the requested screen or failed.

---

## 3. Repro Steps & Root Cause

### Repro Steps
1. Open Chrome DevTools Console on `http://localhost:4173/dashboard`.
2. Observe `document.title`.
3. Click "Orders" in the sidebar navigation.
4. Check `document.title` again in Console -> still `"MillLedger | Order-to-Audit System for a Small Food Manufacturer"`.
5. Check `document.activeElement` -> points to `BODY`.

### Root Cause
`AuthenticatedLayout` and route configurations in `client/src/app.tsx` do not utilize React Router's route handles or a title-management hook (e.g. `useEffect` on `location.pathname`) to update `document.title` and announce the route in an `aria-live` container.

---

## 4. Recommended Fix & Regression Test

### Recommended Fix
1. Implement a route title & live announcement effect in `AuthenticatedLayout` or `AuthenticatedShell`:
   ```tsx
   useEffect(() => {
     const title = routeTitles[location.pathname] || "MillLedger";
     document.title = `${title} | MillLedger`;
     announceLiveRegion(`${title} view loaded`);
   }, [location.pathname]);
   ```
2. Add a hidden live region:
   ```tsx
   <div className="sr-only" role="status" aria-live="polite" id="route-announcer" />
   ```
3. Shift focus to `#main-content` upon navigation.

### Regression Test
Run Playwright route transition test: assert `document.title` matches expected pattern for every route, and assert `aria-live` region announces new view.
