## Expected (Source)
- **Source**: `audit/01-expected-spec.md` (REQ-053) and W3C Internationalization Standards.
- In an Indian ERP application supporting English and Tamil:
  1. Currency and numbers must follow Indian numbering system grouping (e.g. `1,00,000.00` for 1 Lakh instead of Western `100,000.00`), using `Intl.NumberFormat('ta-IN')` or `Intl.NumberFormat('en-IN')`.
  2. Dates must respect the active UI language toggle, formatting via `Intl.DateTimeFormat(language === "ta" ? "ta-IN" : "en-IN")`.
  3. Table column sorting and alphabetical lists must use language-aware collation (`String.prototype.localeCompare(other, language)`).

## Delta
No localization formatting exists for numbers, currencies, dates, or collation. All financial values lack Indian comma grouping (Lakhs/Crores), dates remain hardcoded to English `"en-IN"`, and collation for Tamil text is nonexistent.

---

## Impact
- **Who is hurt**: Mill owners, accountants, and Tamil-speaking floor managers reviewing financial ledgers and stock balances.
- **How**: Reading large numbers without Indian grouping (e.g. `1250000.00` instead of `12,50,000.00`) causes cognitive strain and frequent transcription errors when balancing books or verifying payment receipts against physical bank deposits.

## Root Cause
- File: [`client/src/lib/utils.ts`](file:///home/snehan/projects/web/mill-ledger/client/src/lib/utils.ts)
  - Utility module contains only Tailwind `cn()`. No centralized number or date formatting helpers exist in the codebase.
- Components across `client/src/pages/` directly execute inline `.toFixed(2)` and `toLocaleDateString("en-IN")`.

---

## Recommended Fix (Do Not Apply)
1. In `client/src/lib/utils.ts`, implement centralized formatters:
   ```ts
   export function formatCurrency(amount: number, lang: "en" | "ta" = "en"): string {
     return new Intl.NumberFormat(lang === "ta" ? "ta-IN" : "en-IN", {
       style: "currency",
       currency: "INR",
       maximumFractionDigits: 2,
     }).format(amount);
   }

   export function formatDate(date: string | Date, lang: "en" | "ta" = "en"): string {
     return new Intl.DateTimeFormat(lang === "ta" ? "ta-IN" : "en-IN", {
       dateStyle: "medium",
     }).format(new Date(date));
   }
   ```
2. Replace all inline `.toFixed(2)` and `toLocaleDateString("en-IN")` calls with `formatCurrency` and `formatDate`.
