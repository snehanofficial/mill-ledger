# F-085: Complete Absence of Indic/Tamil Number Formatting, Date Localization, and Collation (Sorting)

- **ID**: F-085
- **Title**: Complete Absence of Indic/Tamil Number Formatting, Date Localization, and Collation (Sorting)
- **Severity**: P2
- **Category**: Localization (l10n) / Data Formatting
- **Standard Refs**:
  - `audit/01-expected-spec.md` (REQ-053 Bilingual Interface: Tamil & English)
  - W3C Internationalization Best Practices: Numbers, Dates, and Currencies
  - Unicode Technical Standard #10: Unicode Collation Algorithm (UCA)
  - Reserve Bank of India (RBI) / Indian Accounting Standards (Lakh/Crore Numbering System)

---

## Expected (Source)
- **Source**: `audit/01-expected-spec.md` (REQ-053) and W3C Internationalization Standards.
- In an Indian ERP application supporting English and Tamil:
  1. Currency and numbers must follow Indian numbering system grouping (e.g. `1,00,000.00` for 1 Lakh instead of Western `100,000.00`), using `Intl.NumberFormat('ta-IN')` or `Intl.NumberFormat('en-IN')`.
  2. Dates must respect the active UI language toggle, formatting via `Intl.DateTimeFormat(language === "ta" ? "ta-IN" : "en-IN")`.
  3. Table column sorting and alphabetical lists must use language-aware collation (`String.prototype.localeCompare(other, language)`).

---

## Actual (Evidence Links)
- **Evidence**:
  - Currency and number formatting:
    - Search across `client/src/` reveals `Intl.NumberFormat` was used without Tamil support or collation algorithm.
    - Dates hardcoded `"en-IN"`, failing to translate months to Tamil when UI toggled to `ta`.
    - No linguistic collation existed across entities.

---

## Delta
Localization formatting lacked Tamil Indic date localization, Tamil currency options, and Unicode collation.

---

## Impact
- **Who is hurt**: Mill owners, accountants, and Tamil-speaking floor managers reviewing financial ledgers and stock balances.
- **How**: Reading dates and sorting Tamil entities without linguistic collation caused friction and inconsistencies.

---

## Root Cause
- File: `shared/src/formatters.ts`
  - Formatters hardcoded "en-IN" with no support for "ta-IN" or Unicode collation UTS #10.

---

## Fix & Verification

### Implementation
- `shared/src/formatters.ts`:
  * Upgraded `formatINR` and `formatQuantity` with `locale` and `lang` configuration (`ta-IN` / `ta`).
  * Upgraded `formatDate`, `formatDateShort`, `formatDateTime`, `formatTime` with `FormatDateOptions` supporting `ta-IN` Tamil month formatting.
  * Added `compareStrings(a, b, locale, options)` implementing Unicode Collation Algorithm (UTS #10) supporting Tamil and English collation.
- `client/src/hooks/use-formatters.ts`:
  * Created contextual `useFormatters()` hook synchronizing formatters and collation with active UI language.
- `client/src/lib/formatters.ts`:
  * Exported `useFormatters`.
- `client/src/lib/formatters.test.ts`:
  * Added unit test assertions covering Tamil currency grouping, Tamil date months, and Tamil/English collation.
