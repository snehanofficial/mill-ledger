# Finding F-035: Absence of API Request Logging, Missing Correlation IDs, and Mutable Database Audit Log

**ID**: F-035  
**Title**: Zero HTTP request logging middleware exists; no correlation IDs are generated; operational mutations bypass audit logs; and `audit_log` records are mutable and lack search/export UI  
**Severity**: P1  
**Category**: Security Logging & Monitoring / Non-Repudiation / Data Integrity  
**Standard Refs**: OWASP Top 10:2021 A09:2021 (Security Logging and Monitoring Failures), OWASP ASVS v4.0.3 Sec 8.2, Sec 8.3.1, REQ-050  
**Status**: OPEN  

---

### Expected (source)
Under [architecture.md](file:///home/snehan/projects/web/mill-ledger/docs/architecture.md) and [product-requirements.md](file:///home/snehan/projects/web/mill-ledger/docs/product-requirements.md) REQ-050:
1. Every API request must be logged with structured metadata: `requestId`, `userId`, `role`, `method`, `routePattern`, `status`, `latency`, `ip`, `userAgent`, and `payloadSize`.
2. A unique correlation ID (`x-request-id`) must be assigned to each incoming request and returned in headers.
3. Passwords, session tokens, and financial secrets must be strictly redacted from logs.
4. Business audit logging must record actor, action, before-and-after state, and reason across all critical lifecycle events: login, failed login, logout, permission/role changes, price overrides, stock movements, invoice postings, and payment reversals.
5. The `audit_log` table must be strictly append-only at the database layer (preventing UPDATE/DELETE).
6. Super admins must have a UI to search, filter, and safely export audit logs.

### Actual (evidence links)
Execution of [/audit/scripts/verify-logging-audit.ts](file:///home/snehan/projects/web/mill-ledger/audit/scripts/verify-logging-audit.ts) revealed comprehensive failures:
1. **Zero API Logging Middleware**: Runtime introspection of the Express stack in [app.ts](file:///home/snehan/projects/web/mill-ledger/server/src/app.ts) confirms no logger (Pino, Morgan, Winston) is registered.
2. **Missing Correlation ID**: `x-request-id` header is completely absent from all HTTP responses.
3. **Password Redaction**: Tested by sending canary password `CANARY_SECRET_P4_AUDIT_998877` to `/api/auth/sign-in/email`. Better Auth did not leak the password to logs or database (`VERIFIED-PASS` for password confidentiality), but no audit log entry of the authentication failure was written.
4. **Operational Mutations Bypass Audit**: Creating an order, approving an order, posting an invoice, and recording a payment produced exactly 0 new records in `audit_log`. Only report CSV export invokes `auditService.log` ([audit.service.ts:30-56](file:///home/snehan/projects/web/mill-ledger/server/src/modules/reporting/audit.service.ts#L30-L56)).
5. **Database Audit Log is Mutable**: Direct SQL execution confirmed that `audit_log` rows can be altered via `UPDATE` and removed via `DELETE`. No PostgreSQL rules or triggers prevent tampering.
6. **No Audit Export or Search UI**:
   - Calling `GET /api/v1/reports/audit/export?format=csv` returns HTTP 400 `{"error":"Unknown report type: audit"}`.
   - The React UI ([reports-page.tsx:635-699](file:///home/snehan/projects/web/mill-ledger/client/src/pages/reports-page.tsx#L635-L699)) renders a plain, non-paginated table without search, date filtering, actor filtering, or export controls.

Artifact: [/audit/evidence/logging-audit-verification.json](file:///home/snehan/projects/web/mill-ledger/audit/evidence/logging-audit-verification.json).

### Delta
Complete lack of operational API telemetry and request tracing. Business audit logs cover <5% of required business events and can be tampered with or deleted at will.

### Impact
1. Forensic blindness: Security incidents, insider fraud, unauthorized price overrides, or data corruption cannot be attributed to specific sessions or actors.
2. Non-repudiation failure: Without immutable before/after state captures, invoice alterations and inventory discrepancies cannot be legally substantiated.
3. Inability to monitor performance degradation, latency spikes, or brute-force attacks.

### Repro Steps
1. Run `node --env-file=audit/.env.audit server/node_modules/tsx/dist/cli.mjs audit/scripts/verify-logging-audit.ts`.
2. Observe output showing 0 API loggers, 0 audit rows created during order/invoice mutations, and `UPDATE`/`DELETE` succeeding on `audit_log`.

### Root Cause
1. [app.ts](file:///home/snehan/projects/web/mill-ledger/server/src/app.ts) lacks a request-id and logging middleware.
2. Domain services do not inject or invoke `auditService.log`.
3. Database migrations lack PostgreSQL `BEFORE UPDATE OR DELETE` triggers on `audit_log`.

### Recommended Fix (do not apply)
1. Install `pino` and `pino-http`, generating an `x-request-id` with `crypto.randomUUID()`.
2. Add PostgreSQL trigger:
   ```sql
   CREATE RULE audit_log_no_update AS ON UPDATE TO audit_log DO INSTEAD NOTHING;
   CREATE RULE audit_log_no_delete AS ON DELETE TO audit_log DO INSTEAD NOTHING;
   ```
3. Hook `auditService.log` into domain service mutation transactions.
4. Add search, date filtering, and CSV export to the Super Admin audit interface.
