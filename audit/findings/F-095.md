## Delta
- Rather than zero `any` in domain logic, 14 instances bypass compiler checking in `reporting.service.ts` and `audit.service.ts`.
- Prisma query objects (`where: any`) allow misspelled columns to pass compilation without runtime query safety.

---

## Impact
- **Financial & Audit Inaccuracy**: Untyped `where: any` filters on SQL models can cause queries to fail at runtime or omit records, directly contributing to reporting discrepancies like F-036 (silent ₹12,000 revenue omission).
- **Subtle Runtime Exceptions**: In `reports-page.tsx`, casting table rows to `any` prevents TypeScript from catching property access errors (e.g. `row.invoiceDate` vs `row.date`).

---

## Repro Steps
1. Run type safety audit script:
   ```bash
   node audit/scripts/audit-type-safety.js
   ```
2. Verify domain violations in `server/src/modules/reporting/reporting.service.ts` and `audit.service.ts`.

---

## Root Cause
- Rapid developer prototyping using `any` to quickly build complex Prisma `where` filter objects and CSV serialization mappers without importing Prisma typed filter interfaces (e.g., `Prisma.SalesInvoiceWhereInput`).

---

## Recommended Fix
1. Add `"strict": true` to `client/tsconfig.app.json`.
2. Replace `where: any` with typed Prisma filter definitions:
   ```typescript
   import { Prisma } from "@prisma/client";
   const where: Prisma.SalesInvoiceWhereInput = { organizationId: orgId, ... };
   ```
3. Type report row data using `@mill-ledger/shared` contract types rather than `any[]` and `row: any`.
