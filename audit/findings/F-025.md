# Finding F-025: Express 5 Middleware Deviations: Missing Request ID, Missing App Rate Limit, Missing 404 JSON Handler, and 413 Payload Error Emitting HTTP 500

**ID**: F-025  
**Title**: Application middleware pipeline deviates from security baseline: lacks request correlation IDs, app-wide rate limits, JSON 404 envelope, and translates 413 payload limits into 500 server crashes  
**Severity**: P2  
**Category**: Middleware Architecture / Error Handling / Denial of Service  
**Standard Refs**: OWASP API Security Top 10:2023 API4:2023 (Unrestricted Resource Consumption), API8:2023 (Security Misconfiguration), OWASP ASVS v4.0.3 Section 13.1  

---

## Expected (Source)
Source: Expected Middleware Pipeline:
`request-id -> security headers -> CORS -> body size limits and parsers -> request logging -> rate limit -> session/auth -> permission check -> input validation -> idempotency -> handler -> not-found -> error envelope`.
All unmapped routes must return a consistent JSON error envelope `{ "error": "Not Found" }` with status 404. Body parser `PayloadTooLargeError` must return HTTP 413 Content Too Large. Every request must be traceable with a correlation ID (`X-Request-Id`).

## Actual (Evidence Links)
Evidence: Executed [/audit/scripts/verify-middleware-chain.ts](file:///home/snehan/projects/web/mill-ledger/audit/scripts/verify-middleware-chain.ts).

1. **Missing 404 JSON Handler**:
   Requesting `GET /api/v1/does-not-exist` returns Express's default HTML page (`Content-Type: text/html`):
   ```html
   <!DOCTYPE html><html><head><title>Error</title></head><body><pre>Cannot GET /api/v1/does-not-exist</pre></body></html>
   ```
   Because [server/src/app.ts:59](file:///home/snehan/projects/web/mill-ledger/server/src/app.ts#L59) mounts `app.use(errorHandler)` without a preceding 404 catch-all, unmatched requests bypass `errorHandler` and hit Express's built-in `finalhandler`.
2. **Missing Request ID & Request Logging**:
   `x-request-id` header is absent from all server responses. No request logging middleware (pino-http, morgan) is present.
3. **Missing API Rate Limiting**:
   `/api/v1/*` routes have zero rate-limiting headers (`ratelimit-limit: null`). Rate limiting is only configured inside Better Auth for `/api/auth/*`.
4. **413 Payload Error Returns HTTP 500 With Stack Trace**:
   Sending a 150KB payload (>100KB default) triggers `body-parser`'s `PayloadTooLargeError`.
   Because [server/src/middleware/error.middleware.ts](file:///home/snehan/projects/web/mill-ledger/server/src/middleware/error.middleware.ts) does not check for `entity.too.large` or status 413, it enters unhandled error handling, returning HTTP 500 Internal Server Error and leaking the full server stack trace.

## Delta
The middleware pipeline omits 4 required security components (request correlation, request logging, API rate limiting, JSON 404 handler) and misclassifies body size limit violations as internal server errors.

---

## Impact
- **Observability & Resilience**: Distributed tracing across client and server is impossible without request IDs. API routes can be flooded with volumetric requests without throttling. Client developers receiving HTML 404s suffer JSON parsing errors in API clients.

---

## Repro Steps
1. Send `GET /api/v1/unknown-endpoint`. Observe HTTP 404 with HTML body.
2. Send `POST /api/v1/sales/orders` with body exceeding 100KB. Observe HTTP 500 with stack trace.
3. Check response headers on any API response; verify `x-request-id` is absent.

---

## Root Cause
- [server/src/app.ts](file:///home/snehan/projects/web/mill-ledger/server/src/app.ts): Lacks request-id middleware, rate limiting on `/api/v1`, and 404 catch-all before `errorHandler`.
- [server/src/middleware/error.middleware.ts](file:///home/snehan/projects/web/mill-ledger/server/src/middleware/error.middleware.ts): Lacks handler for `err.type === "entity.too.large"` / status 413.

---

## Recommended Fix
1. Add `crypto.randomUUID()` request ID middleware setting `req.id` and `res.setHeader('X-Request-Id', ...)`.
2. Add rate limiting middleware (e.g. `express-rate-limit`) to `/api/v1`.
3. Add 404 middleware right before `errorHandler`: `app.use((_req, res) => res.status(404).json({ error: "Route not found" }));`.
4. In `errorHandler`, check `if (err.status === 413 || (err as any).type === "entity.too.large") return res.status(413).json({ error: "Payload Too Large" });`.

---

## Regression Test to Add
Add tests in `server/src/app.test.ts` verifying that unknown routes return JSON 404 and oversized bodies return HTTP 413.
