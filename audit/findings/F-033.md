# Finding F-033: Missing Domain Validation for Statutory Formats, UOM Quantities, Credit Limits, and Dates

**ID**: F-033  
**Title**: Application lacks domain-level validation for statutory formats (PIN, Phone, Email, State, HSN), discrete UOM integer quantities, customer credit limits, and chronological dates  
**Severity**: P1  
**Category**: Domain Logic / Statutory Compliance / Business Invariants  
**Standard Refs**: CGST Act 2017, CBIC HSN Guidelines, Postal Index Number Specification, REQ-006, REQ-027, REQ-034  
**Status**: OPEN  

---

### Expected (source)
Under [business-rules.md](file:///home/snehan/projects/web/mill-ledger/docs/business-rules.md) and [product-requirements.md](file:///home/snehan/projects/web/mill-ledger/docs/product-requirements.md):
1. Parties must have valid 6-digit PIN codes, 10-digit Indian phone numbers, and standard email formats.
2. States must map to 2-digit statutory GST State Codes (01 to 38).
3. HSN codes must be 4, 6, or 8 numeric digits.
4. Quantities must adhere to Unit of Measure precision (e.g. discrete units like `BAG` accept only positive integers; `KG` allows max 3 decimal places).
5. Customer credit limits must be enforced on sales order approval and dispatch.
6. Chronological date invariants must be enforced (`dueDate >= invoiceDate`, `paymentDate <= current_date`).
7. Approval price/quantity overrides must require an audit justification reason.

### Actual (evidence links)
Execution of [/audit/scripts/verify-domain-validation.ts](file:///home/snehan/projects/web/mill-ledger/audit/scripts/verify-domain-validation.ts) produced 10 failures out of 10 evaluated domain rules:
- **PIN Code**: Column does not exist in `Customer` or `Organization` models ([schema.prisma:145-166](file:///home/snehan/projects/web/mill-ledger/server/prisma/schema.prisma#L145-L166)).
- **Phone Number**: Customer phone accepted invalid string `"12345"` without error.
- **Email**: Customer email accepted non-email string `"not-an-email-at-all"`.
- **State Code**: Stored as free-text string `"Tamil Nadu"` rather than statutory 2-digit code (`"33"`).
- **HSN Code**: Product table accepted alphanumeric string `"INVALID_HSN"`.
- **UOM Precision**: `POST /api/v1/sales/orders` accepted `quantity: 1.55555555` for discrete packaging units (returned HTTP 201).
- **Credit Limits**: Zero credit limit columns in data model; zero balance checks before approving orders.
- **Date Ordering**: `POST /api/v1/finance/invoices` accepted `dueDate: "1970-01-01"` (HTTP 201); `POST /api/v1/payments` accepted `paymentDate: "2999-12-31"` (HTTP 201).
- **Override Reason**: In [sales.routes.ts:35](file:///home/snehan/projects/web/mill-ledger/server/src/modules/sales/sales.routes.ts#L35), `overrideReason` is marked `.optional()`.

Artifact: [/audit/evidence/domain-validation-results.json](file:///home/snehan/projects/web/mill-ledger/audit/evidence/domain-validation-results.json).

### Delta
Zero enforcement of essential food manufacturing domain rules, statutory Indian business formats, or temporal invariants.

### Impact
1. Commercial risk: Over-crediting insolvent distributors with unlimited orders.
2. Floor chaos: Physical warehouse packing bays cannot dispatch 0.555 bags of flour.
3. Statutory non-compliance: Invoices with invalid HSNs, missing PIN codes, or retroactive dates violate GST Rule 46.

### Root Cause
Database models and Zod schemas use generic, unconstrained types (`z.string().optional()`, `z.number().positive()`, `String?` in Prisma) without domain refinement constraints or custom validators.

### Recommended Fix (do not apply)
1. Add `pinCode String`, `creditLimit Decimal @default(0)` to `Customer` in `schema.prisma`.
2. Refine Zod schemas with regex rules (`z.string().regex(/^[1-9][0-9]{5}$/)` for PIN; `z.string().regex(/^[6-9]\d{9}$/)` for phone).
3. Validate integer quantities when variant UOM is discrete (`code === 'BAG'`).
4. Validate `dueDate >= new Date()` and mandate `overrideReason` when `lineOverrides` are present.
