# Finding F-041: Unrestricted Report Tabs Cause 403 Console Errors for Scoped Roles (Salesman & Production)

**ID**: F-041  
**Title**: Unrestricted Report Tabs Cause 403 Console Errors for Scoped Roles (Salesman & Production)  
**Severity**: P2 (Degraded UX / Unhandled authorization errors)  
**Category**: Frontend Authorization & Error Handling  
**Standard refs**: OWASP Top 10:2021 A01 (Broken Access Control), NN/g Heuristic #5 (Error prevention)  

---

## 1. Expected vs Actual (E9 Triple)

- **EXPECTED (Authorization Matrix Section 5 & REQ-058)**:
  UI tabs should reflect the user's role scope:
  - Salesman should only see the Sales report tab.
  - Production manager should only see Production and Stock report tabs.
  Unpermitted tabs should either be hidden or disabled to prevent users from triggering forbidden API requests.
- **ACTUAL (`client/src/pages/reports-page.tsx:165-186` & Playwright Dead UI test)**:
  `ReportsPage` renders all 6 navigation tabs (`Sales register`, `GST outward summary`, `Stock valuation`, `Production & variances`, `Receivables & ageing`, `Audit logs`) to every role indiscriminately.
  When a Salesman clicks "GST outward summary" or "Audit logs", the client fires `GET /api/v1/reports/gst` or `/reports/audit`.
  The Express server correctly returns `403 Forbidden` (`reporting.routes.ts:87`), but the React client logs unhandled console errors and displays a broken or empty view without a clear user explanation.
- **DELTA**:
  14 unhandled 403 authorization crashes were logged during automated Playwright element clicks across Salesman and Production roles on `/reports/*`.

---

## 2. Impact

- Degraded user experience: Field salesmen and shop-floor production operators encounter error states and confusing empty tables on tabs they were never meant to see.

---

## 3. Repro Steps & Root Cause

1. Sign in as Salesman (`salesman1@millledger.local`).
2. Navigate to `/reports/sales`.
3. In the tab bar, click "GST outward summary" or "Audit logs".
4. Open DevTools Console: observe `403 Forbidden` Axios network errors.
5. **Root Cause**: `client/src/pages/reports-page.tsx:165-186` hardcodes a static tab array with zero role filtering based on `useCurrentUser()`.

---

## 4. Recommended Fix (Do Not Apply)

- In `ReportsPage`, filter the visible tabs based on `user?.role`:
  ```ts
  const allowedTabs = TABS.filter(t => t.roles.includes(user.role));
  ```

---

### Remediation Summary
- Defined `REPORT_TABS` with explicit permitted role sets (`roles: Role[]`) in `client/src/pages/reports-page.tsx`.
- Integrated `useCurrentUser()` to filter tabs dynamically via `allowedTabs`.
- Validated `effectiveTab` against permitted tabs for the active role, defaulting safely to the first accessible tab if the requested tab in the URL query is unauthorized.
- Conditioned React Query data queries (`useQuery`) on `effectiveTab === tab.id`, preventing unpermitted background network requests.
- Added comprehensive regression test `audit/tests/f-041-regression.test.ts` verifying UI tab filtering and backend HTTP 403 enforcement. All 39 test files and 10 SQL invariants pass.
