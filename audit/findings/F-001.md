# Finding F-001: Playwright E2E Test Failure via Duplicate Skip-to-Main-Content Links

**ID**: F-001  
**Title**: Duplicate "Skip to main content" links violate Playwright strict mode and degrade keyboard navigation  
**Severity**: P1  
**Category**: Accessibility / Test Failure  
**Standard Refs**: WCAG 2.2 SC 2.4.1 (Bypass Blocks, Level A), SC 2.4.3 (Focus Order, Level A), Playwright Strict Mode  
**Status**: VERIFIED (Merged with F-061)  
**Consolidation Note**: Incorporates Phase 8 finding F-061 regarding duplicate keyboard focus tab stops in `authenticated-shell.tsx:845` and `1079`.  

---

### Expected (source)
- `README.md` lines 56-57: `pnpm test:e2e` must pass cleanly across all browser tests.
- WCAG 2.2 SC 2.4.1: A single accessible mechanism to bypass blocks of repeated content.

### Actual (evidence links)
- Running `pnpm test:e2e` failed on test 8 of 26:
  `[desktop] › e2e/app-shell.spec.ts:251:3 › MillLedger Application Shell › keyboard accessibility: skip-to-main content link and focus`
  ```
  Error: locator.focus: Error: strict mode violation: getByRole('link', { name: 'Skip to main content' }) resolved to 2 elements:
    1) <a href="#main-content" ...>Skip to main content</a> in AuthenticatedShell
    2) <a href="#main-content" ...>Skip to main content</a> in Header
  ```
- Evidence log: [audit/evidence/10-test-e2e.txt](file:///home/snehan/projects/web/mill-ledger/audit/evidence/10-test-e2e.txt)

### Delta
Expected 1 unique skip link in DOM; found 2 duplicate skip links, causing test crash and redundant tab stop for keyboard users.

### Impact
Breaks CI test suite (`pnpm test:e2e` exits with code 1). Screen reader and keyboard-only users encounter two identical skip links on every authenticated route.

### Repro Steps
1. Run `pnpm test:e2e`
2. Observe test `e2e/app-shell.spec.ts:251:3` fails with strict mode error.

### Root Cause
File: [client/src/components/shell/authenticated-shell.tsx](file:///home/snehan/projects/web/mill-ledger/client/src/components/shell/authenticated-shell.tsx#L845-L852)
Line 845 defines a skip link inside `Header`.
Line 1080 defines a second skip link inside the outer `AuthenticatedShell` component wrapper.

### Recommended Fix (DO NOT APPLY - AUDIT ONLY)
Remove the redundant skip link at line 845 inside `Header`, retaining only the top-level skip link at line 1080 (ensuring it also supports bilingual text if desired).

### Regression Test to Add
`e2e/app-shell.spec.ts` should assert `await expect(page.getByRole("link", { name: /Skip to main content|முதன்மை பகுதி/ })).toHaveCount(1)`.

### Effort
S (Small)

## 5. Remediation & Verification

### Implementation
- Removed redundant `<a href="#main-content">` inside `StickyHeader` in `client/src/components/shell/authenticated-shell.tsx`.
- Retained canonical root skip link in `AuthenticatedShell` placed before `<Sidebar>` and `<StickyHeader>` in DOM order to guarantee proper keyboard focus order (WCAG 2.2 SC 2.4.3).
- Added bilingual support to root skip link via `useLanguage()` (`முதன்மை பகுதிக்குச் செல்லவும்` / `Skip to main content`).
- Un-quarantined `e2e/app-shell.spec.ts` test "keyboard accessibility: skip-to-main content link and focus" and added assertion verifying strict count of 1 skip link in the DOM.

### Regression Test
- Added `audit/tests/f-001-regression.test.ts` verifying:
  1. Exactly 1 skip link anchor in `authenticated-shell.tsx`.
  2. Skip link is placed at root before navigation landmarks.
  3. `StickyHeader` contains no duplicate skip link.
  4. Skip link provides bilingual label support.
