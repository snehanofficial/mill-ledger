# F-047: Absence of Sticky Table Headers and Card Transformation on Mobile Viewports

- **ID**: F-047
- **Title**: Absence of Sticky Table Headers and Card Transformation on Mobile Viewports
- **Severity**: P2
- **Category**: UX / Responsive Layout / Mobile Density
- **Standard refs**: Apple HIG adapted (Designing for Real Device Context), NN/g H8 (Aesthetic and Minimalist Design), Phase 7 Specification Check 4

---

## 1. Expected vs Actual

- **EXPECTED (Phase 7 Spec Check 4, UI-UX-Spec)**:
  1. Data tables with many rows must feature sticky headers (`sticky top-0`) so column contexts (e.g. Rate vs Taxable vs Total) remain anchored as the user scrolls through dozens of ledger entries.
  2. On mobile phone viewports (320px–390px), wide tables (8–11 columns) must adapt by transforming each row into a compact card or selectively collapsing lower-priority columns, avoiding excessive horizontal scrolling.
- **ACTUAL (evidence: `client/src/components/ui/table.tsx:23-31`, `client/src/pages/orders-page.tsx:535-640`, `client/src/pages/invoices-page.tsx:250-320`, `/audit/evidence/screenshots/SALESMAN/en/320px/orders.png`, `/audit/evidence/screenshots/ADMIN/en/390px/invoices.png`)**:
  1. `TableHeader` has `border-b border-border bg-muted/50` without `sticky top-0 z-10`. Once scrolled, all column titles vanish.
  2. Tables on mobile viewports do not adapt into card layouts. They render standard HTML tables inside a scroll wrapper:
     ```tsx
     <div className="relative w-full max-w-full overflow-x-auto ...">
     ```
     On an iPhone (390px) or 320px phone, the orders table is 950px wide. Users must swipe horizontally through 3 full screen-widths to see order status or action buttons.
- **DELTA**:
  Headers do not stick during vertical scrolling; mobile devices are forced to horizontally pan across wide desktop table rows.

---

## 2. Impact

- **Who is hurt**: Field salesmen and warehouse managers reviewing order lists and stock tables on mobile phones.
- **Operational consequence**: Losing column context when scrolling long lists; high friction swiping back and forth between customer name on the left and dispatch status / actions on the far right.

---

## 3. Repro Steps & Root Cause

### Repro Steps
1. Navigate to `http://127.0.0.1:4173/orders` on a 390px viewport (or mobile device).
2. Observe table: only the first 2 columns ("Order number", "Status") fit on screen.
3. User must swipe horizontally to see "Customer", "Salesman", "Ordered", "Taxable", "GST", "Total", "Shortage status", "Actions".
4. Scroll vertically: column headers scroll off-screen, making numbers indistinguishable.

### Root Cause
1. `client/src/components/ui/table.tsx:23` lacks `sticky top-0 bg-background z-10`.
2. Pages lack a responsive breakpoint switch (`<div className="md:hidden space-y-3">{orders.map(o => <OrderCard ... />)}</div><div className="hidden md:block"><Table ... /></div>`).

---

## 4. Recommended Fix & Regression Test

### Recommended Fix (Do Not Apply - Audit Only)
1. Add `sticky top-16 z-20 bg-background/95 backdrop-blur-xs` to `TableHeader`.
2. Implement card view components for mobile (`<md`) screens that stack essential fields: Order Number, Customer, Total (₹), and Status badge in a single thumb-tappable card.

### Regression Test to Add
- Add Playwright spec `tests/responsive-table.spec.ts` asserting:
  - At viewport 390px, table wrapper does not require `scrollLeft > 0` to view action buttons, or renders mobile card elements.
  - At scroll position Y = 500px, `thead` boundingClientRect top remains `<= 64px`.
