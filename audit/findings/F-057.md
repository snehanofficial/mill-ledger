# F-057: Unwarned Session Expiry and Form Data Destruction Under Better Auth Timeout

- **ID**: F-057
- **Title**: Unwarned Session Expiry and Form Data Destruction Under Better Auth Timeout
- **Severity**: P1
- **Category**: Accessibility / Timing / Data Preservation
- **Standard refs**: WCAG 2.2 SC 2.2.1 (Timing Adjustable - Level A), SC 3.3.7 (Redundant Entry - Level AA)

---

## 1. Expected vs Actual

- **EXPECTED (WCAG 2.2 SC 2.2.1 Level A, SC 3.3.7 Level AA)**:
  1. For each time limit that is set by the system (such as session expiration), the user must be warned at least 20 seconds before the time limit expires and given a simple action (such as pressing space or enter) to extend the time limit.
  2. If a session expires during form entry, user input must be preserved or recoverable, avoiding redundant re-entry of the same data upon re-authenticating.
- **ACTUAL (evidence: `client/src/layouts/authenticated-layout.tsx:32-46`, `server/src/modules/auth/auth.config.ts`, `audit/evidence/a11y/snapshots/comprehensive_wcag_verification.json`)**:
  In `client/src/layouts/authenticated-layout.tsx`:
  ```tsx
  useEffect(() => {
    const handleUnauthorized = () => {
      queryClient.clear();
      navigate("/auth/login", {
        replace: true,
        state: { from: location },
      });
    };

    window.addEventListener("millledger:unauthorized", handleUnauthorized);
    return () => {
      window.removeEventListener("millledger:unauthorized", handleUnauthorized);
    };
  }, [navigate, queryClient, location]);
  ```
  1. When an active session expires, the first 401 response from the API immediately wipes the cache (`queryClient.clear()`) and forcibly redirects the user to `/auth/login`.
  2. Zero warning dialog or timer is presented before expiration.
  3. No countdown or "Extend session" control exists.
  4. Form data currently in progress (e.g. multi-step production batch details with flour, oil, salt and output measurements, or an elaborate sales order) is completely destroyed without local caching or recovery.
- **DELTA**:
  Abrupt, unannounced session termination with 100% loss of uncommitted data.

---

## 2. Impact

- **Who is hurt**: Floor operators taking time to record physical scale weights, accountants cross-referencing paper ledgers, and users with cognitive or motor disabilities who require additional time to complete forms.
- **Operational consequence**: Wasted labor, data loss, frustration, and potential shop floor delays.

---

## 3. Repro Steps & Root Cause

### Repro Steps
1. Navigate to `/production/new` and enter batch ingredients and machine parameters.
2. In developer tools, invalidate the session cookie or trigger a `millledger:unauthorized` custom event.
3. Observe immediate jump to `/auth/login`.
4. Log back in -> verify `/production/new` is empty and all entered numbers are gone.

### Root Cause
Session expiry handling was designed solely as a reactive HTTP 401 error handler without a client-side session timeout warning or draft persistence layer.

---

## 4. Recommended Fix & Regression Test

### Recommended Fix
1. Track session age or Better Auth cookie expiration and display a 2-minute modal countdown: "Your session will expire in 2 minutes. [Extend Session]".
2. Before redirecting to login on 401, serialize dirty form drafts to local IndexedDB (Dexie) so they can be rehydrated upon re-login.

### Regression Test
Simulate impending timeout in test harness: assert warning dialog appears with extend action, and assert form state is restored after re-authentication.

- **Effort**: M
- **Status**: VERIFIED
- **Resolution**: Implemented proactive `useSessionTimeout` tracking with a 15-minute default timeout, 2-minute countdown warning modal (`SessionTimeoutModal`), and automatic form draft serialization (`saveActiveFormDraft`, `getSavedFormDraft`, `clearFormDraft`) into `sessionStorage`. Both idle timeout and reactive 401 unauthorized events preserve unsubmitted form data before redirecting to `/auth/login` with `sessionExpired: true`.
