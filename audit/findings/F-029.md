# Finding F-029: Software Supply Chain Integrity Deviations: Mutable CI Actions, Missing Minimum Release Age, and Unconstrained Production Seed

**ID**: F-029  
**Title**: CI pipeline uses mutable GitHub Action references, lacks package manager release-age protection, and exposes unconstrained database seeds  
**Severity**: P2  
**Category**: Software & Data Integrity Failures / Supply Chain  
**Standard Refs**: OWASP Top 10:2021 A08:2021 (Software and Data Integrity Failures), OWASP API Security Top 10:2023 API8:2023 (Security Misconfiguration), OWASP ASVS v4.0.3 Section 10.3.1 (Verify that third-party components are verified for integrity), Section 14.2.1 (Verify that all build and deployment pipeline tasks are hardened)  

---

## Expected (Source)
Source: OWASP ASVS v4.0.3 Sec 10.3, 14.2 & GitHub Actions Security Hardening Guide.
1. GitHub Actions steps must be pinned to full 40-character commit SHAs rather than mutable tags (`@v4`) to prevent upstream supply-chain tampering.
2. Package manager configurations (`.npmrc`, `pnpm-workspace.yaml`) must enforce minimum package release age (`minimumReleaseAge` or `min-release-age = 7`) and `blockExoticSubdeps` to protect against newly published zero-day typosquatting or compromised releases.
3. Database seed scripts containing hardcoded default credentials must be explicitly prohibited from running in production (`process.env.NODE_ENV === "production"`).

## Actual (Evidence Links)
Evidence: Semgrep scan results in [/audit/evidence/semgrep-results.txt](file:///home/snehan/projects/web/mill-ledger/audit/evidence/semgrep-results.txt) and inspected code in [.github/workflows/ci.yml](file:///home/snehan/projects/web/mill-ledger/.github/workflows/ci.yml) and [server/prisma/seed.ts](file:///home/snehan/projects/web/mill-ledger/server/prisma/seed.ts).

1. In `.github/workflows/ci.yml:43,46,51`:
   - `uses: actions/checkout@v4`
   - `uses: pnpm/action-setup@v4`
   - `uses: actions/setup-node@v4`
   All use mutable tags subject to silent tag retargeting in compromised upstream repositories.
2. In `.npmrc` and `pnpm-workspace.yaml`:
   - Omit `min-release-age = 7`
   - Omit `blockExoticSubdeps: true`
   - Omit `trustPolicy: no-downgrade`
3. In `server/prisma/seed.ts:601-615`:
   `runFullSeed()` executes unconditionally without verifying `env.NODE_ENV !== "production"`. Running seed in a live deployment will create default accounts (`admin@millledger.local` with password `AdminPassword123!`) on the production database.

---

## Delta
The build and CI infrastructure lacks immutable action pinning, delayed package resolution defenses, and production environment guardrails on seeding default credentials.

---

## Impact
- **Supply Chain Compromise**: If an upstream action maintainer account or token is compromised, arbitrary malicious code could run during CI with access to GitHub repository secrets and tokens.
- **Credential Poisoning**: Accidental or automated invocation of `pnpm db:seed` in production populates well-known administrative credentials with static passwords.
