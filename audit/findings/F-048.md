# F-048: Missing Confirmation Dialogs for Irreversible Operations (Dispatch, Order Rejection)

- **ID**: F-048
- **Title**: Missing Confirmation Dialogs for Irreversible Operations (Dispatch, Order Rejection)
- **Severity**: P2
- **Category**: UX / Error Prevention / Safety
- **Standard refs**: NN/g H5 (Error Prevention), Phase 7 Specification Check 5

---

## 1. Expected vs Actual

- **EXPECTED (Phase 7 Spec Check 5, UI-UX-Spec)**:
  Irreversible operational transitions—such as posting a vehicle dispatch (which irrevocably deducts physical finished goods inventory and generates immutable dispatch tracking), or rejecting a submitted sales order (which permanently cancels reserved stock allocations)—must present a dedicated confirmation dialog. The dialog must explicitly state the consequences (e.g. "This action will permanently deduct 200 packets from inventory and cannot be undone") and require explicit confirmation.
- **ACTUAL (evidence: `client/src/pages/dispatch-page.tsx:541-555`, `client/src/pages/orders-page.tsx:1030-1065`, `client/src/components/ui/confirmation-dialog.tsx`)**:
  1. `ConfirmationDialog` and `AlertDialog` exist in `client/src/components/ui/` but are ONLY used in `showcase-page.tsx`!
  2. On `/dispatch`: Filling the slide-out sheet and clicking "Confirm dispatch" immediately sends `POST /api/v1/dispatch` without any intermediate confirmation warning or explanation of immutable stock consequences.
  3. On `/orders`: Clicking "Confirm rejection" immediately fires `rejectMutation` without summarizing the business impact on the customer's outstanding booking.
  4. Once dispatched or rejected, the UI offers zero reversal, credit note, or undo path.
- **DELTA**:
  High-consequence destructive actions lack consequential warnings; safety primitives built in the UI library remain unintegrated into production pages.

---

## 2. Impact

- **Who is hurt**: Dispatch clerks and warehouse supervisors who accidentally click "Confirm dispatch" on the wrong sales order or enter an incorrect vehicle number.
- **Operational consequence**: Inventory ledger is immediately and permanently altered in PostgreSQL; reversing the erroneous dispatch requires manual DB manipulation or complex off-system adjustments.

---

## 3. Repro Steps & Root Cause

### Repro Steps
1. Navigate to `http://127.0.0.1:4173/dispatch` as `admin@millledger.local`.
2. Click "New dispatch", select an approved order.
3. Click "Confirm dispatch" button at the bottom of the sheet.
4. Observe: The dispatch is executed immediately without a modal confirmation dialog warning that stock will be deducted permanently.

### Root Cause
1. `dispatch-page.tsx:541` binds submission directly to `dispatchMutation.mutate()` without an `AlertDialog` interceptor.

---

## 4. Recommended Fix & Regression Test

### Recommended Fix (Do Not Apply - Audit Only)
1. Wrap destructive submit triggers in `<ConfirmationDialog>`:
   - Title: "Confirm Physical Dispatch?"
   - Description: "This will deduct X units of finished goods stock and generate an immutable dispatch record. This action cannot be undone."
2. Provide an administrative dispatch cancellation or return workflow in subsequent milestones.

### Regression Test to Add
- Add Playwright spec `tests/irreversible-confirmations.spec.ts` asserting:
  - Clicking "Confirm dispatch" opens a Radix `AlertDialog` with role="alertdialog" explaining consequences.
