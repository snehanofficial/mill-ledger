# F-045: Lack of Skeleton Loaders and Omission of Request IDs in UI Error States

- **ID**: F-045
- **Title**: Lack of Skeleton Loaders and Omission of Request IDs in UI Error States
- **Severity**: P2
- **Category**: UX / System Feedback / Error Recovery
- **Standard refs**: NN/g H1 (Visibility of System Status), NN/g H9 (Help Users Recognize, Diagnose, and Recover from Errors), Phase 7 Specification Check 2

---

## 1. Expected vs Actual

- **EXPECTED (Phase 7 Spec Check 2, UI-UX-Spec)**:
  Every screen must provide structured loading feedback using layout skeletons (not spinner-only boxes) to maintain layout stability (zero CLS) and communicate content hierarchy before data arrives. When an error occurs, the screen must display what happened, recommended user action, and the specific Request ID (`x-request-id` from server error envelope) to enable support debugging.
- **ACTUAL (evidence: `client/src/pages/orders-page.tsx:499-514`, `client/src/pages/dashboard-page.tsx:131-144`, `client/src/pages/invoices-page.tsx:221-236`, `client/src/components/ui/loading-error-empty.tsx:34-63`)**:
  1. **Loading State**: Despite `Skeleton` and `SkeletonTable` components existing in `client/src/components/ui/`, all 11 production pages render a centered spinner:
     ```tsx
     <div className="flex items-center justify-center p-12 text-sm text-muted-foreground">
       <RefreshCwIcon className="mr-2 h-4 w-4 animate-spin" />
       Loading orders...
     </div>
     ```
     This collapses the table height to 96px during fetch and causes Cumulative Layout Shift (CLS) when table rows pop in.
  2. **Error State**: When API requests fail, the error boundary renders a generic box:
     ```tsx
     <div className="flex flex-col items-center justify-center gap-2 p-12 text-sm text-destructive">
       <AlertTriangleIcon className="h-6 w-6" />
       <span>Failed to load sales orders</span>
       <Button variant="outline" size="sm" onClick={() => refetch()}>Retry</Button>
     </div>
     ```
     Zero screens extract or display the `requestId` returned by the Express error middleware (`{ error: { code, message, requestId } }`).
- **DELTA**:
  Skeleton loading is completely absent from all functional pages; error states omit the server Request ID needed for diagnostic triage.

---

## 2. Impact

- **Who is hurt**: Users on 2G/3G mobile networks experiencing layout jumps as data streams in; customer support and developers attempting to triage customer bug reports without a correlation ID.
- **Operational consequence**: High bounce/frustration due to layout shift; support staff cannot match a user's "Failed to load orders" error to backend server logs.

---

## 3. Repro Steps & Root Cause

### Repro Steps
1. In Chrome DevTools Network tab, throttle connection to "Slow 3G".
2. Navigate to `http://127.0.0.1:4173/orders`.
3. Observe: Screen renders a single text line with spinning icon; table geometry is collapsed. Once data arrives, entire layout jumps down.
4. Block URL `/api/v1/sales/orders` in DevTools network blocking.
5. Reload page.
6. Observe: "Failed to load sales orders" alert appears with a Retry button, but no Request ID or error code is displayed.

### Root Cause
1. Page components use inline ternaries (`isLoading ? <RefreshCwIcon /> : ...`) rather than rendering `<SkeletonTable />`.
2. Error state rendering ignores `error.response?.data?.error?.requestId`.

---

## 4. Recommended Fix & Regression Test

### Recommended Fix (Do Not Apply - Audit Only)
1. Replace `<RefreshCwIcon animate-spin />` in page bodies with `<SkeletonTable rows={6} />` and KPI card skeletons.
2. In `ErrorState` component (`loading-error-empty.tsx`), add an optional `requestId?: string` prop and render `Request ID: {requestId}` with a one-click copy button.

### Regression Test to Add
- Add Playwright spec `tests/states-diagnostics.spec.ts` asserting:
  - During loading, `[data-slot="skeleton"]` elements exist in the DOM.
  - When API returns HTTP 500 with `{ requestId: "req-123" }`, text `"Request ID: req-123"` is visible on screen.
