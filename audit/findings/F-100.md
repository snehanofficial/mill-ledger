# F-100: Missing Fail-Fast Environment Validation on `DATABASE_URL` and Absence of Staging / Production Env Configs

- **ID**: F-100
- **Title**: Missing Fail-Fast Environment Validation on `DATABASE_URL` and Absence of Staging / Production Env Configs
- **Severity**: P1
- **Category**: Configuration & Secret Management
- **Standard Refs**:
  - OWASP Top 10:2021 A05:2021 (Security Misconfiguration)
  - 12-Factor App (Factor III: Config)
  - Master Rulebook: "If a required setting is missing, fail loudly. Don't quietly carry on."

---

## Expected (Source)
- **Source**: Master Rulebook and Twelve-Factor App Principles:
  - Required infrastructure settings (specifically database connection strings) must be strictly validated at process startup.
  - In production (`NODE_ENV=production`), omitting `DATABASE_URL` must immediately crash the process with an unambiguous error rather than silently defaulting to local development credentials.
  - Distinct configuration templates must exist for development, staging, and production environments.

---

## Actual (Evidence Links)
1. **Silent Fallback to Local Database in Production**:
   - [`server/src/config/env.ts:14-19`](file:///home/snehan/projects/web/mill-ledger/server/src/config/env.ts#L14-L19):
     ```typescript
     DATABASE_URL: z
       .string()
       .url()
       .default(
         "postgresql://postgres:postgres@localhost:5432/mill_ledger?schema=public",
       ),
     ```
   - In [`server/src/config/env.ts:24-56`](file:///home/snehan/projects/web/mill-ledger/server/src/config/env.ts#L24-L56), the `superRefine` hook validates `BETTER_AUTH_SECRET` and `CORS_ORIGIN` in production, but **does not check `DATABASE_URL`**.
   - **Verification Execution** (`audit/evidence/config-boot-results.json`):
     ```bash
     NODE_ENV=production BETTER_AUTH_SECRET="thirty-two-character-valid-production-secret!" CORS_ORIGIN="https://mill.example.com" pnpm --filter @mill-ledger/server exec tsx -e 'import { env } from "./src/config/env.js"; console.log(env.DATABASE_URL);'
     ```
     **Result**: Exit code `0`. Prints:
     `postgresql://postgres:postgres@localhost:5432/mill_ledger?schema=public`
     The server silently assumes a local development PostgreSQL instance.
2. **Missing Environment Configuration Files**:
   - The workspace contains only `.env.example` and `server/.env`.
   - No `.env.development`, `.env.staging`, or `.env.production` files exist. There is zero configuration for a staging environment.

---

## Delta
- The server fails to enforce mandatory `DATABASE_URL` presence in production, silently falling back to a default localhost connection string with default credentials `postgres:postgres`. Staging environment configurations are completely absent.

---

## Impact
- **Silent Boot Failure / Wrong Target**: If a deployment manifest (e.g. Helm chart or ECS task definition) accidentally omits the secret reference for `DATABASE_URL`, the production application will boot without error, attempt to contact `localhost:5432`, and throw intermittent connection refused exceptions during customer transactions.
- **Accidental Local Connection**: In container networks where localhost might resolve to a sidecar or local container, it may write production transactions to an unmonitored default local database.

---

## Repro Steps
1. Run `audit/scripts/test-phase14-config.ts` or:

2. Observe process exits with code 0 and logs default localhost URL.

---

## Root Cause
- `DATABASE_URL` was configured with `.default(...)` in the Zod schema without a conditional override in the production `superRefine` block.

---

## Recommended Fix
1. In `server/src/config/env.ts`, ensure `DATABASE_URL` has no `.default(...)` when `NODE_ENV === "production"`, or add a check in `superRefine`:
   ```typescript
   if (data.NODE_ENV === "production") {
     if (!process.env.DATABASE_URL || data.DATABASE_URL.includes("localhost") || data.DATABASE_URL.includes("127.0.0.1")) {
       ctx.addIssue({
         code: z.ZodIssueCode.custom,
         path: ["DATABASE_URL"],
         message: "DATABASE_URL must be explicitly configured with a non-localhost production database in production",
       });
     }
   }
   ```
2. Provide `.env.development.example`, `.env.staging.example`, and `.env.production.example` templates.
