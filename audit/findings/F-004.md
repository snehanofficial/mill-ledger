# Finding F-004: Seed Script Lacks Production Guard Allowing Test Fixture Injection

**ID**: F-004  
**Title**: Prisma seed script executes in production mode without guard or confirmation, injecting hardcoded test accounts  
**Severity**: P0  
**Category**: Security / Data Integrity / Credential Exposure  
**Standard Refs**: OWASP Top 10:2021 A01 (Broken Access Control), A07 (Identification and Authentication Failures), OWASP ASVS v4.0.3 Item 2.1.1, Req 1.14.1, ISO/IEC 27001:2022 Control 8.31  
**Status**: OPEN (Merged with F-101)  
**Consolidation Note**: Incorporates Phase 14 finding F-101. Evidence also captured in `audit/evidence/config-boot-results.json`.  

---

### Expected (source)
Production seeding scripts must guard against execution in `NODE_ENV === "production"` unless an explicit `--force` flag or dedicated environment flag is provided, to prevent overwriting live master data and creating vulnerable accounts with known passwords.

### Actual (evidence links)
- Running `NODE_ENV=production BETTER_AUTH_SECRET="long-secure-random-prod-secret-1234567890" CORS_ORIGIN="https://millledger.com" BETTER_AUTH_URL="https://millledger.com" ./server/node_modules/.bin/tsx server/prisma/seed.ts` executed cleanly without any warning.
- It upserted 8 test accounts with known static passwords (`AdminPassword123!`, `SalesmanPassword123!`, etc.) into the database.
- File: [server/prisma/seed.ts](file:///home/snehan/projects/web/mill-ledger/server/prisma/seed.ts#L600-L615) contains zero environment guards.

### Delta
Expected production block or explicit refusal; observed unrestricted execution and injection of test accounts into production environment.

### Impact
Critical security and audit failure. If accidentally run on staging or production, anyone knowing the default repository passwords can access Admin, Owner, Accountant, and Salesman roles immediately.

### Repro Steps
1. Set `NODE_ENV=production` with valid production secrets.
2. Run `tsx server/prisma/seed.ts`.
3. Script executes and reports `M2 benchmark master data seed successfully completed`.

### Root Cause
File: [server/prisma/seed.ts](file:///home/snehan/projects/web/mill-ledger/server/prisma/seed.ts#L600-L615)
No verification of `process.env.NODE_ENV === "production"`.

### Recommended Fix (DO NOT APPLY - AUDIT ONLY)
Add a strict guard at the beginning of `seed.ts`:
```ts
if (process.env.NODE_ENV === "production" && !process.env.ALLOW_PRODUCTION_SEED) {
  console.error("FATAL: Seed script cannot run in production mode without ALLOW_PRODUCTION_SEED=true");
  process.exit(1);
}
```

### Regression Test to Add
Unit test asserting that invoking `seed.ts` in `NODE_ENV=production` exits with code 1.
