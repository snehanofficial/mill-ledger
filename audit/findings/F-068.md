# Finding F-068: Route Transitions Fail to Manage Focus to `<main>` or `<h1>`

- **ID**: F-068
- **Title**: Route Transitions Fail to Reset Focus to `<main>` or `<h1>`
- **Severity**: P1
- **Category**: Accessibility / SPA Routing
- **Standard Refs**:
  - W3C WCAG 2.2 Success Criterion 2.4.3 Focus Order (Level A)
  - W3C WCAG 2.2 Success Criterion 1.3.2 Meaningful Sequence (Level A)
  - W3C WAI-ARIA Authoring Practices Guide: SPA Navigation and Focus Management
  - Master Rulebook Phase 9 Requirement: "Page and route transitions: focus management is kept, scroll position handled, no blank flash."

---

## Expected Behavior
In single-page applications (SPAs) built with client-side routers (such as React Router), navigating to a new route does not trigger a full browser reload. Assistive technology and keyboard-only users rely on the framework to actively shift focus upon route change—either to `<main id="main-content">` or to the top-level page `<h1>` heading—and announce the new view title.

---

## Actual Behavior
1. In `client/src/components/shell/authenticated-shell.tsx:1182`, `<main id="main-content">` has `tabIndex={-1}`, but there is NO effect or hook listening to location changes to shift focus into it.
2. When a user clicks a navigation link in the sidebar (for example, clicking `Orders` or `Stock`), focus remains trapped on the clicked `<a>` element in the sidebar DOM list:
   - Programmatic audit evidence from `audit/evidence/motion/metrics/route-transition-audit.json`:
     ```json
     "focusAfterNav": {
       "activeTagName": "A",
       "activeClassName": "peer/menu-button flex w-full ...",
       "isMainContent": false,
       "isH1": false,
       "isBody": false
     },
     "focusManagedObserved": false
     ```
3. Because focus remains on the clicked navigation item, pressing `Tab` continues tabbing through the remainder of the sidebar navigation links rather than entering the new page's primary content.

---

## Delta
Route changes fail to reset or manage keyboard focus, leaving focus trapped inside the sidebar navigation list on every client route transition.

---

## Impact
Screen reader users are not notified that the page has loaded new content and cannot immediately read the new page title or main view. Keyboard users must press `Tab` 15-25 times through the remaining sidebar items to reach the content of the page they just selected.

---

## Repro Steps
1. Navigate to `/dashboard` using keyboard navigation.
2. Press `Tab` to navigate down the sidebar and press `Enter` on `Stock`.
3. Check `document.activeElement`.
4. Observe that focus is still on `<a href="/stock">` inside the sidebar. Pressing `Tab` focuses the next sidebar item (`Purchases`) instead of the Stock search bar or page heading.

## Recommended Fix
In `client/src/layouts/authenticated-layout.tsx`, add an effect on `location.pathname`:
```tsx
useEffect(() => {
  const main = document.getElementById("main-content");
  if (main) {
    main.focus({ preventScroll: true });
  }
}, [location.pathname]);
```

- **Resolution**: Integrated route transition focus management in `client/src/layouts/authenticated-layout.tsx`. On every client-side route navigation (`location.pathname`), the layout locates the primary `<main id="main-content" tabIndex={-1}>` landmark, shifts keyboard focus into it with `preventScroll: true`, and resets scroll positions (`main.scrollTo` and `window.scrollTo` to top: 0). Satisfies WCAG 2.2 SC 2.4.3 (Focus Order) and SC 1.3.2 (Meaningful Sequence).
