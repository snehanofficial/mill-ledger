# F-055: Interactive Touch Targets Below WCAG 2.5.8 Minimum (24x24px) and Apple HIG (44x44px)

- **ID**: F-055
- **Title**: Interactive Touch Targets Below WCAG 2.5.8 Minimum (24x24px) and Apple HIG (44x44px)
- **Severity**: P2
- **Category**: Accessibility / Motor Impairment / Touch Target Sizing
- **Standard refs**: WCAG 2.2 SC 2.5.8 (Target Size (Minimum) - Level AA), Apple Human Interface Guidelines (Touch Targets)

---

## 1. Expected vs Actual

- **EXPECTED (WCAG 2.2 SC 2.5.8 Level AA, Apple HIG)**:
  1. Under WCAG 2.2 SC 2.5.8 (Level AA), the size of the target for pointer inputs must be at least 24 by 24 CSS pixels, unless an exception applies (e.g. inline text links, user agent controls).
  2. Under Apple HIG (and mobile-first ERP standards), touch targets for handheld operational devices must be at least 44 by 44 CSS pixels.
- **ACTUAL (evidence: `client/src/components/ui/sidebar.tsx:707-721`, `client/src/pages/orders-page.tsx:631, 642, 653`, `audit/evidence/a11y/snapshots/comprehensive_wcag_verification.json`)**:
  1. **WCAG 2.5.8 Level AA Violation**:
     - The `SidebarRail` interactive button (`client/src/components/ui/sidebar.tsx:707`):
       ```tsx
       <button
         data-sidebar="rail"
         aria-label="Resize sidebar"
         className="absolute inset-y-0 z-20 hidden w-4 -translate-x-1/2 transition-all ease-linear ..."
       ```
       The bounding box is **16px wide** (`width: 16px, height: 800px`). A 16px wide target is an outright violation of the 24 CSS px minimum.
     - Breadcrumb navigation links (`<a class="...">`) render with `height: 20px`.
  2. **Apple HIG (< 44x44px) Violations**:
     Automated measurement across `/orders`, `/invoices`, and `/dashboard` found **21 interactive elements** measuring between 24px and 36px:
     - Table row action buttons: `h-6 px-2` (24px height x 28px width) and `h-7 px-2` (28px height x 32px width).
     - Compact outbox sync and delete buttons.
- **DELTA**:
  Sidebar rail control fails WCAG 2.5.8 AA (16px < 24px); 21 table and toolbar buttons fail Apple HIG guidelines on mobile touchscreens.

---

## 2. Impact

- **Who is hurt**: Users with tremors, motor impairments, and warehouse floor operators wearing work gloves or using mobile phones.
- **Operational consequence**: Frequent mis-taps, accidental trigger of adjacent table row actions, or inability to hit the 16px sidebar rail handle.

---

## 3. Repro Steps & Root Cause

### Repro Steps
1. Navigate to `/orders`.
2. Inspect `button[aria-label="Resize sidebar"]` in Chrome DevTools -> Computed styles: `width: 16px`.
3. Inspect action buttons in orders table: `height: 24px, width: 28px`.

### Root Cause
Applying desktop-density micro-utility classes (`h-6`, `w-4`, `text-2xs`) without minimum touch target padding or invisible pseudo-element expansion (`before:absolute before:-inset-2`).

---

## 4. Recommended Fix & Regression Test

### Recommended Fix
1. For `SidebarRail`, expand the interactive hit area to at least 24px (e.g. `w-6` or add an invisible pseudo-element `after:absolute after:inset-y-0 after:-inset-x-2`).
2. For compact table buttons, add a touch-target expansion utility:
   ```css
   .touch-target {
     min-width: 44px;
     min-height: 44px;
   }
   ```
   or expand the hit target with `before:content-[''] before:absolute before:-inset-2`.

### Regression Test
Run Playwright bounding rect test on all buttons: assert `width >= 24 && height >= 24` for every interactive control.
