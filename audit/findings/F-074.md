# F-074: Absence of Server Pagination and List Virtualization Across All Enterprise Entity Grids

- **ID**: F-074
- **Title**: Absence of Server Pagination and List Virtualization Across All Enterprise Entity Grids
- **Severity**: P1
- **Category**: Network & UI Scalability / DOM Performance
- **Standard Refs**:
  - OWASP API Security Top 10:2023 API4:2023 (Unrestricted Resource Consumption)
  - NN/g Heuristic #8: Aesthetic and minimalist design / System performance

---

## Expected (Source)
- **Source**: Phase 10 Audit Prompt & Specification (`audit/01-expected-spec.md` REQ-055, REQ-064).
- Enterprise ERP entity listings (orders, invoices, stock items, customer records, payments) must enforce server-side pagination with sane limits (e.g. 25-100 items per page), and frontend tables exceeding ~100 rows must use DOM list virtualization to prevent main-thread freezing and browser DOM bloat.

---

## Actual (Evidence Links)
- **Evidence**:
  - Backend controllers search: `grep -rn "findMany" server/src/modules/`.
    - `sales.service.ts`: `getOrders` calls `prisma.salesOrder.findMany({ where })` without `take` or `skip`.
    - `finance.service.ts`: `getInvoices` calls `prisma.salesInvoice.findMany({ where })` without `take` or `skip`.
    - `inventory.service.ts`: `getItems` and `getStockMovements` call `findMany` without `take` or `skip`.
    - `payment.service.ts`: `getPayments` calls `findMany` without `take` or `skip`.
    - `dispatch.service.ts`: `getDispatches` calls `findMany` without `take` or `skip`.
  - Frontend components search:
    - Zero virtualization libraries installed (`client/package.json` lacks `@tanstack/react-virtual`, `react-window`, or `react-virtualized`).
    - [`client/src/pages/orders-page.tsx`](file:///home/snehan/projects/web/mill-ledger/client/src/pages/orders-page.tsx), [`customers-page.tsx`](file:///home/snehan/projects/web/mill-ledger/client/src/pages/customers-page.tsx), and [`invoices-page.tsx`](file:///home/snehan/projects/web/mill-ledger/client/src/pages/invoices-page.tsx) render plain `<table>` elements iterating over `items.map(...)`.

---

## Delta
Server pagination is missing across 100% of core operational entities (only `audit_log` supports a `limit` parameter).
Frontend virtualization is completely absent. When a factory accumulates 5,000 invoices or 10,000 orders:
1. The backend transfers 20+ MB uncompressed JSON over the network.
2. The browser attempts to instantiate 10,000 `<tr>` and 80,000 `<td>` elements in the DOM tree simultaneously, freezing the UI thread for multiple seconds and crashing low-memory mobile browsers.

---

## Impact
- **Who is hurt**: All users viewing historical records.
- **How**: Severe client tab freezing, high memory consumption (> 500 MB RAM per browser tab), unresponsive buttons, and mobile browser crashes.

---

## Repro Steps
1. Navigate to `/invoices` or `/orders` with seeded 5,000 invoices or 10,000 orders.
2. Open Chrome DevTools Performance monitor.
3. Observe DOM node count jump from ~500 nodes to over 60,000 nodes, with prolonged JavaScript execution time (> 3,000ms).

---

## Recommended Fix (Do Not Apply)
1. Add `page` and `limit` query parameters (default `limit=50`, max `limit=100`) to all list endpoints.
2. Return standard pagination metadata: `{ data: [...], pagination: { page, limit, total, totalPages } }`.
3. Implement `@tanstack/react-virtual` or pagination controls (`Previous` / `Next`) on all frontend table pages.

---
