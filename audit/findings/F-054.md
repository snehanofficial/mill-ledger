# F-054: Label in Name Mismatch on Multilingual Language Switcher

- **ID**: F-054
- **Title**: Label in Name Mismatch on Multilingual Language Switcher
- **Severity**: P2
- **Category**: Accessibility / Accessible Names / Speech Input
- **Standard refs**: WCAG 2.2 SC 2.5.3 (Label in Name - Level A), Lighthouse audit `label-content-name-mismatch`

---

## 1. Expected vs Actual

- **EXPECTED (WCAG 2.2 SC 2.5.3 Level A)**:
  For user interface components with labels that include text or images of text, the accessible name must contain the text that is presented visually.
- **ACTUAL (evidence: `client/src/pages/login-page.tsx:181-192`, `audit/evidence/a11y/lighthouse/login-accessibility.json`)**:
  On `/auth/login`, the language switch button is coded as:
  ```tsx
  <Button
    variant="outline"
    size="sm"
    onClick={() => setLanguage(language === "en" ? "ta" : "en")}
    aria-label={
      language === "en"
        ? "Switch language to Tamil"
        : "ஆங்கிலத்திற்கு மாற்று"
    }
  >
    {language === "en" ? "தமிழ்" : "English"}
  </Button>
  ```
  1. When `language === "en"`, the visible button text is `"தமிழ்"`, but the accessible name (`aria-label`) is `"Switch language to Tamil"`. The visible word `"தமிழ்"` does NOT appear anywhere in the accessible name.
  2. When `language === "ta"`, the visible button text is `"English"`, but the accessible name (`aria-label`) is `"ஆங்கிலத்திற்கு மாற்று"`. The visible word `"English"` does NOT appear in the accessible name.
  Lighthouse accessibility audit on `/auth/login` failed with score 0 on `label-content-name-mismatch`:
  > "Elements with visible text labels do not have matching accessible names. Text inside the element is not included in the accessible name."
- **DELTA**:
  Direct violation of WCAG 2.2 SC 2.5.3 on the primary public entrypoint.

---

## 2. Impact

- **Who is hurt**: Speech-recognition users (e.g. Dragon NaturallySpeaking, Windows Speech Recognition, Apple Voice Control) and screen reader users navigating by visual text.
- **Operational consequence**: A speech-input user speaking the visual label "Click தமிழ்" or "Click English" will fail because the software matches the command against the accessible name, which contains entirely different words.

---

## 3. Repro Steps & Root Cause

### Repro Steps
1. Navigate to `http://localhost:4173/auth/login`.
2. Inspect the top-right button in DOM:
   Visual text: `தமிழ்`
   Attribute: `aria-label="Switch language to Tamil"`
3. Run Lighthouse accessibility audit -> flags `label-content-name-mismatch`.

### Root Cause
Overriding the button's accessible name with an explanatory phrase (`"Switch language to Tamil"`) rather than including the visible text or relying on the button's natural inner text.

---

## 4. Recommended Fix & Regression Test

### Recommended Fix
Ensure the accessible name starts with or contains the visible text label:
```tsx
<Button
  variant="outline"
  size="sm"
  onClick={() => setLanguage(language === "en" ? "ta" : "en")}
  aria-label={
    language === "en"
      ? "தமிழ் (Switch language to Tamil)"
      : "English (ஆங்கிலத்திற்கு மாற்று)"
  }
>
  {language === "en" ? "தமிழ்" : "English"}
</Button>
```

### Regression Test
Run Lighthouse accessibility audit: assert `audits['label-content-name-mismatch'].score === 1`.
