## Expected (Source)
- **Source**: MillLedger Architecture Baseline (`AGENTS.md`) and Master Rulebook:
  - Consistency Principle: One money formatter, one date formatter, one API client, one error handler, one validation library, one folder convention, one naming convention.
  - Indian accounting ERPs must consistently display currency formatted to Indian numbering standards (`en-IN` format: ₹1,00,000.00) with two decimal places.
  - Dates and timestamps must follow consistent Indian Standard Time (IST) formatting.

3. **Dual HTTP Client Implementation**:
   - `client/src/lib/api-client.ts` defines an Axios instance for all business routes.
   - `client/src/lib/auth-client.ts` uses native `fetch()` for `/api/auth/sign-in/email` and `/api/auth/sign-out`, bypassing Axios interceptors and error logging.
4. **Mismatched Error Envelopes**:
   - Client pages parse errors inconsistently: `orders-page.tsx` checks `err.response?.data?.message` (which fails silently), while `production-page.tsx` checks `err.response?.data?.error`.

---

## Delta
- The architecture violates the "Rule of One": zero single source of truth for currency formatting, zero single source of truth for date formatting, two HTTP clients, and competing error parsing conventions.

---

## Impact
- **Financial Ambiguity**: Numbers appear differently depending on the screen. On `/stock`, large numbers use Indian numbering (e.g., `₹1,25,000.00`), while on `/reports/sales`, numbers appear as `₹125000.00` without commas, confusing shop floor managers and accounting auditors.
- **Client Locale Fragility**: Passing `undefined` to `toLocaleString()` results in US format (`$100,000.00` with commas every 3 digits) or European format (`100.000,00` with dots) depending on the end-user's device settings.

## Root Cause
- Organic component development without creating a foundational UI utility module (`@/lib/formatters.ts`) prior to implementing pages.

---

## Recommended Fix
1. Create a single, canonical formatting utility `client/src/lib/formatters.ts` (and expose via `@mill-ledger/shared`):
   ```typescript
   export function formatINR(amount: number | string): string {
     const num = typeof amount === "number" ? amount : Number(amount);
     if (isNaN(num)) return "₹0.00";
     return new Intl.NumberFormat("en-IN", {
       style: "currency",
       currency: "INR",
       minimumFractionDigits: 2,
       maximumFractionDigits: 2,
     }).format(num);
   }

   export function formatDate(date: string | Date): string {
     return new Intl.DateTimeFormat("en-IN", {
       day: "2-digit",
       month: "short",
       year: "numeric",
     }).format(new Date(date));
   }
   ```
2. Refactor all 7 operational pages to import `formatINR` and `formatDate`.
3. Standardize `auth-client.ts` to use `apiClient` or migrate all requests to a unified `fetch` wrapper.
