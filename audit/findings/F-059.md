# F-059: Dynamic Shortage Banners and Form Errors Lack ARIA Live Region / Status Role

- **ID**: F-059
- **Title**: Dynamic Shortage Banners and Form Errors Lack ARIA Live Region / Status Role
- **Severity**: P2
- **Category**: Accessibility / Assistive Technology / Dynamic Announcements
- **Standard refs**: WCAG 2.2 SC 4.1.3 (Status Messages - Level AA), SC 3.3.1 (Error Identification - Level A)

---

## 1. Expected vs Actual

- **EXPECTED (WCAG 2.2 SC 4.1.3 Level AA, SC 3.3.1 Level A)**:
  In content implemented using markup languages, status messages and dynamically injected alert banners must be programmatically determined through role or properties (such as `role="status"`, `role="alert"`, or `aria-live="polite"|"assertive"`) so they are announced to assistive technologies without receiving focus.
- **ACTUAL (evidence: `client/src/pages/orders-page.tsx:995-1002`, `client/src/pages/payments-page.tsx:856-861`, `audit/evidence/a11y/snapshots/comprehensive_wcag_verification.json`)**:
  1. **Order Shortage Warning Banner (`orders-page.tsx:995`)**:
     When approving an order where stock is insufficient, the shortage notice is injected as a plain `<div>`:
     ```tsx
     <div className="flex items-center gap-2 rounded-lg bg-amber-500/10 p-2.5 text-xs text-amber-600 dark:text-amber-400 border border-amber-500/20">
       <AlertTriangleIcon className="h-4 w-4 shrink-0" />
       <span>
         Notice: Full quantity cannot be reserved because shortage is {selectedOrderForAction.totalShortage} packets.
       </span>
     </div>
     ```
     This container has zero `role="status"` or `aria-live`. Screen readers are unaware of the shortage warning.
  2. **Payment Form Validation Errors (`payments-page.tsx:856`)**:
     When payment submission fails validation or API returns an error:
     ```tsx
     {paymentError && (
       <div className="flex items-center gap-2 rounded-lg bg-destructive/10 p-3 text-xs text-destructive">
         <AlertTriangleIcon className="h-4 w-4 shrink-0" />
         <span>{paymentError}</span>
       </div>
     )}
     ```
     Rendered in a generic `<div>` without `role="alert"` or `aria-live="assertive"`.
- **DELTA**:
  Dynamic warning and error states appear visually on screen but produce zero screen reader announcements.

---

## 2. Impact

- **Who is hurt**: Screen reader users and blind operators reviewing order approvals and recording payments.
- **Operational consequence**: An operator might unknowingly approve an order with massive stock shortages because the warning banner was never announced by assistive technology.

---

## 3. Repro Steps & Root Cause

### Repro Steps
1. Navigate to `/orders` and select an order with known shortage for approval.
2. Inspect the amber shortage warning container in DOM -> note absence of `role="status"` or `aria-live`.
3. In Chrome DevTools Accessibility pane, verify the node is a plain `generic` element with no live region properties.

### Root Cause
Authoring custom alert containers with ad hoc CSS rather than utilizing the standard `@/components/ui/alert` primitive (which correctly includes `role="alert"`).

---

## 4. Recommended Fix & Regression Test

### Recommended Fix
Replace raw `<div>` alert containers with the established `Alert` component from `@/components/ui/alert.tsx`:
```tsx
<Alert variant="warning" role="status" aria-live="polite">
  <AlertTriangleIcon className="h-4 w-4" aria-hidden="true" />
  <span>Notice: Full quantity cannot be reserved...</span>
</Alert>
```

### Regression Test
In Playwright, trigger shortage banner or error: assert `container.getAttribute('role') === 'status' || container.getAttribute('aria-live') !== null`.
