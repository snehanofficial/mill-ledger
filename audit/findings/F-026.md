# Finding F-026: CSV Formula Injection (Formula Injection) in Export Reports

**ID**: F-026  
**Title**: Unsanitized user inputs exported to CSV files allow formula injection in spreadsheet viewers  
**Severity**: P1  
**Category**: Injection / Data Export  
**Standard Refs**: OWASP Top 10:2021 A03:2021 (Injection), OWASP API Security Top 10:2023 API3:2023 (Broken Object Property Level Authorization), OWASP ASVS v4.0.3 Section 5.1.4 (Verify that structured data is strongly typed and validated), CWE-1236 (Improper Neutralization of Formula Elements in a CSV File)  

---

## Expected (Source)
Source: OWASP CSV Injection Prevention Cheat Sheet & ASVS v4.0.3 Sec 5.1.4.
When exporting user-controlled tabular data to CSV or TSV format, any cell value beginning with formula trigger characters (`=`, `+`, `-`, `@`, `0x09` tab, `0x0D` carriage return) must be neutralized (e.g. prepended with an apostrophe `'`, sanitized, or space-prefixed) so spreadsheet applications like Microsoft Excel, LibreOffice Calc, or Google Sheets treat the content as literal text rather than executable macro formulas or dynamic DDE expressions.

## Actual (Evidence Links)
Evidence: Executed [/audit/scripts/verify-csv-injection.ts](file:///home/snehan/projects/web/mill-ledger/audit/scripts/verify-csv-injection.ts).

In [server/src/modules/reporting/reporting.service.ts:974-982](file:///home/snehan/projects/web/mill-ledger/server/src/modules/reporting/reporting.service.ts#L974-L982):
```typescript
    for (const r of rows) {
      const line = headers.map((h) => {
        const val = r[h];
        if (val === null || val === undefined) return '""';
        const str = String(val).replace(/"/g, '""');
        return `"${str}"`;
      });
      csvLines.push(line.join(","));
    }
```
The routine only escapes double quotes (`"` -> `""`) and wraps values in quotes. Cells starting with `=cmd|' /C calc'!A0`, `@SUM(1,2)`, or `+2+5+cmd|...` are emitted verbatim into the CSV payload as `"=cmd|' /C calc'!A0"`. When opened by users in Microsoft Excel or LibreOffice, the spreadsheet parser strips outer quotes and executes the expression.

---

## Delta
The CSV exporter lacks formula character neutralization. User-supplied fields (customer names, order notes, product descriptions, batch numbers) containing formula prefixes are passed directly into exported files.

---

## Impact
- **Financial & Operational Users**: Accountants and Owners downloading monthly sales registers, GST summaries, or collections reports into Microsoft Excel can suffer remote command execution, data exfiltration via DDE/HYPERLINK, or credential harvesting.
- **Data Integrity**: Excel formulas can modify adjacent numerical totals silently upon file opening.

## Root Cause
[server/src/modules/reporting/reporting.service.ts:978](file:///home/snehan/projects/web/mill-ledger/server/src/modules/reporting/reporting.service.ts#L978):
The string transformation does not test for leading formula characters (`^[=+\-@\t\r]`) to prepend a single apostrophe `'`.

---

## Recommended Fix (Do Not Apply)
In `reporting.service.ts:exportToCSV`, sanitize each cell value before wrapping:
```typescript
let str = String(val).replace(/"/g, '""');
if (/^[=+\-@\t\r]/.test(str)) {
  str = `'${str}`;
}
return `"${str}"`;
```
