# F-061: Redundant Duplicate Skip Links in App Shell Header and Layout

- **ID**: F-061
- **Title**: Redundant Duplicate Skip Links in App Shell Header and Layout
- **Severity**: P3
- **Category**: Accessibility / Keyboard Navigation / Redundant Focus Stops
- **Standard refs**: WCAG 2.2 SC 2.4.1 (Bypass Blocks - Level A), SC 2.4.3 (Focus Order - Level A)

---

## 1. Expected vs Actual

- **EXPECTED (WCAG 2.2 SC 2.4.1, 2.4.3 Level A)**:
  A bypass mechanism (skip link) must provide a direct, single keyboard tab stop at the start of the document allowing keyboard users to jump directly to the primary main content landmark without stepping through redundant identical links.
- **ACTUAL (evidence: `client/src/components/shell/authenticated-shell.tsx:845-852`, `client/src/components/shell/authenticated-shell.tsx:1079-1089`)**:
  `authenticated-shell.tsx` renders **two duplicate skip links** with identical `href="#main-content"`:
  1. The first skip link is rendered at line 1079, immediately inside `<SidebarProvider>`:
     ```tsx
     {/* Line 1079 */}
     <a
       href="#main-content"
       className="sr-only focus:not-sr-only focus:fixed focus:left-4 focus:top-4 ..."
     >
       Skip to main content
     </a>
     ```
  2. The second skip link is rendered at line 845 inside `<header className="sticky top-0 ...">` (`HeaderBar` component):
     ```tsx
     {/* Line 845 */}
     <a
       href="#main-content"
       className="sr-only focus:not-sr-only focus:fixed focus:top-3 focus:left-4 ..."
     >
       {language === "ta" ? "முதன்மை பகுதிக்குச் செல்லவும்" : "Skip to main content"}
     </a>
     ```
  When a keyboard user tabs from the top of an authenticated page, they encounter two identical "Skip to main content" controls in sequence.
- **DELTA**:
  Unnecessary duplicate tab stops for keyboard and screen reader users targeting the identical `#main-content` anchor.

---

## 2. Impact

- **Who is hurt**: Keyboard-only users and screen reader users.
- **Operational consequence**: Redundant cognitive load and repeated tab presses on every page navigation.

---

## 3. Repro Steps & Root Cause

### Repro Steps
1. Navigate to `/dashboard` as an authenticated user.
2. Press Tab once: first "Skip to main content" button appears.
3. Press Tab again: a second, virtually identical "Skip to main content" button appears.

### Root Cause
A skip link was added to the top-level shell wrapper and subsequently duplicated inside the sticky `HeaderBar` subcomponent during layout refactoring.

---

## 4. Recommended Fix & Regression Test

### Recommended Fix
Remove the second redundant skip link in `HeaderBar` (`authenticated-shell.tsx:845-852`), consolidating all skip-to-content logic into the top-level link at line 1079 (and ensuring it includes Tamil localization via `useLanguage`).

### Regression Test
In Playwright, query `document.querySelectorAll('a[href="#main-content"]')`: assert `length === 1`.
