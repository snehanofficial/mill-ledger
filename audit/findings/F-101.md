# F-101: Benchmark Seed Script Executes Unchecked in Production Without Environment Guard

- **ID**: F-101
- **Title**: Benchmark Seed Script Executes Unchecked in Production Without Environment Guard
- **Severity**: P0
- **Category**: Operations & Database Integrity
- **Standard Refs**:
  - OWASP ASVS v4.0.3 Req 1.14.1 (Verify that test, demo, and development data cannot be seeded into production)
  - ISO/IEC 27001:2022 Control 8.31 (Separation of development, test and production environments)

---

## Expected (Source)
- **Source**: Master Rulebook and Operational Baseline:
  - Database seed scripts containing fixture data, demo organizations, and hardcoded test users with well-known passwords must strictly refuse execution when `NODE_ENV === "production"`.
  - Accidental execution of `pnpm db:seed` in a production environment must fail immediately with a fatal exit code unless an explicit override flag is supplied.

---

## Actual (Evidence Links)
1. **Zero Production Environment Guard**:
   - [`server/prisma/seed.ts:600-615`](file:///home/snehan/projects/web/mill-ledger/server/prisma/seed.ts#L600-L615):
     ```typescript
     if (
       process.argv[1]?.endsWith("seed.ts") ||
       process.argv[1]?.endsWith("seed.js")
     ) {
       runFullSeed()
         .then(async () => {
           await prisma.$disconnect();
           process.exit(0);
         })
         .catch(async (error) => {
           console.error("Failed to seed database:", error);
           await prisma.$disconnect();
           process.exit(1);
         });
     }
     ```
   - Neither `seed.ts` nor `src/db/seed.ts` inspects `process.env.NODE_ENV`.
2. **Execution Under `NODE_ENV=production`** (`audit/evidence/config-boot-results.json`):
   - Command run:
     ```bash
     NODE_ENV=production DATABASE_URL="..." BETTER_AUTH_SECRET="..." CORS_ORIGIN="..." pnpm --filter @mill-ledger/server exec tsx prisma/seed.ts
     ```
   - **Result**: Exit code `0`. Raw output:
     ```
     Seeding test users for M1...
     Seeding benchmark master data and opening stock (M2)...
     M2 benchmark master data seed successfully completed.
     ```
   - The script successfully executed in production mode, upserting test users with known credentials (`AdminPassword123!`, `SalesmanPassword123!`), overwriting tax rates, product pricing, and inventory ledger records.

---

## Delta
- The database seed script completely lacks a `NODE_ENV === "production"` protection gate, allowing catastrophic overwriting of live business data.

---

## Impact
- **Total Compromise & Data Corruption (P0)**:
  - Creates 8 hardcoded accounts with known passwords in production (e.g. `admin@millledger.local` with `AdminPassword123!`), granting immediate root administrative access to any attacker.
  - Overwrites live product catalog prices (e.g. resets prices to ₹50.00), tax rates, and customer records with demo mock data.

---

## Repro Steps
1. In a terminal, run:
   ```bash
   NODE_ENV=production DATABASE_URL="postgresql://postgres:postgres@localhost:5432/mill_ledger_audit_throwaway?schema=public" BETTER_AUTH_SECRET="thirty-two-character-valid-production-secret!" CORS_ORIGIN="https://mill.example.com" pnpm --filter @mill-ledger/server exec tsx prisma/seed.ts
   ```
2. Observe script exits with code 0 and logs successful completion without any warning or prompt.

---

## Root Cause
- Missing guard clause at the entry point of `server/prisma/seed.ts` and `server/src/db/seed.ts`.

---

## Recommended Fix
- Insert an immediate fail-loud guard clause at the beginning of `runFullSeed()`:
  ```typescript
  if (process.env.NODE_ENV === "production" && process.env.ALLOW_PRODUCTION_SEED !== "true") {
    console.error("FATAL: Database seed script cannot be run in production environment (NODE_ENV=production). Set ALLOW_PRODUCTION_SEED=true to override.");
    process.exit(1);
  }
  ```
