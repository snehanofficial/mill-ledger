# Finding F-005: Unused Redundant Dependency `cn` in Client Workspace

**ID**: F-005  
**Title**: Unused dependency `cn@^0.5.2` installed in client package.json alongside `clsx` and `tailwind-merge`  
**Severity**: P3  
**Category**: Dependency Hygiene / Dead Code  
**Standard Refs**: MLD Architecture Guidelines (Package boundaries and dependency hygiene)  
**Status**: OPEN  

---

### Expected (source)
`client/package.json` should contain only dependencies that are actively required and imported by the frontend bundle.

### Actual (evidence links)
- `client/package.json` line 23 lists `"cn": "^0.5.2"`.
- Grep across the entire client codebase found 0 imports of `from "cn"`.
- `client/src/lib/utils.ts` implements `cn` locally using `clsx` and `tailwind-merge`:
  ```ts
  import { clsx, type ClassValue } from "clsx";
  import { twMerge } from "tailwind-merge";
  export function cn(...inputs: ClassValue[]) {
    return twMerge(clsx(inputs));
  }
  ```
- Evidence inventory: [audit/evidence/dependencies-table.md](file:///home/snehan/projects/web/mill-ledger/audit/evidence/dependencies-table.md)

### Delta
Package `cn` is installed as a production dependency but is completely unused.

### Impact
Adds 394 kB of unneeded unpacked bytes to node_modules and presents unnecessary supply chain surface area.

### Repro Steps
1. Grep for `from "cn"` or `from 'cn'` in `client/src/`.
2. 0 occurrences found.

### Root Cause
File: [client/package.json](file:///home/snehan/projects/web/mill-ledger/client/package.json#L23)
Installed during scaffold/vibe coding under the mistaken assumption that shadcn's `cn` utility required a package named `cn`.

### Recommended Fix (DO NOT APPLY - AUDIT ONLY)
Remove `"cn": "^0.5.2"` from `client/package.json` and run `pnpm install`.
