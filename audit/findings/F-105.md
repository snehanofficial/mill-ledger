# F-105: Missing Production Runbooks (Deploy, Rollback, Restore, Secret Rotation, Super Admin) and Absence of Comprehensive Data Dictionary

- **ID**: F-105
- **Title**: Missing Production Runbooks (Deploy, Rollback, Restore, Secret Rotation, Super Admin) and Absence of Comprehensive Data Dictionary
- **Severity**: P2
- **Category**: Operations & Documentation Hygiene
- **Standard Refs**:
  - ISO/IEC 27001:2022 Control 8.1 (User endpoint devices and standard operating procedures)
  - ITIL 4 Service Management (Service Operations & Incident Response Runbooks)
  - IEEE 1063-2001 (Standard for Software User Documentation)

---

## Expected (Source)
- **Source**: Master Rulebook Requirements (Section 7):
  - Standard Operating Procedures (Runbooks) must exist for:
    1. Production Deployment
    2. Rollback
    3. Database Restore / Disaster Recovery
    4. Secret Rotation (Better Auth secrets, DB credentials)
    5. Emergency Super Admin User Creation
  - A comprehensive Data Dictionary must document all database models, column data types, constraints, nullability, and business definitions.

---

## Actual (Evidence Links)
1. **Total Absence of Runbooks**:
   - Searching repository: `git grep -in "runbook" docs/` returns 0 results.
   - There are no runbooks in `docs/` or anywhere in the workspace for:
     - Deploying container updates to staging/production.
     - Rolling back a failed deployment or bad Prisma migration.
     - Performing a disaster recovery database restoration.
     - Rotating `BETTER_AUTH_SECRET` without invalidating legitimate active sessions or handling secret rollover.
     - Provisioning an emergency super-admin user if all credentials are lost.
2. **Missing Comprehensive Data Dictionary**:
   - [`docs/data-model.md`](file:///home/snehan/projects/web/mill-ledger/docs/data-model.md) contains only high-level conceptual bullet points of entity groups (e.g. "customers and customer addresses/tax registrations").
   - There is no field-by-field, column-by-column Data Dictionary specifying:
     - Column data types and precisions (e.g. `NUMERIC(18,6)` vs `Double`)
     - Nullability and default expressions
     - Foreign key cascades and check constraints (`chk_current_stock_non_negative`)
     - Business definitions for the 39 tables and 11 enums present in `schema.prisma`.

---

## Delta
- Operational runbooks for incident handling, maintenance, and secret rotation do not exist. Technical data documentation lacks a column-level data dictionary.

---

## Impact
- **Operational Panic During Incidents**: During production outages, data corruptions, or credential compromises, on-call engineers lack documented, verified steps to restore data, execute rollbacks, or rotate credentials without causing cascading downtime.
- **Compliance & Onboarding Friction**: Auditing teams and new developers cannot determine field-level semantics and constraints without reading raw Prisma schema and migration SQL files.
