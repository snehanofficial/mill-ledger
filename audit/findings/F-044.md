# F-044: Touch Targets Below Minimum 44x44px Across Mobile Viewports

- **ID**: F-044
- **Title**: Touch Targets Below Minimum 44x44px Across Mobile Viewports
- **Severity**: P2
- **Category**: Accessibility / Mobile UX
- **Standard refs**: WCAG 2.2 SC 2.5.8 (Target Size (Minimum) - Level AA), Apple HIG adapted (Minimum 44x44 px touch targets), Phase 7 Specification Check 3

---

## 1. Expected vs Actual

- **EXPECTED (Apple HIG adapted, WCAG 2.2 SC 2.5.8, UI-UX-Spec)**:
  On touch devices (320px, 390px, and 768px tablet viewports), all primary interactive elements (buttons, form inputs, icon buttons, language toggles, table action buttons) must maintain a minimum bounding box of 44x44 px (or at minimum 24x24 px with adequate spacing per WCAG 2.2 AA) to prevent mis-taps during one-handed field operations or dusty shop floor use.
- **ACTUAL (evidence: `audit/evidence/screenshots-index.json`, `client/src/components/ui/button.tsx:32-44`, `client/src/components/shell/authenticated-shell.tsx:878-890`)**:
  Automated viewport bounding box analysis across all 212 mobile screenshots (320px viewport) revealed that **100% of routes contain interactive elements smaller than 44x44 px**:
  - Language toggle button in sticky header: `h-8 px-2` (32px height x 36px width).
  - Search trigger icon in header: `size-8` (32px x 32px).
  - Avatar dropdown trigger: `size-8` (32px x 32px).
  - Table inline action buttons (e.g. "Approve", "Reject", "View"): styled with `size="sm"` (`h-8 px-3 text-xs`, 32px height).
  - Filter tabs and badge pills: 24px–28px height.
- **DELTA**:
  Essential primary controls on phones measure 32px or smaller, violating the Apple HIG 44x44 px standard and creating tap fatigue and mis-taps on mobile viewports.

---

## 2. Impact

- **Who is hurt**: Delivery drivers, mill floor workers wearing industrial gloves, and field salesmen operating mobile phones with one hand.
- **Operational consequence**: Tapping adjacent action buttons (e.g. accidentally clicking "Reject" instead of "Approve" on an order, or mis-tapping the language toggle when aiming for search), causing frustration and erroneous order state transitions.

---

## 3. Repro Steps & Root Cause

### Repro Steps
1. Open Chrome DevTools with device emulation set to 320x640 (e.g. iPhone SE).
2. Navigate to `http://127.0.0.1:4173/orders`.
3. Inspect the header buttons: language switch button height is `32px`, avatar icon is `32px`.
4. Inspect the table action buttons: "Approve" button height is `32px` (`h-8`).
5. Attempt to tap the button using finger touch emulation; observe adjacent tap overlaps.

### Root Cause
1. `client/src/components/ui/button.tsx` defines default `sm` variant as `h-8 px-3 text-xs` (32px), and header/page components consistently assign `size="sm"` to primary mobile controls without responsive padding overrides (`md:h-8 h-11`).

---

## 4. Recommended Fix & Regression Test

### Recommended Fix (Do Not Apply - Audit Only)
1. Add responsive minimum touch targets in Tailwind classes for mobile viewports: e.g. `min-h-[44px] min-w-[44px]` or use `aria-label` buttons with transparent hit-area padding extensions (`p-2 -m-2`).
2. Ensure header icon buttons on `<md` screens reserve `size-11` (44x44 px).

### Regression Test to Add
- Add Playwright spec `tests/touch-targets.spec.ts` asserting:
  - At viewport `390x844`, all visible `<button>` elements have `getBoundingClientRect().height >= 44 && getBoundingClientRect().width >= 44`.
