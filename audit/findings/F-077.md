# F-077: Offline Stale Price Acceptance Without Server-Side Price List Revalidation

- **ID**: F-077

- **Severity**: P2
- **Category**: Offline Sync / Data Integrity & Financial Risk
- **Standard Refs**:

## Expected (Source)
- **Source**: `audit/01-expected-spec.md` (REQ-006, REQ-024, REQ-051).
- Offline-created sales orders must be revalidated against server statutory and master data upon synchronization. If a price list or SKU price changed on the server while the device was offline, the server must either flag a price revision conflict for administrative review or re-price the order according to current effective price lists.

## Delta
Because `createSalesOrder` blindly accepts any `line.unitPrice` supplied in the request body without checking the customer's currently active price list or verifying that the price matches the server's current tariff, stale prices stored in offline IndexedDB become binding submitted orders upon sync. If the mill owner raised the price of Murukku from ₹45 to ₹55, any salesman who cached data prior to the price hike can submit orders at ₹45 indefinitely.

---

## Impact
- **Who is hurt**: Mill owner and finance department.
- **How**: Margin erosion and revenue loss from honoring obsolete prices quoted from out-of-date device caches.

---

## Repro Steps
1. Salesman logs into app and synchronizes products (e.g. Murukku 200g @ ₹45).
2. Mill admin updates price list in database: Murukku 200g is now ₹55.
3. Salesman books offline order using cached ₹45 price.
4. Salesman reconnects and syncs outbox.
5. Server posts the sales order with `lineTotal` calculated at ₹45 without error or warning.

---

## Root Cause
- File: [`server/src/modules/sales/sales.service.ts`](file:///home/snehan/projects/web/mill-ledger/server/src/modules/sales/sales.service.ts#L215-L225)
  - Missing server-side price discrepancy check between `line.unitPrice` and `customerPriceList.lines`.

---

## Recommended Fix (Do Not Apply)
1. In `createSalesOrder`, fetch the customer's effective price tier.
2. Compare `line.unitPrice` with `effectivePrice`.
3. If `Math.abs(line.unitPrice - effectivePrice) > 0.01`:
   - Either reject with HTTP 409 `PRICE_MISMATCH`, or
   - Accept order into `UNDER_REVIEW` state with `overrideReason: "Offline order price mismatch: quoted ₹X vs current ₹Y"`.
