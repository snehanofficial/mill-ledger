# F-103: Total Absence of Observability: Unstructured Console Logging, Zero Source Maps, No Error Tracking, No Metrics, and Missing Alert Rules

- **ID**: F-103
- **Title**: Total Absence of Observability: Unstructured Console Logging, Zero Source Maps, No Error Tracking, No Metrics, and Missing Alert Rules
- **Severity**: P2
- **Category**: Observability & Monitoring
- **Standard Refs**:
  - OWASP Top 10:2021 A09:2021 (Security Logging and Monitoring Failures)
  - Google SRE Handbook (Monitoring Distributed Systems)
  - OpenTelemetry Standards for HTTP Services

---

## Expected (Source)
- **Source**: `docs/architecture.md:36` ("Logging: Structured Pino-style logging") & Production Standards:
  - Backend must emit structured JSON logs with correlation IDs (`req.id` / `trace_id`), timestamps, HTTP method, status codes, and duration.
  - Client and server production builds must emit source maps for APM/error trackers (e.g. Sentry/Datadog) to enable meaningful stack trace symbolication.
  - Metrics for latency, error rate, and database connection pool saturation must be collected and exposed (e.g. Prometheus `/metrics`).
  - Alert definitions for high error rates, database connection exhaustion, and latency spikes must be specified.

---

## Actual (Evidence Links)
1. **Unstructured Console Logging**:
   - `docs/architecture.md:36` claimed "Structured Pino-style logging".
   - Fact: Neither `pino`, `winston`, nor `bunyan` is installed in `server/package.json` (`audit/evidence/observability-inventory.json`).
   - The entire backend contains 34 raw `console.log` and `console.error` statements without timestamps, structured JSON fields, or correlation IDs.
2. **Zero Source Maps in Production Builds**:
   - Client: [`client/vite.config.ts:65`](file:///home/snehan/projects/web/mill-ledger/client/vite.config.ts#L65) does not enable `sourcemap: true`. `client/dist/assets/` contains **0** `.map` files.
   - Server: [`server/tsconfig.json:8`](file:///home/snehan/projects/web/mill-ledger/server/tsconfig.json#L8) does not enable `"sourceMap": true`. `server/dist/` contains **0** `.map` files.
   - When runtime exceptions occur, stack traces cite minified/transpiled JS line numbers without mapping to the original TypeScript source lines.
3. **No Centralized Error Tracking**:
   - Neither Sentry, Bugsnag, Datadog RUM, nor Rollbar is configured on the client or server.
   - Client code has **0** React Error Boundaries (`audit/evidence/observability-inventory.json`), meaning any unhandled UI render error causes a blank white screen.
4. **No Metrics and No Alert Definitions**:
   - No Prometheus client (`prom-client`) is installed; no `/metrics` route exists.
   - Latency, error rates, and DB pool utilization are completely unmonitored.
   - Zero alerting rules or dashboard definitions exist in the repository.

---

## Delta
- Observability is entirely non-existent beyond raw stdout `console.log` statements. Source maps, structured loggers, error reporting services, metrics scrapers, and alert rules are missing.

---

## Impact
- **Blind Production Operations**: SRE and engineering teams will have zero visibility into error rates, latency regressions, or database connection pool starvation until users report outages.
- **Prolonged MTTR (Mean Time to Resolution)**: Without source maps and structured logs with correlation IDs, debugging production incidents in minified builds will be slow and error-prone.

---

## Repro Steps
1. Run `pnpm --filter @mill-ledger/server exec tsx ../audit/scripts/verify-observability-inventory.ts`.
2. Inspect `audit/evidence/observability-inventory.json`.
3. Check `client/dist/assets/` and `server/dist/` for `.map` files.

---

## Root Cause
- Architecture document claimed "Structured Pino-style logging" during design phase, but implementation used raw `console.log` and omitted APM integrations.

---

## Recommended Fix
1. Install `pino` and `pino-http` in `server/package.json`; configure JSON formatting with request ID tracing middleware.
2. Enable `build: { sourcemap: "hidden" }` in `client/vite.config.ts` and `"sourceMap": true` in `server/tsconfig.json` for uploading to an APM.
3. Wrap root React app with a top-level `ErrorBoundary` fallback UI component.
4. Install `prom-client` to expose standard Node.js and HTTP metrics on `/metrics`.
