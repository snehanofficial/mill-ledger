# F-051: Missing Accessible Name and APG Dialog Semantics on Core Modal Overlays

- **ID**: F-051
- **Title**: Missing Accessible Name and APG Dialog Semantics on Core Modal Overlays
- **Severity**: P1
- **Category**: Accessibility / Assistive Technology / Keyboard Navigation
- **Standard refs**: WCAG 2.2 SC 1.3.1 (Info and Relationships - Level A), SC 2.1.2 (No Keyboard Trap - Level A), SC 2.4.3 (Focus Order - Level A), SC 4.1.2 (Name, Role, Value - Level A), WAI-ARIA Authoring Practices Guide (APG) Dialog (Modal) Pattern

---

## 1. Expected vs Actual

- **EXPECTED (WAI-ARIA APG Dialog Pattern, WCAG 2.2 SC 1.3.1, 2.1.2, 4.1.2)**:
  1. Modal dialogs must expose `role="dialog"` or `role="alertdialog"` and `aria-modal="true"`.
  2. The dialog must be labelled by its header title via `aria-labelledby` or `aria-label`.
  3. Upon opening, keyboard focus must be trapped within the dialog container (tabbing must cycle exclusively between interactive elements inside the modal).
  4. Pressing the `Escape` key must dismiss the modal and restore focus to the triggering element.
- **ACTUAL (evidence: `client/src/pages/orders-page.tsx:792-800`, `client/src/pages/invoices-page.tsx:355, 532`, `client/src/pages/production-page.tsx:497, 757`, `client/src/pages/payments-page.tsx:665, 833`, `client/src/pages/purchases-page.tsx:313`, `client/src/pages/dispatch-page.tsx:409`, `audit/evidence/a11y/snapshots/raw_modal_verification.json`)**:
  Ten operational modal workflows across the application bypass the established `@/components/ui/dialog` (Radix UI) component and instead render custom raw `<div>` overlays:
  ```tsx
  {showNewOrderModal && (
    <div className="fixed inset-0 z-50 flex items-center justify-center bg-black/50 p-4">
      <div className="max-h-[90vh] w-full max-w-lg overflow-y-auto rounded-xl bg-card p-6 shadow-xl border">
  ```
  Executable verification (`raw_modal_verification.json`) demonstrated:
  - `modalRole`: `null` (assistive tech treats the overlay as a generic division).
  - `modalAriaModal`: `null`.
  - `activeElementInsideModal`: `false` (focus remains on the background trigger button outside the modal).
  - `dismissedOnEscape`: `false` (pressing Escape does nothing).
  - `focusEscapesModalOnTab`: `true` (tabbing moves focus out into background table links behind the dark backdrop).
- **DELTA**:
  Zero dialog semantics, zero focus trap, no Escape dismissal, and focus leak on 10 critical operational screens.

---

## 2. Impact

- **Who is hurt**: Screen reader users, keyboard-only operators, and low-vision users.
- **Operational consequence**: Blind users have no indication that a modal has opened. Keyboard users cannot close the dialog with Escape and easily tab outside the modal into obscured page controls, triggering accidental background actions.

---

## 3. Repro Steps & Root Cause

### Repro Steps
1. Navigate to `http://localhost:4173/orders` as salesman or admin.
2. Press Tab until the "New sales order" button is focused; press Enter.
3. Observe the modal appears. Check `document.activeElement` -> focus is still on the "New sales order" button.
4. Press `Escape` -> modal remains open.
5. Press `Tab` repeatedly -> focus moves to the underlying sidebar and table rows behind the backdrop.

### Root Cause
Direct use of raw `<div>` with Tailwind classes (`fixed inset-0 z-50`) instead of importing and composing the Radix UI Dialog primitive (`@/components/ui/dialog`) which automatically handles ARIA roles, focus traps, Escape dismissal, and focus restoration.

---

## 4. Recommended Fix & Regression Test

### Recommended Fix
Refactor all 10 custom modal instances to use the existing `Dialog`, `DialogContent`, `DialogHeader`, `DialogTitle`, and `DialogDescription` components from `@/components/ui/dialog.tsx`:
```tsx
<Dialog open={showNewOrderModal} onOpenChange={setShowNewOrderModal}>
  <DialogContent>
    <DialogHeader>
      <DialogTitle>Create new sales order</DialogTitle>
    </DialogHeader>
    {/* Form contents */}
  </DialogContent>
</Dialog>
```

### Regression Test
Run `audit/scripts/verify-modal-a11y.ts` in Playwright: assert `modalRole === "dialog"`, `modalAriaModal === "true"`, `dismissedOnEscape === true`, and `focusEscapesModalOnTab === false`.
