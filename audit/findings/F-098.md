# F-098: Documentation Drift and False Claims: "Modular Monolog" Typo, False API Port, and Overstated Deliverables in README

- **Title**: Documentation Drift and False Claims: "Modular Monolog" Typo, False API Port, and Overstated Deliverables in README

- **Category**: Documentation Hygiene & Integrity

## Expected (Source)
- **Source**: `README.md` and Project Authority Specifications:
  - Technical documentation must accurately describe runtime port configurations, architecture, and delivered features.
  - Claims regarding workflow completion, master data management, and report availability must match reality.

---

## Actual (Evidence Links)
1. **Typo in Architecture Description**:
   - [`README.md:7`](file:///home/snehan/projects/web/mill-ledger/README.md#L7):
     > "The application is built as a TypeScript **modular monolog** with React 19 and Vite 6 on the client..."
     The term "modular monolog" is an embarrassing typographical corruption of "modular monolith".
2. **False Backend API Port Claim**:
   - [`README.md:40`](file:///home/snehan/projects/web/mill-ledger/README.md#L40):
     > "The frontend runs at `http://localhost:5173` and the backend API runs at `http://localhost:3000`."
     **Fact**: The backend default port is `4000` (`server/src/config/env.ts:13: PORT: z.coerce.number().default(4000)` and `server/.env:2`). Furthermore, Vite's proxy ([`client/vite.config.ts:60`](file:///home/snehan/projects/web/mill-ledger/client/vite.config.ts#L60)) proxies `/api` requests to `http://localhost:4000`. Running client against port 3000 fails immediately with `ECONNREFUSED`.
3. **Overstated Deliverables & False Scope Claims**:
   - **Claim**: `README.md:109` claims full master records for *"suppliers, customers, and BOM recipes"*.  
     **Reality**: As documented in Phase 6 ([`audit/phase-06-features-flows.md`](file:///home/snehan/projects/web/mill-ledger/audit/phase-06-features-flows.md)), suppliers and recipes cannot be created or updated via UI or API. There is zero `POST /api/v1/inventory/suppliers` endpoint; procurement users are restricted to hardcoded seed data in dropdowns.
   - **Claim**: `README.md:112` claims complete *"order to cash workflow: mobile sales order creation, admin stock verification, ATP checking, invoice posting, and dispatch"*.  
     **Reality**: Invoicing has **zero UI affordance** anywhere in the frontend (Finding F-037). An invoice can only be created via backend seed scripts or raw HTTP curl commands.
   - **Claim**: `README.md:121` claims a *"purchase register"* report.  
     **Reality**: No purchase register report exists in the reporting module.
   - **Claim**: `README.md:126` claims *"Full bilingual support toggled on the application shell for floor staff and operators"*.  
     **Reality**: 751 out of 755 user-visible UI strings (99.5%) are completely untranslated English text (Finding F-080). Only navigation buttons switch to Tamil.

---

## Delta
- The README contains factual inaccuracies regarding ports, prominent typos, and claims that features are complete when they are missing essential UI affordances or entire report types.

---

## Impact
- **Developer & Evaluator Onboarding**: A new engineer or evaluator following the README instructions will configure or probe port 3000 and believe the backend is unresponsive.
- **Audit Credibility**: Claiming full bilingual support and order-to-cash workflows when core buttons and translations do not exist undermines trust in the system.

---

## Repro Steps
1. Read `README.md` lines 7, 40, 109, 112, 121, 126.
2. Check `server/src/config/env.ts:13` and `client/vite.config.ts:60` to confirm port 4000.
3. Check `client/src/pages/orders-page.tsx` and observe the lack of any "Generate Invoice" or "Post Invoice" button.

---

## Root Cause
- Documentation was authored during initial ideation and pitch phase and never audited or reconciled against the actual committed implementation.

---

## Recommended Fix
1. Correct typo in `README.md:7`: replace `modular monolog` with `modular monolith`.
2. Correct backend port in `README.md:40`: replace `http://localhost:3000` with `http://localhost:4000`.
3. Reconcile scope claims to honestly reflect current implementation status:
   - Note that invoicing currently requires API or script dispatch.
   - Note that supplier and recipe master management are read-only dropdowns pending UI release.
   - Note that Tamil translation covers shell navigation and outbox status.
