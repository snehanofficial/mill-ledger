# Finding F-063: Width and Height Animated in Sidebar Transition and Collapsible Triggering Reflow

- **ID**: F-063
- **Title**: Width and Height Animated in Sidebar Transition and Radix Collapsible Triggering Layout Reflow
- **Severity**: P2
- **Category**: Performance / CSS Motion
- **Standard Refs**:
  - Web Vitals & Rendering Performance: Avoid animating layout-triggering properties (`width`, `height`, `top`, `left`)
  - NN/g: Animation and Interaction Latency Guidelines
  - Chromium Rendering Architecture: Compositor vs Layout & Paint Pipelines

---

## Expected Behavior
Modern web animation best practices require animating only GPU-composited properties (`transform` and `opacity`) where possible. Transitions on geometric dimensions such as `width`, `height`, `margin`, or `padding` force recalculation of styles, layout reflow of sibling elements, and layer repaints on every frame (up to 60 or 120 times per second), degrading responsiveness and frame rates on low-power devices.

---

## Actual Behavior
1. In `client/src/components/ui/sidebar.tsx:285`:
   ```tsx
   "transition-[width] duration-220 ease-[cubic-bezier(0.2,0,0,1)]",
   "motion-reduce:transition-none shrink-0",
   ```
   Toggling the desktop navigation sidebar animates CSS `width` over 220ms. This forces layout reflow on the adjacent `<main id="main-content">` container and all contained responsive grid items and data tables during every animation frame.
2. In `client/src/index.css:201-213`:
   ```css
   @keyframes collapsible-open {
     from {
       height: 0;
     }
     to {
       height: var(--radix-collapsible-content-height);
     }
   }
   @keyframes collapsible-close {
     from {
       height: var(--radix-collapsible-content-height);
     }
     to {
       height: 0;
     }
   }
   ```
   The Radix collapsible accordion open/close animations directly mutate `height`, forcing vertical reflow and layout thrashing across parent content.
3. Programmatic audit evidence recorded in `audit/evidence/motion/metrics/cls-and-layout-thrashing.json`:
   - `reflowPropertiesAudit` flags both `sidebar.tsx:285` (`width`) and `index.css:201` (`height`) as `causesLayoutReflow: true`.

---

## Delta
Instead of using composited off-screen transforms (`transform: translateX(...)` with `scaleX`) or CSS grid `grid-template-rows: 0fr -> 1fr`, the application animates geometric `width` and `height`, generating avoidable CPU layout recalculation spikes.

---

## Impact
Low-spec warehouse tablets and handheld POS devices experience frame drops, sluggish UI response, and elevated battery consumption during sidebar expansion and collapsible accordion toggles.

---

## Repro Steps
1. Open Chrome DevTools > Performance panel.
2. Start CPU throttling (4x or 6x slowdown).
3. Toggle sidebar or expand collapsible sub-menus.
4. Observe repeated "Layout" and "Recalculate Style" tasks logged during the transition window.

---

## Recommended Fix
1. For Sidebar: Animate `transform: translateX(...)` or composite overlay drawer pattern on small screens, and avoid transitioning width on dense table views.
2. For Collapsible: Transition `grid-template-rows` from `0fr` to `1fr` with child `min-height: 0` to minimize geometry calculations, or use CSS transforms with `clip-path`.
