# Finding F-065: Sonner Toasts Missing `role="status"`, Pause on Focus, and Persistent Retrieval Store

- **ID**: F-065
- **Title**: Sonner Toasts Missing `role="status"`, Pause on Focus, and Persistent Notification Store
- **Severity**: P1
- **Category**: Accessibility / Feedback Patterns
- **Standard Refs**:
  - W3C WCAG 2.2 Success Criterion 4.1.3 Status Messages (Level AA)
  - W3C WCAG 2.2 Success Criterion 2.2.1 Timing Adjustable (Level A)
  - W3C WCAG 2.2 Success Criterion 1.4.13 Content on Hover or Focus (Level AA)
  - Master Rulebook Phase 9 Requirement: "toast with role=status, adequate duration, pause on hover or focus, and a persistent place to find the message again."

---

## Expected Behavior
Per Phase 9 requirements and WCAG 2.2 SC 4.1.3 & SC 2.2.1:
1. Toast notifications must expose `role="status"` or `aria-live="polite"` so screen readers announce background updates without stealing focus.
2. Toast timers must pause when hovered by mouse OR focused by keyboard.
3. System notifications and feedback toasts must be retained in a persistent notifications center/log so users who miss transient toasts (after the default 4-second timeout) can retrieve them.

---

## Actual Behavior
1. In `client/src/components/ui/sonner.tsx:5-30`:
   ```tsx
   function Toaster() {
     return (
       <Sonner
         position="bottom-right"
         visibleToasts={4}
         richColors
         toastOptions={{ ... }}
       />
     );
   }
   ```
   The `Toaster` component does not set explicit `role="status"` or ARIA live region bindings on individual toast items.
2. Programmatic inspection evidence in `audit/evidence/motion/metrics/feedback-patterns-audit.json`:
   - `toasterRole: null`
   - `toastRole: null`
   - `toastAriaLive: null`
   Screen readers do not automatically announce toasts when they pop up.
3. Keyboard pause behavior: Sonner pauses on mouse hover, but does NOT pause dismissal timers when toasts receive keyboard focus. Keyboard users navigating through the page cannot inspect or read long toast messages before they auto-dismiss.
4. Persistent message store: In `client/src/components/shell/authenticated-shell.tsx:1240-1265`, the notifications drawer sheet is hardcoded to an empty state:
   ```tsx
   <Sheet open={notificationsOpen} onOpenChange={setNotificationsOpen}>
     <SheetContent side="right" className="w-80 p-0">
       ...
       <p className="text-sm font-medium text-foreground">No notifications</p>
       <p className="mt-1 text-xs text-muted-foreground">Activity and system events will appear here.</p>
     </SheetContent>
   </Sheet>
   ```
   `toast` calls across orders, purchases, invoices, and outbox sync write directly to transient DOM elements via `sonner`, completely bypassing the notifications drawer. Once a toast dismisses, the message is permanently lost.

---

## Delta
Toasts lack ARIA status announcements, lack keyboard focus pausing, and provide zero persistence in the app's notifications drawer.

---

## Impact
Blind users never hear critical toast feedback (such as "Order rejected" or "Sync failed"). Motor-impaired or slow-reading keyboard users cannot prevent auto-dismissal. Users who look away during a 4-second sync operation have no log or history to verify whether an action succeeded or failed.

---

## Repro Steps
1. Navigate to `/orders`.
2. Submit a new order.
3. Observe the transient toast "Sales order created successfully." appears for 4 seconds at the bottom right.
4. Attempt to focus the toast with `Tab`. The timer does not pause.
5. Click the bell icon in the header to check Notifications.
6. The drawer displays "No notifications. Activity and system events will appear here."

## Recommended Fix
1. Configure `sonner` with `toastOptions={{ ... }}` including `role="status"` and `aria-live="polite"`.
2. Implement a unified notification event bus / Zustand store that records every emitted toast into a persistent history list accessible via the `Notifications` drawer sheet.
3. Ensure keyboard focus into the toast container pauses auto-dismissal.
