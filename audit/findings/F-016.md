# Finding F-016: Ephemeral Packaging Capacity Mismatch Warning with Hardcoded Ratio

**ID**: F-016  
**Title**: Packaging capacity mismatch warning is hardcoded to specific SKU and multiplier, and is never persisted to database  
**Severity**: P2  
**Category**: Business Rules / Production / Auditing  
**Standard Refs**: REQ-019, Benchmark Specification (Item 3), NN/g Heuristic #5 (Error Prevention)  
**Status**: OPEN  

---

### Expected (source)
Under [benchmark.md](file:///home/snehan/projects/web/mill-ledger/docs/benchmark.md), [business-rules.md](file:///home/snehan/projects/web/mill-ledger/docs/business-rules.md), and [product-requirements.md](file:///home/snehan/projects/web/mill-ledger/docs/product-requirements.md) REQ-019:
"When good packets exceed carton packing capacity (e.g. 188 packets vs 9 cartons × 20 pkts/carton = 180 capacity), the system must generate a non-blocking packaging mismatch warning. The conversion factor must resolve from the `unit_conversion` master table, and the warning flag or loose packet discrepancy must be auditable on historical production records."

### Actual (evidence links)
In [production.service.ts:362-370](file:///home/snehan/projects/web/mill-ledger/server/src/modules/production/production.service.ts#L362-L370):
```typescript
if (invItem.sku === "PKG-CARTON" && actualQty > 0) {
  const packetsHeld = actualQty * 20;
  if (packetsHeld < actualGoodQty) {
    warnings.push(
      `${actualQty} cartons represent ${packetsHeld} of ${actualGoodQty} packets.`,
    );
  }
}
```
1. The conversion ratio is hardcoded to `* 20` and the check is hardcoded to `invItem.sku === "PKG-CARTON"`. It ignores `unit_conversion` master table and cannot work for other packaging types (e.g. 10-packs, 50-packs, jars, tins).
2. The warning string is pushed to an in-memory `warnings` array returned only in the immediate API HTTP response body `{ run, warnings }`.
3. In `schema.prisma`, `ProductionRun` has **no column** to persist warnings or loose packet counts. Once the HTTP response is sent, the warning disappears forever.
4. When queried via `getProductionRunById` or viewed in historical production reports, there is no record that a packaging mismatch occurred.
- Verified in `/audit/scripts/verify-production-costing.ts`.

### Delta
Packaging mismatch warnings are completely ephemeral and hardcoded. Historical production audits cannot see that a batch had 8 loose, unboxed packets.

### Impact
Lack of auditable packaging reconciliation. Quality control and inventory auditors cannot determine whether 8 loose packets were stolen, damaged, or stored as unboxed floor stock.

### Repro Steps
1. Post a production run with 188 good packets and 9 cartons.
2. Note warning `"9 cartons represent 180 of 188 packets."` in the HTTP response.
3. Fetch the run from the database via `getProductionRunById(runId)`.
4. Observe the warning is absent from the database record and cannot be retrieved.

### Root Cause
[production.service.ts:362-370](file:///home/snehan/projects/web/mill-ledger/server/src/modules/production/production.service.ts#L362-L370) does not look up `unitConversion` and does not persist warnings to `production_run.notes` or a dedicated warning column.

### Recommended Fix (do not apply)
1. Query `unitConversion` for the active packaging item to product variant UOM.
2. Add a `warnings` JSON or `looseUnits` column to `production_run` table and persist the warning.

### Regression Test to Add
`audit/tests/packaging-mismatch.test.ts` posting a run with 188 packets and 9 cartons, then fetching via `getProductionRunById` and asserting warning is persisted.
