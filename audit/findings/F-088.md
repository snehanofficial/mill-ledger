# F-088: Absence of `noindex` Robots Protection and `X-Robots-Tag` Across Authenticated ERP Routes

- **ID**: F-088
- **Title**: Absence of `noindex` Robots Protection and `X-Robots-Tag` Across Authenticated ERP Routes
- **Severity**: P1
- **Category**: Security Architecture / Search Engine Indexing Protection
- **Standard Refs**:
  - `audit/01-expected-spec.md` REQ-062 ("Application Metadata and Authenticated ERP Page noindex Protection")
  - `Problem_Statement_Winter_Internship_Application_2026.md` Owner Decision 2 ("SEO Scope: Metadata, not public indexing. Keep authenticated ERP pages noindex. Implement descriptive titles, semantic HTML, and relevant metadata throughout the application. Public landing pages may be indexed")

## Expected (Source)
- **Source**: `audit/01-expected-spec.md` (REQ-062) & Formal Owner Decision 2:
  - "Keep authenticated ERP pages `noindex`. Implement descriptive titles, semantic HTML, and relevant metadata throughout the application. Public landing pages may be indexed."
  - In authenticated routes (`/dashboard`, `/orders`, `/stock`, `/invoices`, `/reports/sales`, etc.), the application must deliver either `<meta name="robots" content="noindex, nofollow">` in the document head or an `X-Robots-Tag: noindex, nofollow` HTTP response header to guarantee search engine crawlers do not index internal ERP views, company metrics, or staff workflows.

## Delta
Neither the HTTP response headers (`X-Robots-Tag`) nor the rendered DOM (`<meta name="robots">`) contain `noindex` or `nofollow` directives for any authenticated ERP route.

---

## Impact
- **Who is hurt**: Mill management, employees, and clients.
- **How**: Web crawlers (Google, Bing, Common Crawl, specialized data scrapers) that discover ERP links or shared URLs can crawl and index authenticated application entry points. Furthermore, cache headers do not prevent search engines from storing application snippet shells in public search indices.

## Root Cause
- File: [`client/index.html`](file:///home/snehan/projects/web/mill-ledger/client/index.html#L1-L18) and [`client/src/layouts/authenticated-layout.tsx`](file:///home/snehan/projects/web/mill-ledger/client/src/layouts/authenticated-layout.tsx#L55-L85)
  - No `robots` meta tag was placed in the HTML template, and the authenticated layout does not dynamically set `<meta name="robots" content="noindex, nofollow">`.
- File: [`server/src/app.ts`](file:///home/snehan/projects/web/mill-ledger/server/src/app.ts#L18)
  - Helmet middleware was invoked without the `xXssProtection` / custom header options to emit `X-Robots-Tag: noindex, nofollow`.

---

## Recommended Fix (Do Not Apply)
1. In `client/src/layouts/authenticated-layout.tsx`, add an effect or document head manager:
   ```tsx
   useEffect(() => {
     let meta = document.querySelector('meta[name="robots"]') as HTMLMetaElement | null;
     if (!meta) {
       meta = document.createElement("meta");
       meta.name = "robots";
       document.head.appendChild(meta);
     }
     meta.content = "noindex, nofollow";
   }, []);
   ```
2. In the production web server / reverse proxy (and Express API), configure the response header:
   ```http
   X-Robots-Tag: noindex, nofollow
   ```
