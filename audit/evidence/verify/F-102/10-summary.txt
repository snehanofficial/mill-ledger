F-102 VERIFICATION SUMMARY: READINESS PROBE, TRUST PROXY, & TIMEOUTS
======================================================================
Date: 2026-11-24
Severity: P1 | Tier: T11 | Cluster: CLUSTER-15
Status: VERIFIED-PASS

1. Root Cause:
`GET /api/v1/health` previously reported static uptime without validating database availability.
If PostgreSQL crashed, disconnected, or exhausted its connection pool, the server reported false
200 OK health, causing load balancers to route traffic to failed pods. Furthermore, `/ready` was 404,
`trust proxy` was false (causing X-Forwarded-For headers to be discarded and misattributing client IPs),
request timeouts were unconfigured, and graceful shutdown did not close Prisma connections.

2. Implementation Summary:
- `server/src/modules/health/health.controller.ts`:
  * Implemented `getReadiness()` executing `SELECT 1` probe query via Prisma.
  * Responds with 200 `{ status: "ready", database: "connected" }` when healthy.
  * Responds with 503 `{ status: "unhealthy", database: "disconnected" }` on failure.
- `server/src/modules/health/health.routes.ts`:
  * Mounted `healthRouter.get("/ready", getReadiness)`.
- `server/src/app.ts`:
  * Configured `app.set("trust proxy", 1)` for accurate `req.ip` behind load balancers.
  * Added `requestTimeoutMiddleware(30000)` to abort hung sockets after 30 seconds.
  * Exposed `/ready` and `/api/v1/ready` endpoints.
- `server/src/db/client.ts`:
  * Added `statement_timeout: 10000` (10s) to `pg.Pool` configuration.
- `server/src/index.ts`:
  * Added `await prisma.$disconnect()` during graceful shutdown.
  * Added 10-second forceful exit fallback timer (`unref()`).
