1. Root Cause:
Server mutations in `orders-page.tsx`, `dispatch-page.tsx`, and `settings-page.tsx` lacked
TanStack Query v5 optimistic updates, requiring the UI to await in-flight HTTP responses before
reflecting user intent. On network failures or timeouts, no snapshot rollback mechanisms existed,
violating Master Rulebook Phase 9 requirements.

2. Implementation Summary:
- `client/src/pages/orders-page.tsx`:
  * `approveMutation`: Added `onMutate` to snapshot `["sales-orders"]` query cache, optimistically set
    order status to "APPROVED", and close modal immediately; `onError` rollback to previous snapshot
    with visible error toast; `onSettled` query invalidation for cache coherence.
  * `rejectMutation`: Added `onMutate` to snapshot `["sales-orders"]` query cache, optimistically set
    order status to "REJECTED" with rejection reason; `onError` rollback to previous snapshot with visible
    error toast; `onSettled` query invalidation.
- `client/src/pages/settings-page.tsx`:
  * `toggleUserMutation`: Added `onMutate` to snapshot `["admin-users"]` query cache, optimistically
    toggle `isActive`; `onError` rollback to previous snapshot with visible error toast; `onSettled`
    query invalidation.
- `client/src/pages/dispatch-page.tsx`:
  * `dispatchMutation`: Added `onMutate` to snapshot `["sales-orders"]` and `["dispatches"]` query
    caches, optimistically mark order `fulfilmentStatus: "FULFILLED"`; `onError` rollback to previous
    snapshots with visible error toast; `onSettled` query invalidation.
