=== F-026 Verification: 03 Regression Reproduction ===
Finding Title: Unsanitized user inputs exported to CSV files allow formula injection in spreadsheet viewers
Defect Analysis:
1. Formula Execution in Spreadsheet Viewers:
   When exporting tabular reports to CSV, cells beginning with formula trigger characters (`=`, `+`, `-`, `@`, `0x09` tab, `0x0D` carriage return) were wrapped directly in quotes without neutralizing the leading prefix.
   Applications like Microsoft Excel, LibreOffice Calc, and Google Sheets evaluate such cells as formulas or dynamic DDE expressions upon opening, permitting arbitrary command execution, data exfiltration, or silent modification of financial figures.
2. CWE-1236 & OWASP ASVS 5.1.4 Violation:
   The export routine in `server/src/modules/reporting/reporting.service.ts` only escaped internal double quotes (`" -> ""`):
   ```typescript
   const str = String(val).replace(/"/g, '""');
   return `"${str}"`;
   ```

Fix Applied:
1. Implemented `sanitizeCSVCell(val: unknown): string` method on `ReportingService`:
   ```typescript
   sanitizeCSVCell(val: unknown): string {
     if (val === null || val === undefined) return '""';
     let str = String(val).replace(/"/g, '""');
     if (
       typeof val !== "number" &&
       typeof val !== "boolean" &&
       /^[=+\-@\t\r]/.test(str)
     ) {
       str = `'${str}`;
     }
     return `"${str}"`;
   }
   ```
2. Updated `exportToCSV` in `reporting.service.ts` to transform every header and data row value using `sanitizeCSVCell`.
3. Updated audit script `audit/scripts/verify-csv-injection.ts` and created comprehensive regression test `audit/tests/f-026-regression.spec.ts` verifying all formula trigger characters, number/boolean preservation, and live HTTP endpoint behavior.
