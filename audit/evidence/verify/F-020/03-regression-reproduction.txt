=== F-020 Verification: 03 Regression Reproduction ===
Vulnerability / Defect:
Previously, createSalesOrder accepted arbitrary client-provided `unitPrice` values per line with zero discount bounding or margin controls. A salesman could quote ₹1.00 (a 98% discount against the ₹50.00 list price), causing the order to be immediately submitted without requiring any manager approval or flagging. Furthermore, admin approvals could override unit prices arbitrarily without threshold limits, and draft order updates allowed arbitrary status transitions.

Reproduction Test Suite in server/src/orders.test.ts ("F-020: enforces threshold discount guard and manager approval bounds (OD-07 & REQ-024)"):
1. Salesman quotes unitPrice: 35.0 (30% discount against 50.0 list price) -> Rejected with HTTP 422 DISCOUNT_EXCEEDS_MAX_THRESHOLD.
2. Salesman quotes unitPrice: 48.0 (4% discount, <= 5% discretionary limit) -> Accepted immediately with status SUBMITTED.
3. Salesman quotes unitPrice: 45.0 (10% discount, between 5% and 15%) -> Accepted with status UNDER_REVIEW requiring manager approval.
4. Admin attempts to approve UNDER_REVIEW order without providing `overrideReason` -> Rejected with HTTP 400.
5. Admin approves UNDER_REVIEW order with valid `overrideReason` -> Approved with status APPROVED and recorded overrideReason / approvedByUserId.
6. Admin attempts line override on approval with unitPrice: 35.0 (30% discount) -> Rejected with HTTP 422 DISCOUNT_EXCEEDS_MAX_THRESHOLD.
7. Attempting to update a draft order directly to APPROVED via PUT /orders/:id -> Rejected with HTTP 400 ("Draft orders can only be updated to DRAFT or SUBMITTED status").
