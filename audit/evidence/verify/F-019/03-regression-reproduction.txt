=== F-019 VERIFICATION EVIDENCE 03: REGRESSION REPRODUCTION ===
Target Finding: F-019 (P1)
Title: Direct URL navigation to forbidden routes renders full operational page shells without route-level authorization guards or 403 pages
Standard Refs: OWASP Top 10:2021 A01:2021 (Broken Access Control), NN/g Heuristic #9, WCAG 2.2 SC 3.3.1

[Pre-remediation Defect State]:
1. In client/src/app.tsx and client/src/layouts/authenticated-layout.tsx, all routes under / were wrapped only with authentication verification (checking if user session exists).
2. Zero route-level role checks, role guards, or permission filters existed on any child route (/orders, /invoices, /payments, /dispatch, /stock, /purchases, /production/*, /reports/*, /settings).
3. Directly navigating via browser URL as SALESMAN to /invoices or /payments mounted the full operational page shell and attempted backend API calls, failing with 403 or returning blank cards without rendering an accessible 403 Access Denied barrier.
4. On /orders, both ACCOUNTANT and OWNER saw the "New sales order" / "Create first order" and "Approve/Reject" buttons despite having zero order-creation or approval privileges.
5. On /invoices, non-admin roles saw "Credit note" triggers.
6. On /payments, non-admin roles saw "Record payment" triggers.
7. AuthenticatedLayout and login-page.tsx redirected unconditionally to /dashboard, which is forbidden to non-admin roles (SALESMAN, PRODUCTION, ACCOUNTANT).

[Post-remediation Verification]:
1. Route protection enforced via <RoleGuard allowedRoles={[...]}> wrapping all operational routes in client/src/app.tsx, strictly derived from ROUTE_PERMISSIONS in client/src/lib/role-routing.ts.
2. Direct navigation to forbidden routes immediately renders <ForbiddenPage />, displaying "HTTP 403 Forbidden" status, "Access Denied" heading, role-restriction explanation, and a "Go to workspace" CTA redirecting to the user's role-appropriate home.
3. Added <RoleDefaultRedirect /> so navigating to / or completing login redirects each role to their dedicated operational workspace:
   - SALESMAN: /orders
   - PRODUCTION: /production/today
   - ACCOUNTANT: /invoices
   - ADMIN & OWNER: /dashboard
4. Conditionally guarded action buttons:
   - "New sales order" / "Create first order" on OrdersPage restricted to ADMIN and SALESMAN.
   - "Approve" and "Reject" on OrdersPage restricted to ADMIN.
   - "Credit note" on InvoicesPage restricted to ADMIN.
   - "Record payment" on PaymentsPage restricted to ADMIN.
   - "Record production batch" on ProductionPage restricted to ADMIN and PRODUCTION.
   - "Record dispatch" on DispatchPage restricted to ADMIN.
   - "Record Purchase Receipt" on PurchasesPage restricted to ADMIN and PRODUCTION.
5. AppBrand in AuthenticatedShell dynamically links to getDefaultRouteForRole(user.role), eliminating invalid /dashboard link in sidebar for non-admin roles.
6. MobileBottomNav renders role-appropriate navigation items for each role.
