=== F-030 Verification: 03 Regression Reproduction ===
Finding Title: Order modification endpoint lacks request body schema validation, accepting unvalidated mutations and crashing with HTTP 500 on malformed status values
Defect Analysis:
1. Missing Request Body Schema Validation:
   In server/src/modules/sales/sales.routes.ts, the PUT /orders/:id route handler directly forwarded req.body to salesService.updateDraftOrder without invoking any Zod validation schema.
2. HTTP 500 Crash on Malformed Status / Invalid Types:
   When non-enum or wrong-type values (e.g. { status: 12345 } or { status: "NON_EXISTENT_ENUM_VALUE" }) were supplied, Prisma threw PrismaClientValidationError. The global unhandled exception handler caught this, returning HTTP 500 Internal Server Error and leaking internal database schemas and Node.js call stacks.
3. Parameter Tampering & Mass Assignment:
   Arbitrary unauthorized fields could be posted in the request body without schema rejection.

Fix Applied:
1. Defined strict updateOrderSchema in server/src/modules/sales/sales.routes.ts:
   - status: constrained to z.enum([OrderStatus.DRAFT, OrderStatus.SUBMITTED]) with explicit errorMap.
   - notes: string max 500 characters, nullable.
   - lines: optional valid order lines array.
   - creatorId: optional (parsed but ignored for authorization).
   - .strict(): rejects any unrecognized or injected parameters.
2. Integrated updateOrderSchema.safeParse(req.body) in PUT /orders/:id handler throwing AppError(..., 400).
3. Enforced server-side ownership check before validation so cross-salesman access is rejected with HTTP 403 Forbidden.
4. Refactored salesService.updateDraftOrder to safely handle optional/null notes and typed status.
5. Added comprehensive regression tests in audit/tests/f-030-regression.spec.ts.
