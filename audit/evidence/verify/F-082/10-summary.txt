VERIFICATION SUMMARY: F-082
Title: Corrupt Outbox Queue Entry Head-of-Line Blocking Halts All Subsequent Offline Order Synchronization
Severity: P1 | Tier: T9 | Cluster: CLUSTER-13
================================================================================

1. Root Cause:
   The catch block in `executeSyncLoop` (`client/src/offline/sync-engine.ts`) assumed any
   error where `err.response?.status` was falsy was a transient network error. When an
   outbox record encountered malformed fields (e.g. undefined `items` or missing `customerId`),
   client code threw a `TypeError`. The catch handler caught this internal exception, reset the
   corrupt order to `status: "queued"`, and executed `break`, causing permanent head-of-line
   blocking that blocked all subsequent valid orders indefinitely.

2. Remediation Applied:
   - Added pre-flight structural validation in `client/src/offline/sync-engine.ts` checking for
     presence of `customerId`, `idempotencyKey`, and a non-empty `items` array with valid variant IDs
     and positive numeric quantities. Corrupt records are immediately quarantined into `status: "conflict"`
     with `lastErrorCode: "CLIENT_VALIDATION_ERROR"`, incrementing `conflicts` and continuing (`continue`).
   - Added exception inspection in `catch (err)`: if `err` is an internal JavaScript runtime exception
     (`TypeError`, `ReferenceError`, `SyntaxError`) rather than an HTTP response, it is quarantined to
     `status: "conflict"` with `lastErrorCode: "CLIENT_CORRUPTION_ERROR"` and continues (`continue`).
   - Fixed `processOutbox` check `navigator.onLine === false` to properly handle environments where
     `navigator.onLine` may be undefined without wrongly interpreting it as offline.
