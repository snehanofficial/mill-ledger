======================================================================
F-087 VERIFICATION SUMMARY: PERSISTENT STORAGE REQUEST FOR OUTBOX
======================================================================
Date: 2026-11-24
Severity: P2 | Tier: T9 | Cluster: CLUSTER-13
Status: VERIFIED-PASS

1. Root Cause:
Dexie IndexedDB database was initialized under default browser "best-effort" storage without
requesting persistent storage permission via `navigator.storage.persist()`. Under low-disk pressure
or memory constraints on mobile Android devices, mobile browsers could silently evict local IndexedDB
storage, permanently deleting un-synced offline outbox orders and customer snapshots.

2. Implementation Summary:
- `client/src/offline/db.ts`:
  * Defined and exported `requestPersistentStorage()` using W3C Storage Standard API.
  * Verified `navigator.storage.persisted()` before requesting to avoid redundant prompt invocations.
  * Triggered `requestPersistentStorage()` automatically upon database instantiation in browser environments.
- `client/src/offline/sync-engine.ts`:
  * Invokes `requestPersistentStorage()` when queuing new offline orders (`queueOfflineOrder`).
  * Re-exports `requestPersistentStorage`.
- `client/src/offline/use-offline.ts`:
  * Invokes `requestPersistentStorage()` on mount inside `useSyncManager`.
- `client/src/offline/db.test.ts`:
  * Added unit test coverage for persistent storage requesting, early return when already persisted,
    and graceful degradation when unsupported.
