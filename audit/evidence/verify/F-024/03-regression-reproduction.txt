=== F-024 Verification: 03 Regression Reproduction ===
Finding Title: Better Auth password reset endpoint is unconfigured (returns 404); account lockout is not implemented after repeated authentication failures
Defect Analysis:
1. Missing Password Reset Handler:
   Better Auth disabled the password recovery endpoint because emailAndPassword.sendResetPassword callback was omitted in server/src/lib/auth.ts. Any request to /api/auth/forget-password returned HTTP 404 Not Found.
2. Missing Account Lockout:
   Repeated failed login attempts on a single user identity (e.g. 6 consecutive wrong passwords) returned 401 without locking the account. A subsequent valid login succeeded immediately with HTTP 200, permitting brute-force password stuffing attacks (OWASP Top 10 A07:2021).
3. IP Resolution Warning:
   Rate limiter fell back to a shared per-path bucket due to unconfigured advanced.ipAddress settings.

Fix Applied:
- Implemented LockoutService in server/src/lib/lockout.ts tracking consecutive failed attempts with a 5-attempt threshold and 15-minute temporary lockout duration.
- Created Better Auth plugin (lockoutPlugin) with before/after hooks on /sign-in/email and /reset-password, throwing HTTP 403 Forbidden with ACCOUNT_LOCKED on locked identities and recording audit events upon lock.
- Configured emailAndPassword.sendResetPassword in server/src/lib/auth.ts to enable password reset.
- Mounted express aliases in server/src/app.ts for /api/auth/forget-password and /api/auth/forgot-password forwarding to Better Auth requestPasswordReset.
- Configured advanced.ipAddress with trusted proxies and forwarding headers in Better Auth.
- Fixed audit service organization resolution in server/src/modules/reporting/audit.service.ts.
- Verified with regression suite server/src/auth-lockout.test.ts.
