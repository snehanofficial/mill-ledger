=== STEP 9: STANDARDS CHECK FOR F-007 ===
Finding: F-007
Category: Data Integrity / Concurrency / Inventory Ledger
Standards Refs: ACID Consistency & Isolation, OWASP API Security Top 10:2023 API10:2023, REQ-027

1. Applicable Standards:
   - ACID Consistency and Isolation:
     Under PostgreSQL's default `READ COMMITTED` transaction isolation, concurrent transactions reading uncommitted state without row locks perform interleaved check-then-act operations. Row-level exclusive locking via `SELECT ... FOR UPDATE` serializes concurrent transactions at the database engine level, guaranteeing serializability of ATP stock evaluations and reservation writes.
   - Resource Ordering & Deadlock Freedom (Dijkstra):
     Acquiring multi-row exclusive locks in deterministic sorted order (`involvedItemIds.sort()`) eliminates cyclic wait conditions in PostgreSQL's wait-for graph, mathematically guaranteeing deadlock prevention across concurrent multi-line order approvals.
   - OWASP API Security Top 10:2023 API10:2023 (Unsafe Consumption of APIs / Concurrency & Race Conditions):
     Concurrent API requests to resource-allocation endpoints must not result in overselling or duplicate commitment of finite assets.
   - Product Requirement REQ-027 & CDI Benchmark Specification Item 6:
     Mandates that total active stock reservations for any inventory item must never exceed physical on-hand stock (`sum(active reservations) <= currentStock`). Under concurrent approval requests exceeding available stock, excess requests must fail with HTTP 400 Insufficient Stock.

2. Evidence of Compliance:
   - `server/src/modules/sales/sales.service.ts` acquires row locks on all involved inventory items using `SELECT id, "currentStock" FROM "inventory_item" WHERE id = ${itemId} FOR UPDATE` in deterministic sorted order.
   - 20 concurrent approvals test in `server/src/sales-concurrency.test.ts` passes with exactly 5 approvals, 15 rejections, and total reservations <= 50 units.
   - 10 iterations of 30 parallel requests in `audit/scripts/verify-concurrency-approve-dispatch.ts` produced 0 oversold runs (100% pass rate).
   - Adversarial Probe 1: 50 concurrent requests against 100 units reserved exactly 100 units (10 approved, 40 rejected).
   - Adversarial Probe 2: 30 concurrent multi-line orders with reverse/shuffled line items produced 0 deadlocks (zero PostgreSQL 40P01 errors).
   - Adversarial Probe 3: Partial stock failure triggered atomic transaction rollback with 0 orphaned reservations.
   - 3 deliberate mutants killed with 0 survivors.
